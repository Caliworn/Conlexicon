# 层叠玻璃皮肤 Fluent 化草案

> 草案，非现行规范。现行规范是 [Layered Glass Skin Specification](LAYERED_GLASS_SKIN_SPEC.md)，在本草案被采纳并实装之前不改变任何行为。文中所有数值和取舍都是 agent 起草的提案，不是已定设计，"待决定"一节列出需要用户拍板的点。

## 1. 目的与来源

[Style Skin Plan](STYLE_SKIN_PLAN.md) 把"层叠玻璃的特色设计"留作单独一批，定位待定。现状是：层叠玻璃与液态玻璃都在表达"玻璃"，辨识度低。本草案的提案是把层叠玻璃重新定位为 Windows 11 Fluent 风格：不透明的云母（Mica）底、分层的卡片、克制的亚克力（Acrylic）只用于临时浮层，让三套皮肤的差异落在材质语言上：

| 皮肤 | 材质语言 |
| --- | --- |
| 经典 | 实色纸面，最朴素的基线 |
| 层叠玻璃（Fluent 化后） | 不透明分层，卡片与细边，亚克力仅限临时浮层 |
| 液态玻璃 | 折射、高光，整片连续玻璃 |

本草案参考公开的 [Windows 设计文档](https://learn.microsoft.com/windows/apps/design/signature-experiences/materials)中的 Mica、Acrylic 与 layering 原则，不追求逐像素复制原生平台。已经画过的方向稿保存在会话 scratchpad，不入库。

参考来源需要先说明：上述链接属于 Windows 11 一脉的 Fluent（Mica、Acrylic），草案里的圆角、模糊半径、选中竖条等具体数值是起草时凭印象写的，尚未对照 Fluent 2 的官方 token 核实，定稿前应改用有出处的数值。借用 Fluent 2 只是翻译它的颜色、圆角、阴影和动效取值到 `theme-layered-glass.css`，不引入 Fluent UI React 或任何前端框架，项目继续保持无构建的原生 JS。

## 2. 保持不变

以下契约不因本草案改变：

- 皮肤 ID 仍是 `layered-glass`（`app.js` 的皮肤注册表、`dictionary-data-model.js`、`sqlite-dictionary-repository.js`、`static-server.js` 与多处检查脚本都引用该 ID；改 ID 会让已选该皮肤的用户回退到经典，且项目不设置偏好迁移）。
- 不改组件 DOM，不改布局间距、断点、虚拟列表尺寸和 z-index；皮肤只通过 `--ui-*`、`--material-*`、`--radius-*` 等 token 表达。
- 样式契约：层叠玻璃浅色作用域必须定义全部标准 token（`scripts/check-style-contract.js`）；`styles.css` 不声明皮肤 token。
- 降级：不支持 `backdrop-filter`、减少透明度、强制高对比时，所有材质回退实色，布局和信息层级不变。
- 警告、危险保持独立颜色语义；焦点环使用强调色并保持清楚可见（现行焦点方案见 STYLE_SKIN_PLAN 第 2 节）。
- 词条详情分区、编辑态等已有的 `--material-entry-detail-section-*` 接口继续使用，本草案只改它们的取值。

## 3. 将被替换或停用的现有层叠特性

这些是现行规范里明确存在的内容，Fluent 化会与它们冲突，需要在规范里逐条改写或删除：

| 现行特性 | 现行规范位置 | 草案提案 |
| --- | --- | --- |
| "稳定内容层 + 玻璃功能层"模型、玻璃质感来自透光和边缘高光 | 第 3 节 | 改为"云母底 + 分层表面"，质感来自分层的明度差和细边，不靠高光 |
| 连续的线性环境色场画布 | 第 3 节、LG-3 | 画布改为单一不透明云母色，不再使用色场 |
| 词条详情外壳的两层固定线性反射、`18px` blur | 4.1、第 6 节、LG-4B | 去掉反射和 blur，改为不透明或近不透明的分层表面 |
| 详情内部"无边框玻璃带，上沿 1px 高光" | 第 6 节 | 改为 setting 式卡片：细边框加轻微填充，卡片间距收窄 |
| 局部点光与近边缘高光（LG-4C） | LG-4C.1，`app.js` 约 3570 行起 | 停用并删除：Fluent 不用指针光场 |
| 导航在两种主题下都用深色实色（`#22313a` / `#10181c`） | 第 5 节、第 6 节 | 待决定：改为与画布同色系的云母，还是保留深色导航 |
| 控件高光、迎光上缘 | 4.3 | 改为 Fluent 的"上缘细线 + 下缘略深"的描边，不用镜面高光 |

## 4. 材质方案（提案）

数值是起始值，需要在浏览器里看过并过对比度检查后再定。

### 4.1 底与分层

| 角色 | 提案 | 说明 |
| --- | --- | --- |
| 画布（云母） | 浅色 `#eef1f3`，暗色 `#1f2224`；不透明 | Web 无法取得桌面壁纸，云母只能是一个有轻微色相的实色 |
| 分层表面（内容外壳、`panel`） | 浅色白色约 55%，暗色白色约 3.5%，不透明叠加在云母上；1px 细边 | 与画布拉开一级明度，不使用 blur |
| 卡片（详情分区、`inset`、`list-item`） | 浅色白色约 75%，暗色白色约 5%；1px 细边；圆角 4px；卡片间距 4px | 对应现有 `--material-entry-detail-section-gap`，它已是 token |
| `control` | 浅色白色约 75%，暗色白色约 6%；边框上缘细线、下缘略深 | 凸起感来自下缘比上缘深，不来自阴影 |
| 强调控件（主要动作） | 强调色实底，边框略深于实底 | 每个视图一个，沿用现行"强调色只表达选择与主要动作"原则 |

### 4.2 导航与列表

- 选中项：左侧 3px 圆角强调色竖条加极淡底，替代当前的整块选中底。该竖条需要伪元素，由 `styles.css` 通过 token 控制显隐和颜色，其他皮肤不显示。
- 导航底色是否改为云母同色系见"待决定"。

### 4.3 临时浮层

| 角色 | 提案 |
| --- | --- |
| `floating`、`tooltip` 的结构化浮窗 | 亚克力：浅色约 78%、暗色约 82% 不透明，blur `30px`，细边，浅投影 |
| `overlay-panel`（modal、词汇网络） | 同亚克力，面积大时进一步提高不透明度以保护对比度 |
| `mobile-bar` | 云母实色加底部细线，不使用 blur |
| 普通 tooltip、toast | 保持现有高对比实色 |

只有临时浮层使用 blur，常驻 blur 表面数量在层叠玻璃下降为 0，比现行规范的"导航或移动栏 1 个"更低。

### 4.4 形状与交互

- 圆角：控件和卡片 4px，大外壳和浮层 8px；现行 `--radius-control` 是 8px，需要同时调整。
- Hover：提高少量填充，不缩放；Pressed：降低填充，边框下缘反转；保持现行"状态不能只靠透明度表达"的要求。
- 动效：保留 `120–160ms` 淡入与最多 `3px` 位移，`prefers-reduced-motion` 下移除位移。

## 5. 待决定

以下是 agent 的假设，尚未得到用户确认，实装前逐项确认：

1. **强调色**：沿用青绿（浅色约 `#0F7B6C`，暗色约 `#4CC2B0`），还是改为 Windows 蓝。青绿与现有三套皮肤的强调色一致，蓝更像 Windows，但会让层叠玻璃单独拥有一套强调色。
2. **用户可见名称**：Fluent 化后它不再是"玻璃"。是否把"层叠玻璃 / Layered Glass"改名，ID 仍保持 `layered-glass`。
3. **导航底色**：保留深色实色，还是改为与画布同色系的云母。后者更贴近 Fluent，但会改变层叠玻璃导航在两种主题下"总是深色"的现行约束，也会影响导航内控件的对比度配对。
4. **噪点纹理**：Fluent 的亚克力带细噪点。现行规范明确禁止噪点纹理（第 6 节）；若要加，需要先在规范里为亚克力浮层开例外，并评估对比度和合成成本；不加则亚克力略显平。
5. **字体**：项目自带 Charis SIL 与 Noto Sans（`styles.css` 开头），草案默认不引入 Segoe UI，避免只在 Windows 上一致。
6. **圆角缩小到 4px** 是否可接受，窄屏触控目标不受影响。

## 6. 风险

- 若画布、分层表面与卡片都是接近的中性色，只靠 1px 细边和一级明度差来分层，浅色主题下层次可能过弱；需要在真实内容（形态表格、长词条）上检查。
- 亚克力浮层的不透明度越高越接近实色，与现行 `floating` 的 58% 差别很大，用户可能觉得"不再通透"，这是方向选择，不是缺陷。
- 删除 LG-4C 需要同时清理 `app.js` 的指针监听、样式契约里对应的断言以及规范文字，不能只改 CSS。
- 与 `docs/LIQUID_GLASS_SKIN_SPEC.md` 中引用层叠玻璃的段落需要复核，避免两份规范互相矛盾。

## 7. 实装拆分建议

建议分批，每批单独验收：

1. **F1 取值替换**：只改 `theme-layered-glass.css` 的颜色、圆角、材质 token 与降级值，不新增结构。完成后三套皮肤应能明显区分。
2. **F2 结构性小改**：导航与列表的 3px 选中竖条、控件上下缘描边，涉及 `styles.css` 里读 token 的少量规则。
3. **F3 清理**：停用并删除 LG-4C 指针光场、词条详情双层反射和环境色场，同步改规范和样式契约。
4. **F4 文档**：重写 `LAYERED_GLASS_SKIN_SPEC.md`（或拆成新规范并归档旧文）、更新 STYLE_SKIN_PLAN 与 README 的皮肤描述。

## 8. 验收

沿用现行规范第 12 节的清单（中英文、明暗、320/480/768/1024/1440px、长文本、各浮层、各状态、降级路径），并增加：

- 浅色主题下分层是否可辨：云母、分层表面、卡片三级在真实词条与形态表格上可区分。
- 亚克力浮层上的文字对比度：浅色与暗色分别测量，亚克力不透明度不足时优先提高不透明度。
- 常驻 blur 表面数应为 0，临时浮层同时最多 1 个。
- 切换经典、层叠玻璃、液态玻璃时无残留的指针光场、反射或环境色场。

不能用真实鼠标、触屏或真机完成的项必须在回复和交接文档中逐项列出。
