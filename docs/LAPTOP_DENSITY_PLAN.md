# Laptop Density Plan / 笔记本紧凑密度设计草案

状态：设计草案（2026-11-18），已做一次独立复评（第 6 节）。2026-11-18 用户确认 D1–D6 按代理倾向执行；同日看过 L1 后，用户把阈值上调、要求收窄导航、压缩页头，并缩小词条卡片和词条详情（第 10 节）。L1 与卡片、详情的紧凑档已实装，完整编辑（L2）与其他页面（L3）未实施。

本文处理缩放后可用高度不足的笔记本屏幕，典型是 1080p 屏开 150% 缩放。目标是收紧外壳和留白，正文字号和控件尺寸不变。本文不改变数据模型、API、保存范围、未保存检查和移动端（800px 以下）布局；移动端词条编辑的重设计见交接文档路线图“云同步与移动端”。

## 1. 现状（已由当前实现确认）

### 1.1 实测（2026-11-18）

在浏览器面板中把视口设成 1280×610，测试数据为临时词典，只有 1 个词条、1 条释义、无词源；外观为经典皮肤、暗色、中文。1080p 屏开 150% 缩放后可用 1280×720 CSS px，减去任务栏和浏览器顶栏，最大化窗口的视口高度约为 600–620px。

| 项 | 实测 | 来源 |
| --- | --- | --- |
| 外壳列宽 | 导航 300px，工作区 980px | `.app-shell` `minmax(240px, 300px) minmax(0, 1fr)` |
| 工作区内边距 | 四周 28px | `.workspace` |
| 页头 | 词典名一行和视图标题共占 96px，内容从视口 124px 处开始 | `.top-bar` `min-height: 72px`、`margin-bottom: 24px` |
| 词条列表与详情 | 340px 与 564px，间距 20px | `.content-grid` `minmax(240px, 340px) minmax(320px, 1fr)` |
| 导航工具列表 | 11 个工具，每个 54px，间距 10px，需要 694px，可视 386px，只看到 6 个 | `.tool-button` `min-height: 50px; padding: 14px`，`.tool-list` `gap: 10px` |
| 导航底部 | 皮肤、明暗、语言三个按钮共 88px | `.utility-actions` |
| 完整编辑表单 | 高 1423px，约 2.3 屏；词形输入框 60px 高、字号 38.4px；保存在表单底部 | `#entryForm` |

完整编辑各段高度：词形 86px、发音 76px、标签 91px、释义 232px、词源 297px（其中说明 118px）、形态学 120px、词条备注 191px，删除／取消／保存一行 38px。

### 1.2 相关代码事实

- 断点全部按宽度。`styles.css` 和三套皮肤文件里没有任何 `max-height` 或 `min-height` 媒体查询。
- 导航收起规则在 `app.js` 的 `effectiveNavCollapsed()`：800px 以下用移动抽屉；800–1279px 强制使用 84px 图标栏，收起按钮隐藏，用户不能展开；1280px 及以上展开，用户可以手动收起（`shellState.wideNavCollapsed`，不持久化）。1080p 加 150% 缩放正好 1280px 宽，所以默认展开为 300px。
- 页面整体由 `html` 滚动，词条列表 `position: sticky`。
- 皮肤各自写死部分尺寸，不读共享 token。例如液态玻璃的 `.dictionary-panel .tool-button` 是 `min-height: 50px; padding: 11px 12px`，`.tool-list` 间距是 4px，`.workspace` 左内边距是 `calc(导航宽 + 内嵌距 + 28px)`。层叠玻璃只改导航按钮的材质，没有改尺寸。
- 标签管理已经在用 `@container tag-zones`，按行的实际可用宽度换布局。
- 完整编辑的吸底操作栏（去框化 U5）已于 2026-10-10 由用户决定搁置，桌面可以用 `Ctrl`/`Cmd` + `S` 保存。本文不重新提起。

## 2. 问题与目标

问题出在密度上，不在断点。尺寸是按 100% 缩放下约 1920×1000 的可用空间定的。缩放把可用空间压到 1280×610 左右时，外框和留白的绝对尺寸不变，挤掉了内容。切回 100% 又会把文字和点击目标一起缩小。

目标视口（宽×可用高，CSS px，高度为估算值）：

| 典型设备 | 视口 |
| --- | --- |
| 1080p，150% | 1280 × 610 |
| 1366×768，100% | 1366 × 650 |
| 1080p，125% | 1536 × 750 |
| 1080p，100%（对照，不应变化） | 1920 × 970 |

验收目标（数字为提案，第 5 节 D6 确认）：

1. 1280×610 下，经典皮肤展开导航的 11 个工具全部可见，导航不滚动。
2. 1280×610 下，内容起点从视口 124px 降到约 80px 以内。按 token 初值估算：内边距 18 加页头下间距 12 共 30px，页头本身取 44px 最小高度和内容自然高度的较大值。词典名一行加视图标题的自然高度约 50px（估算），实装时测量。
3. 1280×610 下，按 §1.1 的同一测试词条，完整编辑表单高度降到约 1100px 以下（现在 1423px）。
4. 正文字号、表单控件高度和 `pointer: coarse` 下的 44px 命中区不变。
5. 1920×970 下所有尺寸与现在相同。

## 3. 方案

### 3.1 密度 token 与紧凑档

- 定义外壳和留白的密度 token（L1 实装时改为声明在 `body` 上，见第 9 节）。初版清单：
  - `--shell-gutter`：工作区内边距，28px → 18px。
  - `--view-header-min-height`：页头最小高度，72px → 44px。
  - `--view-header-gap`：页头下间距，24px → 12px。
  - `--nav-padding`：导航面板内边距，24px → 16px。
  - `--nav-item-height`：导航项最小高度，50px → 36px。
  - `--nav-item-gap`：导航项间距，10px → 2px。
  - `--editor-section-gap`：编辑分区间距，具体值在第二批实测后定。
  - `--editor-lemma-size`：编辑态词形字号，具体值在第二批实测后定。
- 舒适档的值等于现在的值。紧凑档在 `@media (min-width: 800px) and (max-height: 760px)` 下覆盖这些 token。宽度方向的问题沿用现有宽度断点和容器查询，不另设宽度阈值（理由见第 6 节）。
- `@media (pointer: coarse)` 下，导航项最小高度仍保持 44px，紧凑档不覆盖它。
- 三套皮肤中写死的对应尺寸改为读取 token。皮肤可以给 token 设自己的舒适值，但紧凑档的覆盖由共享层统一完成，皮肤不各写一份紧凑规则。

### 3.2 第一批：外壳

- **导航**：紧凑档下工具项 36px、间距 2px，11 项共 416px。现在的工具项高度实际由上下各 14px 的内边距撑开（实测 54px，大于 `min-height: 50px`），所以紧凑档要同时缩小上下内边距，只改最小高度不会生效。底部的皮肤、明暗、语言三个按钮从两行合并成一行图标按钮，带 tooltip 和可访问名称，约 40px（D4）。按 1280×610 估算：610 − 内边距 32 − 品牌行 48 − 面板现有的两处 20px 间距 40 − 底部一行 40 = 450px，可以放下 416px 的工具列表。英文界面工具名更长，需要验证不换行或换行后仍能放下。`pointer: coarse` 下工具项保持 44px，11 项需要 504px，触屏笔记本在紧凑档下导航仍会滚动，这一点接受。
- **页头和工作区**：页头最小高度和下间距改读 token；工作区内边距改读 `--shell-gutter`。液态玻璃左内边距 `calc` 里的 28px 换成同一个 token。
- **不改的部分**：导航强制收起的规则，以及 800 和 1280 两个宽度阈值（D3）。

### 3.3 第二批：词条编辑与详情

- 编辑态词形输入框的字号和高度改读 `--editor-lemma-size`。查看态词头仍按详情区宽度取字号，不受影响。
- 编辑分区间距、分区标题与字段的间距、说明文字的上下距改读 token。
- 发音和标签这类短字段，在详情区宽度足够时并排排列，用 `@container` 判断详情区自身的宽度，不按视口宽度判断：展开或收起导航会改变详情区可用宽度。阈值第二批实测后定。
- 局部编辑和快速录入共用同一批字段 token，不另写一套。
- 第二批开工前，先在 1280×610 下用一个有多条释义、词源和形态表的词条重新测量，再定具体数值。§1.1 的测试词条太简单，测不出释义卡片和形态表的密度问题。

### 3.4 第三批：其他页面盘点

设置、语料库、语言文档、形态模板、IPA、标签管理和分析页会自动继承外壳 token。各页自身的留白在第三批逐页测量，只记录问题、提出调整，不在前两批顺带修改。

### 3.5 不做

- 不用 CSS `zoom` 或 `transform: scale` 整体缩放。效果和切回 100% 一样，文字和控件照样变小，还会让 tooltip、浮层定位和液态玻璃的几何计算出错。
- 不全局缩小字号或控件高度。
- 不新增"笔记本专用"的 DOM 或布局分支。紧凑档只是同一布局换一组 token。

## 6. 独立复评

把第 1–5 节当作外部提案重新检查，复评后作了以下修改：

1. **必要性**：成立。问题已在 1280×610 实测确认；1080p 加 150% 是常见的笔记本出厂设置。
2. **触发条件收窄**：初稿同时按"宽度不超过 1440px"或"高度不超过 760px"触发。复评发现：宽度不足的问题已由 800／1280 两个阈值和容器查询处理；1440×900 这类屏幕高度够用，却会被误判为紧凑。所以改为只按高度（D1）。
3. **放弃把图标栏阈值调到 1366px**：初稿建议窄于约 1366px 就默认收成图标栏，让详情区变宽。复评发现 800–1279px 的图标栏是强制的，用户不能展开；把阈值调到 1366px，会让 1080p 加 150% 的用户再也无法展开导航，这是倒退。改为压缩导航行高，宽度维持现状（D3）。详情区在 1280px 下的宽度不变，靠第二批的分区间距和容器查询改善。
4. **皮肤耦合**：液态玻璃写死了三处尺寸。只改共享层的话，液态玻璃不会生效，所以第一批必须包含皮肤的 token 化（第 4 节）。
5. **方案替代**：评估过只提供手动密度设置。默认就应在常见设备上好用，所以以自动为主，手动设置作为备选（D2）。容器查询无法按视口高度判断，所以高度只能用媒体查询。
6. **副作用**：桌面用户开着开发者工具，或窗口不高时也会进入紧凑档。这时正好需要紧凑，可以接受。拖动窗口跨过阈值时布局会跳一次，属于正常的响应式行为。
7. **估算核对**：初稿把导航品牌行按 40px、面板间距按 12px 计算，并以为只改最小高度就能压低工具项。按实测改为 48px 和面板现有的 20px 间距，并补上"工具项高度实际由内边距决定"这一点（§3.2）。页头的目标也从"不超过 72px"放宽为"约 80px 以内"，因为页头的自然高度可能超过 44px 的最小高度。
8. **验收方式**：只靠目视不够。实装时在 `scripts/check-style-contract.js` 中检查：皮肤里不出现与密度 token 重复的写死尺寸；导航项在 `pointer: coarse` 下不低于 44px。具体断言在实装时按 AGENTS.md 的测试规则确定。

## 9. 实施记录（2026-11-18）

第一轮按第 3 节实装导航与页头后，用户在同日看过结果，提出第 10 节的修订。现行取值以 `styles.css` 开头的密度 token 和 "Compact density" 两段规则为准，这里只记与草案不同的结构性决定：

- 密度 token 声明在 `body` 上，皮肤通过 `--skin-nav-width`、`--skin-nav-padding`、`--skin-nav-item-max-height`、`--skin-nav-item-padding-inline`、`--skin-nav-item-gap` 提供舒适值，紧凑档直接覆盖密度 token。样式契约检查禁止皮肤直接声明密度 token。液态玻璃的展开宽度 `--liquid-glass-navigation-expanded-width` 改为读取 `--nav-width`。
- 增加图标栏和底部按钮的 token（`--nav-rail-item-max-height`、`--nav-rail-section-gap`、`--nav-utility-min-height`；第 11 节起导航项高度由行分配），800–1279px 的图标栏在矮窗口里也收紧。
- 底部三个按钮合成一行后，由 `app.js` 的 `navLabelHidden()` 为标签被隐藏的按钮打开 tooltip。
- 词条列表的估算卡片高度由 `app.js` 的 `ENTRY_CARD_ESTIMATED_HEIGHT` 按同一条媒体查询取 145 或 100px；跨过阈值时由 `syncEntryCardEstimate()` 更新并重排列表。样式契约检查要求两边的媒体查询一致。

实测（无头 Edge 浏览器面板，1 万词条临时词典，关闭过渡动画后测量）：

| 视口 | 结果 |
| --- | --- |
| 1280×610 | 三套皮肤、中英文均 11/11 个工具可见，导航中文 220px、英文 272px，按钮、标签和品牌名都不超出导航内边距；页头 34px，内容起点 64px；卡片 90–91px，同屏完整 4 张；详情区 649px（液态玻璃 633px） |
| 1707×840（1440p，150%） | 11/11，内容起点 64px，同屏完整 6 张卡片，详情区 1091px |
| 1920×970 | 页头 72px、内容起点 124px、卡片 129–131px、导航 300px（液态玻璃 288px），与改动前一致；估算卡片高度 145px |

遗留：

- 窗口在会话中跨过阈值时，尚未读取的列表窗口仍按旧的估算高度占位，读到后由窗口比例校正；导航条在这之前的比例会有偏差。
- 液态玻璃图标栏在 610px 及以下高度仍有 1 项要滚动（浮层四周各有 16px 内嵌距）。
- 词条页以外的页头（语言文档、设置等）只随紧凑档缩小标题和间距，眉标仍在标题上方，约 47px。
- 浏览器面板中 `matchMedia` 变化事件、窗口 resize 和 CSS 过渡经常停住，以上数字都在手动触发 `renderShellNav()`、resize 或关闭过渡后测得。

## 10. 用户修订（2026-11-18）

用户看过第一轮结果后提出，代理据此修改：

1. **阈值上调**：1440p 屏开 150% 缩放（视口约 1707×840）也有问题，760px 不够。阈值改为 920px，舒适档导航约需 920px 才能放下 11 项，1080p 屏 100% 缩放的最大化窗口（约 950px）仍为舒适档。具体值 920px 为代理选择，待用户确认。
2. **导航收窄**：紧凑档导航宽 300px → 220px（液态玻璃 288px → 220px），导航项左右内边距 14px → 10px。220px 为代理选择。英文界面改为 272px：第一轮误报英文不截断（只比较了标签自身的宽度），实际 "Morphology Functions" 需要约 237px 的按钮、英文品牌名约 232px，220px 时按钮和品牌名都溢出导航；按用户反馈改正。
3. **页头继续压缩**：词条页的词条数、词根数和语言名放到词典标题右侧同一行；紧凑档页头不设最小高度，标题 1.375rem。
4. **词条卡片缩小**：读音和词性与词头同行，内边距 12px → 8px 10px，行距 5px → 3px，释义 1rem → 0.875rem，取消 104px 最小高度。

## 11. 导航项自适应（2026-11-18，用户提出）

导航项原本跟着阈值跳档（54px → 36px），窗口刚低于 920px 时按钮变扁、下方空出一大块。改为：

- `.tool-list` 的行为 `minmax(var(--nav-item-min-height), var(--nav-item-max-height))`，按钮拉伸到行高。列表作为导航面板的弹性子项收缩到剩余空间，行随之在 36px 与最大值之间等分，再不够才滚动。最大值舒适档沿用改动前的实际高度：经典与层叠玻璃 54px，液态玻璃 50px（`--skin-nav-item-max-height`），图标栏 50px（`--nav-rail-item-max-height`）。按钮上下内边距固定为 4px，高度由行决定。
- 项间距 `clamp(2px, calc(2.5vh - 13px), 皮肤值)`：约 600px 高时 2px，920px 时到经典 10px；液态玻璃最多 4px。
- `@media (pointer: coarse)` 在所有尺寸下把最小行高提到 44px（原先只在紧凑档内）。手机抽屉的列表也会收缩，11 项在 812px 高的手机上以 44px 放下，不再滚动。
- 页面内边距、导航内边距、面板间距和底部按钮合并仍按阈值切换。

实测（无头 Edge，1280 宽，关闭过渡）：经典 610px 时 41.8px／间距 2.25px，760px 时 52px／6px，920px 和 921px 时都是 54px／10px；液态玻璃 610px 时 37.7px，760px 起 50px；图标栏 1100×650 时 40.1px，1100×1000 时 50px。三套皮肤各高度 11/11 可见。
