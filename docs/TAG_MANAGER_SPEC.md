# 标签管理页规范

状态：当前规范。本文规定"标签"页面的布局、交互和可访问性。登记表的数据语义、端点和错误码见 [API Contract](API_CONTRACT.md#标签登记表)，schema 见 [SQLite Backend Specification](SQLITE_BACKEND_SPEC.md)，旧数据转换见 [导入导出规范](IMPORT_EXPORT_SPEC.md) 5.1 节。

## 1. 定位

标签页是导航目的地，与自动 IPA、形态函数、形态表格同属描述语言的工作区：它决定这门语言有哪些词性，显示使用数和未使用的标签，并能跳到词条。

- 每次改动立即保存，没有需要确认的未保存状态，不接入"保存 / 放弃更改 / 取消"流程。
- 正在编辑的显示名按失焦规则保存，离开页面时也一样。
- 默认位于"自动 IPA"之后（`DEFAULT_TOOL_NAV_ORDER`）。已保存的 `toolNavOrder` 不含这一项时，规范化把它补在最后，用户可在其他设置里调整。
- 跨区移动不弹确认，改动可以再拖回；不提供"撤销"提示。删除标签使用独立的确认弹窗。

## 2. 布局

页面分两栏：左侧主栏是登记表（词性区在上、普通区在下），右侧窄栏是"显示"面板。两个区和显示面板是内容外壳（`data-surface="content-shell"`），液态玻璃下为 Q1 磨砂材质；搜索框是 Q3 折射（`continuous` 角色，装饰层 `.tag-manager-search-surface`）。

```
标签                       [搜索标签] [列表｜压缩] [添加标签]
共 128 个标签 · 9 个未使用
┌─ 主栏 ─────────────────────────────────────┐  ┌─ 显示 ──────┐
│ 词性  放在这里的标签会被识别为词性。        │  │ 输入        │
│  ⠿ [名词 n]  [名词    ]  412  ○ 红色  ⋯    │  │ 词条列表    │
│  ⠿ [prep]    [        ]    0  ○ 红色  ⋯    │  │ 筛选菜单    │
├────────────────────────────────────────────┤  │ 词条悬浮卡片│
│ 普通标签  新出现的标签会添加到末尾。        │  └─────────────┘
│  ⠿ [archaic] [        ]   57  ● 红色  ⋯    │
└────────────────────────────────────────────┘
```

顶部摘要显示标签总数和未使用数。顶栏的图标分段控件切换列表和压缩视图，tooltip 显示视图名；视图选择是进程 UI 状态，默认列表，刷新后回到列表，切换词典和离开页面时保持。

整页（含顶栏）宽度上限 1200px 并居中，这样登记表的主栏最宽约 900px，标题和"添加标签"分别对齐内容左右缘。规则见 [Style Skin Plan](STYLE_SKIN_PLAN.md) 第 2 节"工作页宽度"。

## 3. 标签行

| 控件 | 行为 |
| --- | --- |
| 拖动把手 | 区内与跨区拖动。词性区为空时显示"拖到这里设为词性"占位，也是放置目标。搜索时禁用 |
| 标签 | 用实际的标签样式渲染，含红色强调和显示名，原始值始终可见。标签是这一页的主要内容，字号接近正文，不沿用词条列表的紧凑字号。过长时省略，tooltip 显示原始值 |
| 显示名 | 行内输入框，宽度 120–220px，其余空间留给标签列。占位为原始值。`Enter` 或失焦保存，`Esc` 还原；输入法组字中不处理 |
| 使用数 | 按钮，点击跳到按该标签筛选的词条列表，经现有未保存检查。词性走词性筛选，其余走标签筛选。为 0 时禁用 |
| 红色强调 | 开关控件（[Style Skin Plan](STYLE_SKIN_PLAN.md) 第 2 节"开关"），在 `color` 的 `''` 与 `red` 之间切换 |
| 更多菜单 | ⋯ 按钮或在行上右键打开，右键时显示在指针处。移到顶部、移到底部、设为词性／移出词性、删除。在用的标签不能删除：菜单项保持可见但禁用，tooltip 说明原因。显示名输入框不接管右键，保留浏览器的粘贴和输入法菜单 |

- 使用数为 0 的行显示为灰色：标签改为描边样式，红色强调的标签保持红色。
- 显示相同的标签在行内标出"与标签「…」显示相同"，点击定位到对方行。重复允许保存：显示名与原始值的重复可以由词条保存时的自动登记产生，而自动登记不能因此拒绝保存，所以只提示、不阻止。
- 重新渲染保留焦点所在的控件和其中已输入的内容；登记表内容没有变化时不重建。
- 拖动开始时读取一次行位置，拖动过程中只比较数字，放置位置变化时才更新标记。

## 4. 搜索与添加

- 搜索按原始值和显示名过滤两个区。过滤时禁用拖动，因为不相邻的行之间放下位置不明确；更多菜单中的移动仍可用。
- 添加标签在普通区末尾出现输入行，添加后保持打开，便于连续添加。
- 值已存在时关闭输入行并定位到已有行；含半角逗号、全角逗号或顿号时就地提示，保留输入内容。
- `Esc` 取消；输入为空时失焦也关闭。

## 5. 显示面板

面板编辑八项标签显示偏好（`tagListSeparatorStyle`、`entryListTagDisplayLimit`、`entryListTagsIncludeParts`、`entryListTagFiltering`、`entryListRawTagDisplay`、`entryListRawPartDisplay`、`filterMenuRawTagDisplay`、`entryHoverCardRawTagDisplay`），它们存于 settings，不是逐个标签的数据。

- 开关和下拉框改动后立即保存，以 `PUT /settings` 发送只含该字段的请求体。
- 标签显示上限按 `Enter` 或失焦保存，超出 2–10 时就地提示并还原。
- 面板的展开状态是进程 UI 状态，不写入词典。

## 6. 压缩视图

压缩视图只用于排序。每个标签是一个只显示原始值的标签块，一行多个，随宽度换行；词性区和普通区、显示面板、搜索和添加都不变。显示名、使用数和红色开关只在列表视图里编辑。

- 标签块宽度上限 150px，超长省略，tooltip 显示原始值。未使用的灰色描边和红色强调保留。原始值唯一，不需要处理显示歧义。
- 单击或右键打开更多菜单。这里没有 ⋯ 按钮，所以左键不能取消：触屏和键盘都从这里进入。有词条使用的标签，菜单最前面多一项"查看 N 个词条"，代替列表视图的使用数按钮。
- 整个标签块可拖动，放置规则和列表视图相同。放置标记是竖线，始终画在目标标签之前。一行末尾和下一行开头是同一个顺序位置，线画在下一行开头；只有区尾才画在最后一个标签之后。
- 搜索时禁用拖动，菜单中的移动仍可用。
- 添加标签的输入行占满普通区末尾一行。
- 跳转高亮用描边表示，因为标签块自身已有背景色。

## 7. 键盘

- 每个区内只有一个 Tab 停靠点。上下方向键在行间移动，`Home`／`End` 到首尾（roving tabindex）；行内控件按 Tab 进入。
- `Alt` + `↑`／`↓` 移动当前行，焦点跟随。在词性区底部按 `Alt` + `↓` 移入普通区顶部，反之亦然。
- 压缩视图中，左右方向键与上下方向键相同，都按标签顺序走，`Alt` + `←`／`→` 也能移动标签；`Enter` 或空格打开更多菜单。
- 更多菜单打开时焦点进入第一项，`Esc` 关闭并把焦点还给打开它的控件；菜单里的移动完成后，焦点落在被移动的标签上，页面不滚动。

移动请求由 `tagModel.tagMoveToIndex` 和 `tagMoveStep` 按前后顺序算出，不依赖屏幕几何方向，也不依赖行的渲染方式。修改请求按发出顺序串行，后一次移动基于前一次的结果。

## 8. 窄屏

- 窗口宽度 1024px 以下，"显示"面板移到登记表上方，收进默认关闭的"显示选项"按钮。
- 登记表容器宽度不足 560px 时，每行折成两行：把手、标签、使用数／显示名、开关、菜单。这里按容器判断，因为导航展开时内容区比窗口窄得多。
- 触屏不依赖拖动，更多菜单提供全部移动操作。压缩视图的标签块在粗指针设备上高 44px。

## 9. 从其他页面跳转

分析页的词性和标签行，以及质量检查的 `near_duplicate_tags`、`display_label_conflict`、`tag_too_long`，都提供"在标签管理中查看"。跳转清空搜索，高亮相关行并滚动到第一行；离开页面时清除高亮。

## 10. 规模

预期标签数在几十到几百，页面直接渲染全部行，不做虚拟滚动。标签特别多时用压缩视图排序。窗口化依赖等高的行，用不到宽度不一的换行标签块上；如果 2000 标签以上的列表视图出现性能问题，再评估窗口化。

## 11. 验收

修改本页时按 `AGENTS.md` 的 UI 验收检查项检查，并额外覆盖：

- 真实鼠标拖动：区内、跨区、放到空区；压缩视图还要覆盖换行处、区尾和长距离拖动时页面能否滚动；
- 键盘移动后焦点仍在该行；
- 显示名编辑中登记表被改动时，已输入内容不丢失；
- 导航展开和收起时，560px 容器宽度两侧的行布局。

数据行为由 `scripts/check-tag-registry.js` 覆盖。
