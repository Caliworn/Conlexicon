与释义标签（[Definition Tag Specification](DEFINITION_TAG_SPEC.md)）的分工：释义标签规范定义词条标签、释义标签和有效标签；本计划决定形态匹配用哪些标签集合（2.4），以及这些集合会得到哪些形态表（2.3、2.5）。

## 1. 问题

### 1.1 现行模型的问题

1. **匹配条件太弱**：模板组的 `matchTags` 只要求"任一标签相同"，无法表达"且"和"非"。
2. **只取最前**：每个词条只能得到一个组。变化表常常是叠加出来的，例如形容词 = 名词性变化 + 级变化；只取最前，就只能把名词性表格复制进一个"形容词组"。
3. **特殊优先靠排序隐式实现**：比如把"不规则名词"组排在"名词"组前面。规则的含义要依赖一个看不见的顺序。
4. **不规则子类只能复制整张表**：一个子类只在几格上不同，也要把整张表抄一遍，之后改原表时副本不会跟着变。逐词覆写只解决单个词，解决不了一整类词。
5. **格按位置寻址，行列只能在末尾增减**：在中间插一行，要把下面每一行的规则手动往下挪，逐词覆写也得跟着挪。
6. **Syncretism 只能抄规则**：几格系统性同形时，要把同一条规则写进每一格，改一处要改几处，逐词覆写也不会传递。
7. **分不清"不存在"和"没填"**：空格同时表示这两种意思；逐词覆写也不能表示某个词缺某一格。

### 1.2 改造前的基线

以下内容对照基准提交 `6cf0a5c`；格的寻址、尺寸调整和搜索投影的字段对照 `ed01367`。

**模板数据**（`lib/morphology-model.js`）

- 形态模块是 `{ functions: { leftV, rightV }, templateGroups: [...] }`。
- 组：`{ id, name, matchTags, notes, tables: [...], createdAt, updatedAt }`。
- 表：`{ id, title, rowCount, columnCount, rowLabels, columnLabels, cells: { "r,c": { sourceText } }, createdAt, updatedAt }`，只属于一个组。`sourceText` 去掉首尾空白后为空，就当作空格。
- SQLite：`morphology_template_groups(id, position, name, match_tags_json, notes, …)`、`morphology_template_tables(id, group_id, position, title, row_count, column_count, row_labels_json, column_labels_json, …)`、`morphology_template_cells(table_id, row_index, column_index, source_text)`。

**词条数据**

- `morphologyMode` 为 `auto` 或 `manual`；`morphologyGroups: [{ templateGroupId, title, notes, overrides: { [tableId]: { "r,c": value } } }]`。覆写值是字面字符串，空值在规范化时丢掉（`normalizeMorphologyOverrides()`）。
- **自动模式**：`morphologyGroups` 只是叠加层（标题、备注、覆写），挂在自动解析出的组上。没有内容的叠加层会被丢弃；解析不到的组，其叠加层作为"休眠叠加层"保留，`materializeAutomaticMorphologyGroups()` 切换到手动模式时会把它们一起带过去。
- **手动模式**：`morphologyGroups` 是用户显式选择的有序组列表。
- SQLite：`entry_morphology_groups` 主键 `(entry_id, template_group_id)`，存 `title / notes`；`entry_morphology_cell_overrides` 主键 `(entry_id, template_group_id, template_table_id, row_index, column_index)`，外键指向 `entry_morphology_groups`。

**解析与派生**

- `resolveAutomaticTemplateGroups()`：有效标签与组 `matchTags` 有任一相同即匹配，只取排序最前的组。repository 的 `automaticMorphologyGroupId()` 和旧版本迁移里各有一份相同规则。
- `morphologySearchValueRecords()` 按"组 → 表 → 单元格"生成形态搜索记录，字段是值、组 ID、表 ID、行列下标和 `sourcePosition`，不含行列标签；`entry_morphology_search_values` 主键含 `template_group_id`。
- `lib/morphology-write-plan.js`：按组判断生成是否变化（`generationGroupIds`）；`assignmentChanged()` 比较组顺序和各组 `matchTags` 的结构化集合；表被移到别的组、表格缩小或删除组和表时，需要检查词条引用，有引用就返回 409 `morphology_references_in_use`。
- `lib/morphology-analysis-feature.js` 与 `morphologyAnalysis` feature result：summary 的 `groups[]` 给出每个组的 `assignedEntryCount`，`overrideGroups[]`、`overrideTables[]` 统计覆写；筛选 category 支持 `group + templateGroupId` 等；items 的 feature 带 `assignedGroupIds`。

**界面**（`app.js`）

- 详情 `renderMorphologyDisplay()` 按组分节：标题取词条组标题、模板组名，组备注显示在标题下；表标题为空时用组标题。空格显示为空白单元格。
- 编辑器 `renderMorphologyEntryControls()`：自动 / 手动切换，手动模式可添加、排序、移除组；每组可填词条级标题和备注，每张表有覆写输入格。
- 模板页 `createMorphologyGroupEditor()`：按组编辑名称、`matchTags`、备注，组内编辑表的标题、行列标签和单元格规则。尺寸用"行数""列数"两个数字框加"应用尺寸"按钮调整，只能在末尾增减；行列标签为空时填成序号。没有试算或影响范围显示。

### 1.3 目标

1. **去掉形态组**：表格成为直接匹配词条的单位，每张表自带匹配规则。
2. **每张表属于一个槽位**：同一槽位里的表互相竞争，按 **elsewhere condition** 由更具体的规则胜出；不同槽位之间全部生效，自动组合。这对应 Paradigm Function Morphology 的"规则块"。
3. **槽位与表的顺序**：槽位及槽位内表的顺序决定生效表的排列，词条详情在各释义组内沿用这个顺序。顺序不影响哪些表生效。
4. **按释义匹配**：每条释义各自匹配，详情把适用同一组释义的表放在一起。
5. **表可以显式继承另一张表**：子表只写不同的格，其余格沿用父表。
6. **格有明确的状态**：规则、不存在、同某格（syncretism）、还没填；逐词覆写也能标"不存在"。
7. **行列有稳定 ID**：可以在任意位置插入、删除、调整顺序，格、覆写和引用不受影响。
8. **可视化编辑**：结构视图展示竞争与具体程度关系，分配试算解释每个槽位为什么选中某张表，影响范围显示规则对整本词典的作用。
9. **现有数据转换后，形态结果完全不变。**

### 1.4 不做的事

- 不改单元格的规则语言（`applyMorphologyRuleSyntax()`、`leftV / rightV` 函数），那属于第 3 阶段规则引擎。
- 匹配条件只看标签，不看词形或读音；以后由规则引擎扩展。
- 不做文本形式的匹配表达式（理由见第 3 节）。
- 不做与匹配无关的显示分节。详情按各表适用的释义分组（2.14）。
- 不做跨表的格引用，也不做"取某格作词干再加后缀"，这些归规则引擎。
- 不做多维特征空间；多级表头记在交接文档的路线图（见第 4 节）。
- 模板页的表格编辑和词条编辑器逐格显示。详情和词形试算合并 syncretism 和连续的“不存在”（2.13、2.14）。

## 2. 方案

### 2.1 模板数据

```js
morphology: {
  functions: { leftV, rightV },          // 不变
  slots: [{                              // 有序：槽位顺序 = 显示顺序
    id, name,
    tables: [{                           // 有序：只在平局时决定先后
      id, title, notes,
      matchRules: [{ all: [...], none: [...] }],   // 2.2
      inheritsFrom,                      // 父表 ID 或 null（2.8）
      rows: [{ id, label }],             // 有序；子表不带，沿用链顶表（2.6）
      columns: [{ id, label }],
      cells: [Cell],                     // 2.7
      createdAt, updatedAt,
    }],
    createdAt, updatedAt,
  }],
}
```

- 每张表恰好属于一个槽位。新建表时自动建一个只含它的槽位，名称默认为空；把表移进另一个槽位，就和那个槽位里的表形成竞争。
- 界面在槽位变空时自动删除它，所以正常编辑不会产生空槽位；外部输入（HTTP、导入）中的空槽位在边界校验中拒绝（2.2）。
- 槽位名称可以为空。只含一张表时，界面不显示槽位名；有两张以上时显示槽位名，空名显示为"未命名槽位"。
- 表新增 `notes`，承接原来组的模板备注（转换见 2.15）。

数据形状上，槽位与旧的组都是"装着有序表格的容器"，但含义相反：组里的表一起生效，槽位里的表互相竞争。界面与说明文字必须写清这一点（2.13）。

### 2.2 匹配规则

每张表的 `matchRules` 是析取范式：

- 行内 `all` 的标签上下文必须全部带有（"且"）；
- 带有 `none` 中任一标签，这一行就不成立（排除）；
- 行与行之间是"或"；
- `matchRules` 为空的表不会自动匹配。

比较时用结构化键（`normalizeStructuralKey`），去掉首尾空白，区分大小写。

**校验**（只在外部边界做：形态模块的 `PUT` 和 JSON 导入）

- `all`、`none` 按标签列表规范化；
- `all` 不能为空：只有排除条件的行会匹配几乎所有词条，包括没有标签的词条；
- 同一标签不能同时出现在一行的 `all` 和 `none` 中：这一行会永远不成立；
- 违反时返回 400 `invalid_morphology_match_rule`，`details` 指出表 ID 和行号；
- 槽位里没有表时返回 400 `invalid_morphology_slot`。

### 2.3 具体程度与 elsewhere

把一行看成一组条件：`all` 中每个标签是"有它"，`none` 中每个标签是"没有它"。

- **A 行比 B 行更具体**：A 的条件集合真包含 B 的条件集合。这时满足 A 的上下文一定满足 B，反之不然。
- 每一行都只是用"且"连起来的条件，所以集合包含就是逻辑蕴含的精确判断，不需要推理引擎；校验已经排除了自相矛盾的行。
- 排除条件也算条件：同一槽位里，"`n`，排除 `专名`"比 `n` 更具体，上下文不带"专名"时前者覆盖后者。

**对一个上下文 S 的解析**：

1. 找出所有表中在 S 上成立的行；
2. 每个槽位内，去掉"比同槽位另一条成立的行更不具体"的行（elsewhere）；
3. 剩下的行所属的表全部生效。

性质：

- 只含一张表的槽位不存在竞争：满足规则就生效。简单词典完全不用关心槽位。
- **并列生效**：在当前上下文中，条件相同或互不包含的成立行可以同时保留。若它们都没有被其他成立行覆盖，各自所属的表按槽位内顺序生效，分配试算标为“同时生效”。例如“名词格变化”和“名词数变化”条件相同，只要这两行都保留，两表就会同时生效。
- 一张表有多行时，只看实际成立的那几行；只要其中一行没被覆盖，这张表就生效。

### 2.4 匹配上下文：按释义

- 每条释义一个上下文：词条标签 ∪ 该释义标签。没有标签的释义，上下文就是词条标签。词条没有释义时，只有一个上下文：词条标签。释义文字、备注、标签和例句全为空的释义在保存和导入时去掉，不产生上下文。
- 词条标签参与每个上下文，因为变化类这样的词级标签通常挂在词条上。这只是匹配输入，不改变"释义不继承词条标签"的显示与筛选语义。
- **使用约定**：变化类、不规则这类词级属性标在词条上。标在某一条释义上时，其他释义的上下文里没有它，可能匹配到通用表，详情会标出各表适用的释义（2.14）。
- 各上下文的结果合并去重，得到词条的生效表。覆写、搜索投影、形态分析和分配预览都使用合并后的结果；只有详情和词条编辑器的标注按上下文区分。
- 释义都没有标签时，结果等于只用词条标签，现有数据不受影响。

例：释义 1 标 `n, 古语`，释义 2 标 `v`，表规则为 `v, 古语`。没有任何一条释义同时带 v 和古语，所以这张表不生效。释义 1 标 `n`，释义 2 标 `专名`，名词表规则为 `n`、排除 `专名`：释义 1 的上下文是 `{n}`，名词表生效。

### 2.5 解析契约

```js
morphologyMatchContexts(entry)                // → [{ definitionId, tags }]；没有释义时 definitionId 为 null
resolveAutomaticTables(contexts, morphology)  // → { tableIds, contexts: [{ definitionId, tableIds }] }
explainAutomaticTables(contexts, morphology)  // → 每个上下文、每个槽位的判定过程
```

- 三个函数都在共享模型里，所有调用方（模板保存后计算受影响词条、形态分析、搜索投影、分配预览、前端详情、编辑器与试算）都通过它们解析。repository 的 `automaticMorphologyGroupId()` 和前端的旧匹配实现删除。
- `tableIds` 是合并去重后的结果，顺序先按槽位，再按槽位内的表顺序；`contexts[].tableIds` 是每个上下文各自的结果，顺序规则相同。
- `explainAutomaticTables()` 返回每张表的状态和原因，例如"生效"、"被 X 覆盖"、"不满足：缺少 adj"、"不满足：带有排除标签 专名"、"可同时生效"。`resolveAutomaticTables()` 的结果必须与它给出的生效表一致。

### 2.6 行与列

- 非子表有有序的 `rows` 和 `columns`，各至少一项；每项是 `{ id, label }`，ID 由程序按"前缀 + UUID"生成（`mrow-`、`mcol-`）。
- 格、逐词覆写、syncretism 引用都按 `(rowId, columnId)` 定位。子表的格使用链顶表的行列 ID。
- 显示顺序就是列表顺序。标签可以为空，空标签显示为该行（列）的序号。
- 校验（形态模块的 `PUT` 与 JSON 导入）：非子表至少一行一列；行列 ID 在整个形态模块内唯一，导入时与其他实体 ID 一起做完整校验。违反时返回 400 `invalid_morphology_shape`，`details` 指出表 ID 和原因。
- **格名**用 `morphologyCellLabel(table, rowId, columnId)` 生成“行标签·列标签”。syncretism 标注和试算使用当前草稿形状，删除确认中的旧坐标使用已保存形状。

**表头**

- 第一行是列表头，第一列是行表头；表头本身就是标签输入框，标签为空时占位文字显示序号。
- 表头聚焦或悬停时显示拖拽手柄 `⋮⋮` 和菜单按钮 `⋯`。点击 `⋯`、右键表头，或在表头输入框按 `Shift+F10`（或菜单键）都打开同一菜单。有可聚焦输入框时，`⋯` 不另占 Tab 位，输入框标注 `aria-keyshortcuts`。子表的只读表头没有输入框，菜单按钮自身可聚焦。触屏点选表头后仍能点到 `⋯`。
- 菜单项分组：插入（在上方／下方插入行，在左侧／右侧插入列）、移动（上移／下移、左移／右移，标出快捷键）、整行同…／整列同…（见 2.13，不加分组标题）、删除。菜单按可继续加分组的方式实现，多级表头以后作为新的一组加入（第 4 节）。
- 这张表有子表时，插入和删除项旁注明"会同时影响 N 张子表"。
- 行表头一列 `position: sticky`，宽表横向滚动时保持可见。

**操作**

- 插入：菜单在任意位置插入；表格底边的"+ 行"、右边的"+ 列"在末尾追加。插入后焦点落在新行（列）的标签输入框，新格都是还没填（子表里是沿用父表）。不做悬停在行线上出现"+"的插入方式。
- 调整顺序：菜单的上移／下移；在表头输入框里按 `Alt+↑/↓` 移动行、`Alt+←/→` 移动列；拖 `⋮⋮` 排序，拖动时显示插入线。焦点跟随被移动的表头。
- 删除：菜单的删除行（列）。焦点移到相邻的表头。只剩一行（列）时删除项不可用，tooltip 说明原因。
- 子表行列标签只读，表头菜单只提供“整行同…”“整列同…”，编辑的是子表自己的格。表格上方说明形状由哪张链顶表决定，“编辑行列”在同一视图里选中链顶表。结构视图中的“继承自 X”指向直接父表。两种跳转都在同一份草稿内完成。

**删除行列的后果**

- 草稿删除链顶表及其后代在这一行（列）上保存的格记录，并清除直接指向被删坐标的引用记录。链顶表被清除的引用格变为未填写，子表被清除的引用格恢复继承。仍指向有效坐标的引用继续按当前模板解析。
- 被删的行列上如果有逐词覆写（包括子表上的覆写），保存时先确认再一并删除，见 2.12。删除整张表也走同样的确认。

**撤销**

可撤销的操作是删除行列、删除表格（2.13），以及覆盖了已有格记录的“整行同…”“整列同…”（2.13）。

- 两个视图共用一个最近操作提示和“撤销”按钮，放在页面保存区。删除已保存的表或坐标总有撤销入口，包括看起来为空而可能有逐词覆写的行列，以及解除继承后承接已保存坐标的行列。只有纯草稿中无内容的新项可以省略。提示按清除的记录计数，例如“已删除‘呼格’行，另有 2 格的引用变回未填写”“已将‘宾格’行设为同‘主格’（覆盖 3 格）”。
- 撤销应用于当前草稿。记录被删的行列对象、相邻 ID、原位置及连同清除的本表与子表格记录。恢复时优先放在原后一项之前，其次放在原前一项之后，最后按原位置插入。仍在表内的格只在清除引用后未被再次编辑时恢复原引用。
- 删除表时记录表、原槽位及相邻位置。原槽位仍在时插回该槽位，原槽位已空且被移除时恢复槽位，再插回这张表。后来移到其他槽位的表保留当前位置。
- 整行同、整列同记录被覆盖的格记录。撤销时只恢复之后没有再被编辑的格。
- 撤销前校验恢复后的整次操作。若会造成引用环，保留当前草稿并指出冲突，修正后仍可撤销。新建链顶父表后，撤销删除会把行列恢复到新链顶，格和引用恢复到原表。跨链设置父表或解除继承导致本次撤销所需的坐标改址时，该次撤销失效，其他视图切换和无关编辑保留它。
- 每次可撤销的操作记录为一条数据：操作类型、作用对象和恢复所需的记录。提示组件只负责显示和触发撤销。现在只保留最近一条，以后需要多步撤销时扩展为栈。已保存数据的历史记录不属于本计划，随同步的操作日志另行设计（交接文档“同步方向”）。
- 再次执行可撤销的操作、保存成功、放弃更改或成功离开模板页时清空撤销记录。保存失败及取消删除确认时保留提示和撤销。提示不计时。逐词覆写、手动选择和叠加层在确认保存时由服务端处理（2.12）。
- 不绑定 `Ctrl+Z`，以免与输入框自身的文字撤销混在一起。

插入和调整顺序不改动格、覆写和引用；调整顺序只改变显示顺序和合并区域（2.14）。

### 2.7 格的状态与解析

**存储的状态**

| 层级 | 没有记录 | 规则 | 字面形式 | 不存在 | 同某格 |
|---|---|---|---|---|---|
| 普通表（链顶表）的格 | 还没填 | ✓ | — | ✓ | ✓ |
| 子表的格 | 沿用父表 | ✓ | — | ✓ | ✓ |
| 逐词覆写 | 跟随模板 | — | ✓ | ✓ | — |

- 模板里存的是规则，按 lemma 计算出形式；逐词覆写存的是字面形式。
- 规则文本去掉首尾空白后为空，规范化时丢掉，等于没有记录。
- 子表不能显式标"还没填"；逐词覆写不能设"同某格"。

```js
// 模板格：tables[].cells
{ rowId, columnId, kind: "rule", sourceText }
{ rowId, columnId, kind: "absent" }
{ rowId, columnId, kind: "refer", targetRowId, targetColumnId }

// 逐词覆写：morphologyTables[].overrides
{ rowId, columnId, kind: "form", value }
{ rowId, columnId, kind: "absent" }
```

**解析一格**

1. 看这个词在这张表这一格上有没有覆写：写了形式就用这个形式；标了不存在，结果就是不存在。
2. 没有覆写，就从当前表开始沿继承链往上，取第一条记录：
   - 规则：按 lemma 计算；
   - 不存在：结果就是不存在；
   - 同某格：回到第 1 步解析目标格，所以目标格上的覆写和继承都会生效；
   - 到链顶都没有记录：还没填。

**显示结果**

- **形式**：非空字符串，正常显示。
- **空白**：还没填，或者规则计算出空字符串（条件分支没有命中、也没写 else）。详情显示空白。
- **不存在**：详情显示"—"。

解析结果记录最终来源格、是否经由引用取得，以及当前坐标是否直接覆写。详情用这些信息计算合并区域和覆写底色。只有“形式”生成搜索值。

**校验**（形态模块的 `PUT` 与 JSON 导入）

- 每张表里同一个 `(rowId, columnId)` 最多一条记录；坐标必须落在表（子表为链顶表）的形状之内；字段必须与 `kind` 相符。
- 违反时返回 400 `invalid_morphology_cell`，`details` 指出表 ID、格和原因。引用相关的校验见 2.9。

### 2.8 表继承

用于不规则子类：子类只在少数几格上与某张表不同。子表显式指定父表，只写不同的格。

**语义**

- `inheritsFrom` 指向同一形态模块里的另一张表，不要求在同一槽位。父表的父表也照样生效，形成一条继承链；允许多层，不设层数上限。
- **形状沿用链顶表**：子表的行列和行列标签都取自链顶表，不能单独修改。链顶表增删、调整行列，子表随之变化；新插入的行列在子表里都是"沿用父表"。
- 子表的格可以没有记录（沿用父表），也可以写规则、标不存在或设同某格，覆盖父表。解析顺序见 2.7。
- **继承只决定内容，不参与分配**：
  - 子表有自己的匹配规则、槽位、标题和备注，这些都不从父表继承；
  - 父表是否对当前词条生效、在不在同一槽位，都不影响子表的内容；
  - 通常把子表放进父表的槽位，用更具体的规则覆盖父表。例如父表"名词二变"的规则是 `{n, 二变}`，子表"二变不规则"是 `{n, 二变, 不规则}`。
- 词条覆写照常按"词条 + 子表 + 格"记录，继承来的格也可以覆写。

**新建、设置父表与解除继承**

- 卡片菜单的“新建父表”在同一槽位把新表插在现表前面，选中新表并聚焦标题。新父表的标题、备注、匹配规则和自有模板格初始为空。现表已有父表时，新表插在它们之间并继承旧父表。现表是链顶时，新父表接管原行列及其名称、顺序和 ID，整条继承链继续使用原坐标。现有表继续持有各自的模板格、匹配规则、表 ID 和逐词覆写。
- 独立表追认父表和已有子表改换父表共用“设置父表”入口。可从任意槽位选表。自身、后代和当前直接父表不可选。
- 同链候选沿用同一套行列 ID，选择后更新草稿的直接父表。跨链候选的有效形状必须行数、列数分别相同。确认后按此刻草稿的行列顺序一一对应，迁移该表和后代的模板格、syncretism 引用两端及逐词覆写。表 ID 和匹配规则继续归各自的表。跨链确认写明目标父表、位置对应和表头变化，并说明沿用父表的格将从新父表取值。
- **解除继承**：这张表成为新的链顶表。
  - 复制链顶表当时的行列，生成新的行列 ID；
  - 原来沿用父表的格，复制沿链解析出的那条记录（同某格的目标换成新 ID）；
  - 这张表自己的格、这张表上的逐词覆写，以及它所有后代表的格和逐词覆写，都换到新的行列 ID 上。
- 草稿按表记录新行列承接的已保存坐标。多次跨链换父表和解除继承可以同次保存，合成“已保存 ID → 本次最终 ID”。源表与目标链上的原有表分别保有各自的坐标对应。插入的新轴没有旧坐标，删除的轴从映射省略，撤销删除会恢复仍适用的承接关系。服务端凭 `coordinateMappings` 重定位已有覆写。[API 契约](API_CONTRACT.md#形态分配与保存)
- **删除被继承的父表**：返回 409 `morphology_table_has_children`，`details` 列出子表 ID；界面提示先解除这些子表的继承。

**边界校验**

- `inheritsFrom` 必须指向同一模块里存在的表，链上不能有循环；
- 子表不能带 `rows`、`columns`；
- 违反时返回 400 `invalid_morphology_inheritance`，`details` 指出表 ID 和原因。

**不处理的跨变化类不规则**

例如俄语的重音类型与变格类交叉，同一种移重音模式出现在不同的变格类里；又如在任何变化里都缺同样几格的缺项词。这类不规则是在底表产出的形式上再做一层操作，而不是另填一套成品形式，归第 3 阶段规则引擎（格内条件、作用于其他槽位输出的操作层，见第 4 节）。在那之前，缺项词可以用逐词覆写的"不存在"处理。

### 2.9 Syncretism

系统性 syncretism（拉丁语中性名词主格 = 宾格、俄语动物性阳性名词宾格 = 属格）用"同某格"状态表示；偶然同形不标记。

- "同某格"指向同一张表（子表为链顶表的形状）里的另一格，有方向：编辑来源格，指向它的格跟着变。子表里的引用在子表自身里解析：目标格先看子表自己的记录，没有再沿链往上。
- **引用在最后一步解析**：先叠好逐词覆写和继承，再按引用取值（2.7）。因此：
  - 某个词的属格不规则，覆写属格，宾格自动跟着变；
  - 动物性宾格不需要条件引用：子表"阳性动物名词"继承"阳性名词"，只把宾格设为"同属格"；
  - 将来分析或搜索可以区分系统性 syncretism 和偶然同形。
- 词条在引用格上写了自己的形式，就是只对这个词断开引用；清空后恢复跟随。
- 允许链式引用（A 同 B，B 同 C）。目标是"不存在"时，结果也是"不存在"；目标还没填时，结果是空白。

**校验**

- 目标必须落在形状之内，不能指向自己；
- **循环按每张表叠好继承后的完整格局检查**：父表里 A 同 B、B 写了规则，父表本身没问题；子表把 B 设为同 A，叠上继承后 A 同 B，就成了环。逐词覆写不能产生引用，所以不会引入新的环；
- 违反时返回 400 `invalid_morphology_cell`。

### 2.10 词条数据

```js
morphologyMode: "auto" | "manual",
morphologyTables: [{ tableId, notes, overrides: [Override] }],   // Override 见 2.7
```

- 覆写按"词条 + 表 + 格"记录。同一张表无论因为哪个上下文生效，都只有一份覆写。
- **自动模式**：`morphologyTables` 只是叠加层（备注、覆写），挂在解析出的表上；没有内容的叠加层丢弃，解析不到的表的叠加层作为休眠叠加层保留。与现行语义相同，只是单位从组变成表。显示顺序跟随模板的槽位顺序。
- **手动模式**：`morphologyTables` 是用户显式选择的有序表列表，显示顺序就是这个列表的顺序。
- 每张表可以写一条词条级备注；词条级的组标题不再存在（转换见 2.15）。
- 校验：覆写坐标必须落在表的形状之内，同一格最多一条，字段与 `kind` 相符；违反时返回 400 `invalid_morphology_override`。

### 2.11 SQLite

槽位、模板表、行列、模板格和逐词覆写存入 SQLite 结构表。格与覆写的坐标为行列 ID，子表使用链顶表的行列。匹配规则存为 JSON，形态函数识别对象仍在形态模块 blob 中。[SQLite 后端规范](SQLITE_BACKEND_SPEC.md#54-形态学结构化-schema)

旧库先用旧版导出 JSON，再导入当前结构的新库。

### 2.12 派生与写入

- **搜索投影**：按合并后的生效表 → 格生成，只为"形式"生成记录；`sourceType: "morphology"`、`sourceId: <tableId>` 不变，`sourcePosition` 按显示顺序编号。
- **写入计划**（`morphology-write-plan.js`）：
  - **生成变化**按表判断（`generationTableIds`）：格的记录、行列的增删，或所用函数变化。一张表的格或行列变了，沿链向下的全部后代也算生成变化；改 `inheritsFrom` 或解除继承时，这张表及其后代都算生成变化。继承关系不算分配变化。
  - **分配变化**：任一表的 `matchRules` 变化、表在槽位之间移动、表的增删。比较规则时将每行的 `all`、`none` 转成排序后的结构化键集合，再整体排序所有规则行。规则顺序、行内标签顺序、首尾空白和重复的规则行不影响分配。修改标签大小写会触发重新分配。判断由共享模型的 `morphologyAssignmentKey(morphology)` 给出：按表 ID 排序的 `[tableId, slotId, 规则键]` 列表，规则键即上述去重排序后的规则行；两份规范化模块的键不同即为分配变化。写入计划与模板页的保存前影响（2.13）用同一个函数。前端只对 `morphologyForSave()` 转换后的草稿算键，也就是保存时实际提交的规则：编辑过的规则输入框先存为文本、提交时才拆分（2.13），直接对草稿算键会漏掉这类修改。
  - **只改顺序**（槽位顺序、槽位内顺序、行列顺序）不影响哪些表生效，也不改变格的值，只重写搜索投影的 `sourcePosition`。
  - **行列标签**只影响显示和格名，不触发投影重建。
  - **删除会丢失词条数据时先确认**：删除表或行列时，如果有词条引用会随之消失，服务端在写入前返回 409 `morphology_references_in_use`，整次不保存。引用包括：手动模式选了这张表（`manual_table`）、自动模式在这张表上的叠加层（`overlay`，含休眠叠加层），以及落在被删表或行列上的逐词覆写（`override`，含后代子表上的覆写）。
    - `details` 提供 `{ referenceCount, targets: [{ tableId, rowId?, columnId?, label, entryCount }], references }`。`references` 是至多 50 条 `{ entryId, lemma, tableId, rowId?, columnId?, reason }`。弹窗按删除目标显示 `entryCount`，示例按词条 ID 去重。总 `referenceCount` 按记录计，同一词条也可出现在多个目标里。被清除的模板 syncretism 引用由草稿另行统计。
    - 确认后用原请求快照重发，附 `confirmReferenceRemoval: true` 和用户在弹窗里看到的摘要 `confirmedReferences: { referenceCount, targets: [{ tableId, rowId?, columnId?, entryCount }] }`。服务端在保存事务里重算引用；摘要一致时清除引用并保存模板，不一致时整次不执行，返回新的 409 摘要重新确认。
    - 确认弹窗独立于离开确认，打开时只允许操作最上层弹窗。取消后返还焦点，保留整份草稿和最近删除的撤销。点示例词条先关闭删除确认并结束本次保存尝试，再走统一的未保存检查跳转。若此时选择保存，可以重新进入删除确认。
    - 仍被继承的父表不走这个流程，返回 409 `morphology_table_has_children`（2.8），因为要先处理的是其他表，不是词条数据。
  - 表在槽位之间移动不改变覆写的归属，不需要引用检查。
- **形态分析**使用现有 `morphologyAnalysis`。模板页的当前词条数取 `tables[].assignedEntryCount`，以 `tableId` 关联并使用 `table` 分类跳转。覆写统计由 `overrideTables[]` 提供。[API 契约](API_CONTRACT.md#分析功能结果与质量查询)
- **分配预览端点**（2.13 的"保存前影响"，阶段 3 实施）：
  - `POST /api/dictionaries/:id/morphology/assignment-preview`，请求体只含决定分配的部分：`{ slots: [{ id, tables: [{ id, matchRules }] }] }`，取自 `morphologyForSave()` 的结果，与保存提交的规则相同，其余字段忽略。请求体上限与形态保存相同。表和槽位的 ID 可以是草稿里尚未保存的 ID，服务端只用来标识结果。
  - 校验复用 `PUT /morphology` 中槽位、表 ID 和规则的校验函数与错误码：`slots` 不是数组、槽位为空或槽位 ID 不是字符串返回 400 `invalid_morphology_slot`，规则行按 2.2 返回 400 `invalid_morphology_match_rule`，表不是对象或表 ID 不是字符串返回 400 `invalid_morphology_payload`，槽位与表之间的重复 ID 返回 409 `duplicate_entity_ids_scoped`。与保存的唯一差别：保存允许新槽位和新表省略 ID，预览要求每个槽位和表都带 ID（结果要按 ID 对应），缺少或为空时返回 400 `invalid_morphology_payload`。格、行列、继承和形态函数不参与，所以表格视图里尚未修正的格错误不妨碍预览。
  - 服务端用当前已保存的模板和请求中的分配各解析一次自动模式词条，按词条比较合并后的生效表集合，只改顺序不算变化。返回 `{ changedEntryCount, gainedByTable: [{ tableId, entryCount }], lostByTable: [{ tableId, entryCount }], sampleEntries: [{ entryId, lemma, gainedTableIds, lostTableIds }] }`。两张表级列表只含计数大于 0 的表：`gainedByTable` 按请求中的表顺序，`lostByTable` 按已保存模板的表顺序，草稿删掉的表也在其中。
  - `sampleEntries` 按词条顺序取前 20 条，不返回完整 ID 列表。手动模式词条不参与。只读，不写入任何数据，也不推进查询会话 generation。
  - **匹配输入缓存**：解析只依赖每个词条的上下文标签列表（2.4），服务端把自动模式词条按这份列表聚合成 `{ contexts, entryCount, sample }`，`sample` 保留该组按词条顺序的前 20 个 `[position, entryId]`。每组只解析一次，示例的 lemma 最后按 ID 补读。聚合结果按词典缓存在进程内，与查询会话一起失效（词条、标签或模板写入后清除），第一次预览时建立。

### 2.13 模板页

模板页仍是导航里的一个目的地（“形态表格”）。页内用文字标签切换两个视图。

- **结构视图**：分配。槽位结构、匹配规则、表的继承关系、分配试算和词条数。
- **表格视图**：内容。行列与格，附词形试算。

页面标题旁的说明按钮打开匹配规则（行内条件、行间关系）、槽位分配（竞争与并列生效）、词条数口径和形态语法说明。

**草稿与保存**

- 页面控件放在页头（视图的 `.top-bar`），结构与语言文档页相同：标题在左，右侧依次为“结构 / 表格”分段控件、保存状态、“放弃更改”（次要按钮）和“保存”（主按钮）。只在部分状态出现的内容在页头下方另起一行：窄屏的“试算”“属性”或选表下拉框、最近操作的撤销提示、设置父表提示。页头吸顶，用页面自身的背景（液态玻璃为固定的页面渐变），不画分隔线，滚过的内容在它下缘 12px 内淡出，与词条列表的边缘渐隐一致；移动端接在应用顶栏下方。控件换行到标题下方时标题随主区滚走，只有控件吸顶。撤销提示可换行，保存按钮留在原位。
- 两个视图共用当前词典的一份形态草稿及已保存基准。切视图和选表保留当前编辑与试算输入。“保存 / 放弃更改”作用于整份草稿。首次打开进入结构视图，返回时按词典恢复仍存在的视图选择和表 ID。选择、滚动、试算输入和菜单状态只在进程内有效，也不计入未保存更改。
- 离开模板页、切换词典、按用量跳转及从删除确认跳到示例词条走现有未保存检查，浏览器关闭沿用现有退出检查。放弃时清除草稿及其行列映射，失败或取消时保留原输入。未填写的全空规则行可忽略，仍在编辑的无效字段也属于草稿。
- 保存时捕获同一份模板与坐标映射快照。请求和删除确认期间暂停修改草稿，确认重试使用原快照。成功后以响应更新已保存基准，保留仍有效的表选择。保存失败时保留草稿及撤销记录，服务端的校验错误定位到对应的表、规则行或格。

**宽度**：整页不限宽，与[工作页宽度](STYLE_SKIN_PLAN.md#工作页宽度)中"内容用得上宽度的页面保持铺满"一致；宽屏下靠页内元素的宽度上限避免拉伸，具体取值见两个视图。像素值是实现取值，实装时在 1280px、1280×610 和 1920px 下调整。

**表的名称**：标题为空的表在卡片、表格列表、试算原因、手动模式选表、确认弹窗和分析页里统一显示“未命名表格”，用次要文字色。需要在同名表之间选择时，用槽位和表在其中的位置区分。词条详情里没有标题就不显示标题行。

#### 结构视图

工作区宽度达到 760px 时，主区显示槽位列表，右栏吸附在页头下方，上方为分配试算，下方为选中表的属性。右栏约 320–360px，表卡片约 220–320px，多张卡片可以换行。过长的判定详情和属性字段各自在右栏内滚动。矮窗口默认收起判定详情，保留试算输入、上下文切换和生效表数量。

工作区较窄时，页头第二行显示“试算”和“属性”。“试算”旁显示当前词条或标签摘要。两个入口在同一个右侧抽屉中分别打开试算和当前表的属性。按 `Esc` 或点“关闭”返回触发控件，保留草稿和页面滚动位置。抽屉中按 `Ctrl+S` 保存整份草稿，抽屉保持打开。工作区变宽时，打开的面板回到右栏，并保留正在编辑的输入和焦点。

**槽位列表**

- 每个槽位是一条横条，按显示顺序纵向排列；槽位里的表以卡片形式在横条内并排，顺序就是槽位内顺序，放不下时换行。
- **只含一张表的槽位**：虚线横条，不显示槽位名，看起来就是一张普通的表卡片。
- **含两张以上表的槽位**：实线横条，左端显示可就地编辑的槽位名。
- **表卡片**：标题、规则芯片（如 `n, 不规则`、`排除：专名`）、当前词条数；子表另显示"继承自 X"。
- **覆盖关系**：同槽位内，Y 的某一行比 X 的某一行更具体，就说 Y 覆盖 X 的这一行。X 的每一条规则行都被 Y 覆盖时，Y 的卡片标“覆盖：X”；只覆盖一部分时标“部分覆盖：X”，可展开查看是哪几行。例：X 有一行要求 `n`、另一行要求 `古语`，Y 要求 `n, 不规则`，Y 只覆盖 X 的名词行，标“部分覆盖：X”，只带古语的上下文仍可能用 X。卡片保持用户排的顺序。关系由共享模型的行级判断算出，只重算变动的槽位；具体词条用哪些表由分配试算说明。
- **调整槽位顺序**可拖动横条左端的 `⋮⋮`，或在手柄上按 `Alt+↑/↓`。点击手柄、在手柄上按 `Shift+F10`，或右键点击槽位空白处，均可打开“槽位操作”菜单上移或下移槽位。
- **调整槽位内顺序**可以拖卡片、在卡片上按 `Alt+←/→`，或用卡片菜单前移／后移。拖动时按显示行及行内卡片中点判定插入位置。一行末尾、行间空隙和下一行开头指向同一位置，插入线画在下一行第一张卡片之前。整组末尾的线画在最后一张卡片之后。
- **拖动预览**在起拖时读取候选项相对于容器的位置，排版变化时重测，随容器滚动换算指针坐标。落点变化时才更新指示，顺序实际变化时才写入草稿。
- **建立和解除竞争**：拖进另一槽位与“移到槽位…”都追加到目标末尾。在多表槽位选“移出为独立槽位”时，新槽位紧跟原槽位。一次排序或移动统一按 ID 写入草稿，拖拽仅在落点确认时提交，菜单和快捷键走同样的操作。
- **新建表格**可从槽位列表下方的按钮或“槽位操作”菜单进入。列表下方的按钮为新表建一个独立槽位，放在当前选中表所在槽位之后，没有选中时放在最后。菜单里的“在此槽位新建表格”把新表追加到该槽位末尾。两种入口都选中新表并聚焦标题输入框，窄屏打开属性抽屉。
- 卡片菜单可用 `⋯`、右键或卡片聚焦时的 `Shift+F10` 打开。支持前移／后移、移到槽位、移出为独立槽位、新建继承此表的子表、新建父表、设置父表、编辑格和删除表格。新子表放在父表所在槽位并紧跟父表。子表另有解除继承。
- “设置父表”在当前槽位列表内高亮候选，保留槽位分组和顺序。同链卡片以强调色浅底标记“共用行列”，跨链卡片以警告色浅底标记“按位置对应”。不可选的卡片灰显并写明原因。页头显示正在设置的表和“取消”。键盘可以用 Tab 选择候选，按 Enter 确认选择，按 Esc 取消并回到源表卡片。
- **删除表格**：从草稿里删掉这张表，可以撤销（2.6）。仍被草稿里其他表继承的表，删除项不可用，tooltip 提示"先解除 N 张子表的继承"，与服务端的 409 `morphology_table_has_children`（2.8）一致。会带走词条数据时，保存时走 2.12 的确认弹窗。

**选中表的属性**（右栏下方）

- 标题、备注、父表（"继承自 X"）。
- **匹配规则**按行编辑。每行有“同时包含”和“排除”两个输入框，写法与词条标签输入相同（分隔符分隔的文本，三种分隔符都支持）；行与行之间显示“或”，下方有“＋ 或者”。提交时忽略两个框都为空的行。用户没有改动过的输入框，保存时原样保留原来的标签数组，不重新拆分，所以导入数据里带分隔符的标签不会因为保存而被拆开；改动过的输入框按分隔符拆分。
- 未使用标签提示复用同一词典版本的 `/tag-registry` 使用数。成功读取后，未登记或使用数为零的标签在该行提示“没有词条使用此标签”。比较使用区分大小写的结构化键，提示不阻止保存。加载中或失败时不判断是否使用，规则输入保持可编辑。
- "编辑格 →"切到表格视图。

**分配试算**（右栏上方）

- **输入**有“输入标签”和“选择词条”两个入口。标签输入在本地试算。选词条复用来源候选端点及候选列表交互，确认时按 ID 读取一条完整详情，以取得逐条释义的标签。搜索候选时保留防抖和过期响应检查，换词、换词典或退出后丢弃旧结果。选了手动形态词条时，说明这是用该词条标签试算自动分配。
- **输出**使用 `explainAutomaticTables()`。一个上下文中，标出“生效”“同时生效”“被 X 覆盖”和未匹配原因。缺少必需标签与带有排除标签按规则行解释。没有匹配规则的表显示相应状态。仅输入文本但尚未选择词条，或标签输入为空时，卡片不显示判定。
- **多个上下文**用“合并 / 释义 N …”切换，默认“合并”。“合并”说明各表在哪些上下文生效。“释义 N”显示该释义的标签来源和各表判定。编号和“词条标签”项按 2.14。只有一项可试算时省略切换。
- 规则使用草稿即时试算。空规则行跳过，必需标签为空或同一标签同时出现在两边时，定位到出错行并暂停分配试算。选词需要读取数据，编辑规则及切换已加载的上下文在本地完成。格内容的错误由词形试算和保存处理。

**影响范围**

- **当前词条数**从已保存版本的 `morphologyAnalysis` 摘要读取。新建未保存的表显示“尚未保存”，摘要加载和失败各自呈现，只有成功返回的零才显示 0。标题旁的说明弹窗注明词条数基于已保存的配置。点击用现有 `table + tableId` 筛选跳至词条列表，完成未保存检查后以当前已保存的版本与表 ID 发出查询。
- **保存前影响**（阶段 3）：草稿（经 `morphologyForSave()` 转换）与已保存版本的 `morphologyAssignmentKey()` 不同时才计算。只改顺序、标题、备注、继承或表格内容不计算。
  - **何时请求**：编辑停止约 400ms 后发出，只保留最新一个请求，迟到的响应按词典和草稿键丢弃。以下情况一律清除结果，并同时取消待发的防抖和在途请求：草稿的分配键回到已保存版本（包括撤销）、放弃更改、保存成功、确认离开模板页或切换词典。离开时选“取消”则照常继续。有规则行错误时同样取消，显示“匹配规则有误，修正后再计算影响”，与分配试算暂停的条件相同。
  - **影响条**：结构视图主区顶部、槽位列表上方一条，所有宽度下位置相同。统计只覆盖自动分配的词条，文案写明这一点：“保存后，自动分配的词条中有 N 个会增减变化表”，N 为 0 时写“自动分配的词条不会增减任何变化表”。手动选表的词条会因删表而失去选择，这由保存时的删除确认（2.12）列出。展开后按表列出“+增加 / −减少”的词条数，以及示例词条：词形和它增减的表。草稿已删除的表用已保存版本的标题并标“已删除”，未保存的新表用草稿标题，空标题显示“未命名表格”。
  - **卡片**：词条数一行后追加“保存后 +12 −3”，增加用强调色，减少用次要文字色，没有变化不显示。草稿已删除的表只在影响条里列出。
  - **示例词条**：点一个示例，把它载入分配试算（“选择词条”模式，与从候选中选中相同），试算按草稿说明它为什么增减了这些表。不离开模板页，不经过未保存检查。窄屏同时打开试算抽屉。试算只列草稿中的表，所以草稿已删除的表由影响条上的“已删除”说明，试算不另作解释。
  - **状态**：从草稿键变化（防抖开始）到当前键的结果返回之前，影响条只保留上一次的总数并标“正在更新”；表级明细、卡片上的增减和可点击的示例只显示与当前草稿键对应的结果，因为旧结果里的表可能已从草稿中删除，旧示例载入试算也对不上。第一次计算显示“正在计算影响”。失败时显示可重试的错误。保存不被预览阻塞，预览失败也不影响保存。

#### 表格视图

工作区够宽时，左侧表格列表（约 200px）吸附在页头下方，按开始位置和吸顶位置计算可见高度上限。列表内容少时使用自然高度。右侧只挂载选中表的网格和词形试算。网格按内容确定列宽并靠左，超宽部分在网格内横向滚动，行表头保持 `sticky`（2.6）。空间不足时将选表下拉框放进页头第二行。词形试算的结果表也在自身容器内滚动。

**表格列表**：按槽位顺序列出所有表，多表槽位以槽位名作分组标题，单表槽位不加标题。只用于切换要编辑的表，不能在这里排序或移动；这些操作在结构视图。

**表格编辑**

- 顶部是标题输入框（与结构视图的标题是同一字段），下方一行摘要：规则芯片、所属槽位、"继承自 X"，以及"在结构中编辑"链接。备注、规则和继承只在结构视图编辑。
- 行列的表头、插入、移动、删除和撤销见 2.6。
- 每格显示它的状态：
  - 规则：可编辑的规则输入框，写法和校验不变（`applyMorphologyRuleSyntax()`、引用语法校验）；
  - 不存在：单独样式，标"不存在"；
  - 同某格：显示"= 格名"，用次要文字色；
  - 链顶表还没填的格：占位文字"未填写"；
  - 子表没有记录的格显示“继承”，旁边标出继承来的规则文本、直接引用格或不存在。生成结果在词形试算里查看。
- **格的菜单**提供标为不存在、设为同…，以及去掉这一格记录的操作：链顶表写“清除内容”（变回未填写），子表写“恢复继承”（重新沿用父表）。入口与表头菜单相同。格没有规则输入框时仍有可聚焦的目标，`Shift+F10` 在它上面打开菜单。触屏点选格后可点 `⋯`，避免用长按触发文字选择。
- “设为同…”进入选格模式，点目标格或用方向键加 `Enter` 确认，`Esc` 取消。选格期间这些键由选格处理，退出后焦点回到来源格。菜单本身支持方向键、确认、`Esc` 和焦点返回。未接管的键继续按原输入框行为处理，输入法组字中沿用现有键盘保护。
- “整行同…”按同列建立引用，“整列同…”按同行建立引用。一次应用整行或整列，覆盖这一行（列）里已有的记录，可以撤销（2.6）。数据仍逐格存储，之后新加的列（行）不会自动跟随。改变引用图的操作先校验候选结果，覆盖受影响的表和后代。离散操作（包括删除行列时子表恢复继承）形成新环时保留操作前的草稿并指出冲突。按组成环的格判断是否为新环，表里已有的环不掩盖新环，删除操作消除已有的环照常允许。文本输入造成无效规则或引用时保留原输入，暂停依赖它的试算。复用匹配、继承与引用的纯校验部分，服务端保存仍执行完整边界校验。
- 表格编辑逐格显示，保留各自的编辑坐标。

**词形试算**

表格编辑只显示规则、"= 格名"和占位文字，看不到最终形式；词形试算补上这一点。

- 表格编辑下方有一个示例词形输入框，下方按页面上的**草稿**显示当前表算出的形式，编辑规则、格的状态、继承或行列时即时更新，不发请求。
- 词形试算使用模板草稿，子表沿继承链取值。渲染与详情相同，按 2.14 合并 syncretism 区域和连续的“不存在”。
- 输入框为空时不显示结果。选择一个词条后，词形为空或仍为自动填入的值时更新为该词条的词形，手输示例保留。影响当前表生成的语法或引用错误时暂停结果并标明位置。编辑格时保留当前输入节点及焦点，使用同一轮草稿解析更新依赖格和试算。

### 2.14 词条侧

**详情**

- 表标题下显示词条级的表备注。形态分区沿用词条区块排序和“显示空分区”设置。隐藏空分区时，仍可从完整编辑里配置尚无生效表的词条。
- 详情分组、编辑器标记和分配试算共用按释义 ID 生成的显示标签。编号沿用详情的可见释义顺序，只有标签的释义同样编号。无释义的上下文标为“词条标签”。
- **按适用释义分组**。每张生效表只显示一次，适用同一组上下文的表放在一起。组内沿用槽位及槽位内的表顺序。
  - 所有上下文共享的表放在最上方。有其他组时标“共用”。只适用部分上下文时，组头标出对应释义，例如“释义 1、3”，即使只有一个可见组。
  - 部分适用的组按第一条适用释义所在的上下文顺序排列。第一条相同的组按首张表的顺序排列。
  - 同组的小表按内容宽度并排，可完整容纳的组也可并排。空间不足时换行，超宽表在各自的表内横向滚动。
  - 手动模式按词条保存的选表顺序排列。
- **“不存在”**显示“—”，可访问文本为“不存在”。空白保留空单元格。
- **合并显示**基于解析完继承、覆写和引用后的结果。最终来源相同的形式和最终结果为“不存在”的格分别按上下左右相邻求连通区域。各区域各显示一次形式或“—”。空白及各自生成的同形形式按格显示。
  - 详情和词形试算共用只读表格渲染器，格值每张表只解析一次。普通表使用带行列表头的原生 `<table>`。有合并时，视觉表在内接矩形左上格设 `rowspan`／`colspan`，清除区域内的边线并保留外轮廓。视觉表从无障碍树隐藏，同时用同一组格值输出一张视觉隐藏的原生语义表，逐坐标保留单元格与行列表头。横向滚动容器仍可用键盘操作。
  - 候选内接矩形覆盖同一区域内覆写状态一致的格。优先选面积最大的，再依次按接近区域重心、列数更多、位置靠上及靠左决胜。
- **词条直接覆写的坐标**用 `--ui-warning-badge-background` 标出底色，包含覆写为“不存在”的格。语义表在格值后标“已覆写”。

**编辑器**

- 完整编辑与形态局部编辑共用同一套形态草稿和收集逻辑，每张表各有词条级备注和覆写，随原有词条保存送出。自动模式按槽位顺序显示生效表及其释义标签。完整编辑中的词形、词条标签、释义及释义标签使用将要保存的草稿内容更新形态。表离开生效列表时，原备注和覆写成为休眠叠加层，重新生效时恢复。
- 覆写格：
  - 没有覆写时，显示模板算出的形式作为占位文字。模板结果若为不存在，标出“模板中不存在”；词条显式标记的格显示“覆写为不存在”。两种状态下都可输入字面形式。
  - 覆写过的格下方标“已覆写 · 模板 X”（模板结果为不存在时写“模板中不存在”），看得出它与模板不同。
  - 格的菜单可以标为不存在，或“恢复模板结果”（去掉这一格的覆写）；入口与模板页格的菜单相同（`⋯`、右键、`Shift+F10`，2.13）。
  - 同某格的格旁边标出直接目标格。占位形式随来源格的覆写即时更新。在这里写形式会断开这一格的引用，恢复模板结果后重新跟随。更新相关格时保留正在输入的控件和焦点。
- 编辑器逐格显示，保留各自的编辑坐标。
- 有词条备注或覆写的表默认展开，其余折叠；展开状态只在进程内记住。
- **未生效的覆写**：自动模式下词条有休眠叠加层时，形态区底部显示“未生效的覆写：N 张表”，说明重新匹配到这些表时会恢复。“查看”只读展开每张表的覆写和备注；“删除”用危险样式，经独立确认弹窗（例如“删除‘不规则名词’上的 2 格覆写和 1 条备注？这个词以后重新匹配到这张表时也不会恢复”）后从词条草稿删除这些叠加层，随词条保存生效。
- 手动模式支持添加、排序和移除表，显示使用手动列表的顺序。移除表会从当前词条草稿中一并删除该表的备注与覆写，随词条保存生效；这张表有备注或覆写时，按钮写“删除”并用危险样式，先经独立确认弹窗。
- 切到手动时通过 `materializeAutomaticMorphologyTables()` 按当前显示顺序带入生效表，再带入休眠叠加层。恢复自动时按规则重新选择和排列，含备注或覆写的记录保留为叠加层。

**分析页**保留现有按表统计和词条筛选。在表统计行提供模板编辑入口，经统一未保存检查进入模板页，并按表 ID 选中目标。词条数仍链接到对应词条列表。

### 2.15 转换（旧 JSON 导入）

转换集中在 `lib/legacy-dictionary-migration.js`；核心规范化模块只处理新形状。更早的 `morphology.tables[]` 形状已有迁移路径，先转成旧组形状，再走同一个转换。

**模板：结果完全不变**

旧规则是"组按顺序排列，任一标签命中，只取最前"。设旧组依次为 G1…Gn，Gi 的标签集合为 Ti。

- **规则**：Gi 的每张表获得同一组规则。Ti 中每个标签 t 各成一行，`all: [t]`，`none` 为排在前面的所有组的标签之并 T1 ∪ … ∪ Ti-1。
  - 如果 t 已经出现在前面的组里，这一行在旧规则下永远轮不到，直接丢掉；
  - 如果 Gi 的行全部被丢掉，规则为空，这张表不会自动匹配。旧规则下它同样永远不会生效。
- **槽位**：每张旧表各成一个独立槽位，槽位顺序 = 先按旧组顺序，再按组内顺序。生成的规则保证不同旧组不会同时成立，同一旧组的表规则相同、一起生效，所以每个词条生效的表格集合与转换前相同，显示顺序也相同。
- **行列与格**：按旧的行列数生成行列 ID，行列标签照抄；原来的 `"r,c"` 对应到新的行列 ID。旧界面自动填入的序号标签（"1""2"……）和用户写的标签分不出来，一律照抄成文字，插入行列后不会自动重新编号。`sourceText` 非空的格转成 `rule`，空格丢掉，即还没填，所以详情显示与转换前相同。
- **旧组名**：表标题为空时用组名补上；不为空时，在表备注开头写入组名，例如"原形态组：名词"。
- **旧组的模板备注**：写入该组第一张表的 `notes`，与组名分行。

生成的排除列表可能较长。转换只负责结果不变，之后用户可以借助分配试算，改用槽位和具体程度来简化。

转换生成的规则对任何一个标签集合，都给出与旧规则相同的结果。旧规则对每个词条只用一个集合（有效标签），转换后按释义每条一个集合（2.4），所以：

- 释义都没有标签时只有一个上下文，结果与转换前完全相同；
- 释义带标签时，每条释义得到的表，等于旧规则对"词条标签 ∪ 这条释义标签"的结果。比如释义 1 标 `n`、释义 2 标 `v`，旧规则只给排在前面的名词组，转换后释义 2 另外得到动词的表，详情按适用释义分组。这是按释义匹配的预期结果。

转换契约用释义都没有标签的词典验证结果逐一相同，另用带释义标签的词条验证上面的逐释义对应关系。

**词条**

- **覆写**：旧 `overrides[tableId]["r,c"]` 转为该表的 `{ kind: "form", value }`，坐标换成行列 ID。旧模型里一张表只属于一个组，所以不会冲突。
- **手动模式**：所选组按顺序展开为它们的表。
- **自动模式叠加层**：按表拆开。旧组的词条级备注写入该组第一张表的叠加层备注；词条级组标题非空时，写在这条备注的开头，例如"原标题：……"。
- **休眠叠加层**：同样按表拆开保留。

## 3. 设计取舍

**为什么是"表格直接匹配 + 槽位 + 槽位内 elsewhere"**

- 组合是默认行为，竞争要显式声明（放进同一槽位），具体程度自动决定胜负，不依赖顺序；
- 只有一套顺序：槽位及槽位内表的顺序只用来排列生效表，不决定哪些表生效；
- 只含一张表的槽位就是一张普通的表，简单词典无须了解槽位；
- 覆写天然按表记录，不存在同一张表的两份覆写；
- 数据结构是一对多（槽位 → 表），没有多对多关系；
- 和 Paradigm Function Morphology 的规则块对应，以后规则引擎也有现成的理论框架可依。

elsewhere 的结果由规则自动计算，不看试算很难判断一张表为什么没生效，所以编辑界面以分配试算、具体程度关系和影响范围为中心。

**分配方式上排除的做法**

- **保留组，只取最前**（现状加上结构化规则）：组合仍要复制表格。
- **保留组，所有满足规则的组都生效，二选一靠排除条件**：二选一必须手写排除，漏写就会多出变化表；转换要生成排除列表，而且这种排除会永久成为维护负担。
- **保留组，组引用独立的表，组之间按 elsewhere 比较**：需要"组 ↔ 表"的多对多关系，而且组必须写成完整的变化表。"槽位 + 相同规则"就能起到组的打包作用，少一层实体。
- **去掉组，所有表之间统一按 elsewhere 比较，不设槽位**：会误伤组合关系。"不规则形容词名词性变化" `{adj, 不规则}` 比"级" `{adj}` 更具体，会把级表也覆盖掉，而它们根本不是竞争关系。
- **槽位可选，表另有全局顺序**：同时存在两套顺序，容易混淆；"无槽位"还是一个需要单独处理的特例。
- **槽位用自由文本标签，而不是实体**：改名要逐张表修改，拼写不一致时会悄悄拆成两个槽位，也无法承载显示顺序。
- **文本表达式**，如 `(n | adj) & !专名`：需要解析器和转义规则，会和第 3 阶段的规则语法重复；嵌套的"或"也让具体程度无法用集合包含判断。
- **具体程度关系可手工编辑**：会让"规则"与"覆盖关系"两个来源互相矛盾。
- **比较具体程度时不算排除条件**：排除条件就成了只决定成立与否、却不参与竞争的特例，elsewhere 也不再等同于逻辑蕴含。
- **平局时做静态冲突提示**：要分析所有可能的标签组合，成本高；分配试算已经能标出"可同时生效"。

**匹配上下文**

- **只用一个上下文，即有效标签**（词条标签 ∪ 所有释义标签）：更简单，和筛选口径一致，但规则用了"且"或排除、而相关标签分在不同释义上时会出错：释义 1 标 `n, 古语`、释义 2 标 `v` 时误匹配"`v` 且 `古语`"；释义 2 标 `专名` 时名词表被误排除；随释义变化的屈折（hang 的 hung／hanged）只剩更具体的那张表。按释义匹配的代价是要求词级属性标在词条上，详情中的释义标签把这种差异显示出来。
- **按表分组**。每张表在一个词条中共用词形、备注和覆写。按表的适用范围归组，能同时保留适用释义和去重。

**表继承**

- **空格隐式回退到被覆盖的表**：回退目标取决于胜出关系，而胜出关系取决于词条带哪些标签，同一张不规则表对不同词条可能回退到不同的底表；按平局规则，底表实际上只能有一张，直接指明更清楚。
- **继承也带上分配**（子表继承父表的规则，或父表不生效时子表也不生效）：分配和内容两套机制互相干扰，分配试算也解释不清。
- **子表有自己的形状**：要按标签对齐两张表，父表加行加列时容易错位。需要不同形状的子类就建一张独立的表。
- **复制表格并提供"与原表同步"按钮**：仍然存在两份数据，同步时机还要由人来记。
- **删除父表时把子表转成独立表**：删除这一个动作会悄悄改变别的表；先解除继承再删除，每一步的后果都看得见。
- 跨链设置父表采用当前位置对应。行列标签允许为空、重复或使用不同名称，用户在追认前可以调整行列顺序，确认后按当时的位置记录 ID 对应。

**删除时的引用**

- **有词条引用就一律拒绝**（阶段 1 之前的做法）：用户得逐个词条去清引用，而且提示不说是哪些词条。确认后一并清除，代价是一次保存可能改动很多词条的数据，所以必须经过列出词条数和示例的独立弹窗。
- **确认令牌**（对待清除引用的身份和内容做摘要）：能发现数量相同的替换和覆写值变化，但这是本地单用户应用，确认期间另有页面改动这些词条的情况很少。按各删除目标的词条数核对已能发现范围变化，不必在 API 里新增令牌。
- **删除表和删除行列各用一个错误码**：两者是同一种情况（删除会带走词条数据），共用 `morphology_references_in_use` 和同一个确认标记，前端只需要一套弹窗。

**行列与格**

- **继续按位置寻址，插删时由服务端整体挪位**：保存的是最终状态，服务端分不清"删了第 2 行"和"改了第 2 行以后的内容、再删最后一行"，前端得另外发操作记录；每插一行都要改写这张表上所有词条的覆写；子表和 syncretism 引用也得一起挪。
- **多维特征空间，表格只是二维投影**：实际的变化表很少是完整的笛卡尔积（不定式没有人称、复数不分性），会塞满"不存在"或者要处理稀疏组合；入门要先定义维度、再配置排版；维度在整本词典共用还会让模板互相耦合。它的主要收益（按特征写 syncretism、按特征定位一格）要等规则引擎才用得上。二维表加稳定行列 ID 是它的特例，以后可以给行列加特征标注（第 4 节）。
- **普通表不区分"不存在"和"还没填"**：两种意思在详情里看起来一样，"不存在"在三个层级上的含义也不统一。
- **子表能显式标"还没填"、逐词覆写能设"同某格"**：现在没有对应的需求；需要时再加，不影响已有数据。

**Syncretism**

- **继续抄规则**：改一处要改几处，逐词覆写也不会传递。
- **把合并单元格存成数据**会让逐词覆写改变表的形状。显示区域直接从解析结果推导。
- **在规则语法里加"取某格的值"**：整格相同是一种状态，不是一段规则文本；真正需要"取某格作词干"时属于规则引擎。
- **只合并正好成矩形的区域**：L 形、T 形的 syncretism 区域同样是一个形式，退回逐格显示反而看不出它们是一组。
- **按形式相同合并**：会把偶然同形也合在一起。
- **只在空 `<td>` 里放视觉隐藏的文字供读屏**：`rowspan`／`colspan` 覆盖到的坐标没有单元格节点，读屏访问不到。改为并行输出一张语义表，只有存在合并的表需要。

**模板页界面**

- **槽位面板、试算和表格编辑放在同一屏的三栏**：槽位面板只剩约 250px，拖表进别的槽位、对比同槽位的几张表都施展不开，表格网格也被挤窄。分配和内容是两类工作，分成两个视图。
- **槽位管理单独做一个导航目的地**：导航在矮窗口已经放不下（交接文档"导航高度"），减少或增加目的地留给视觉审查；规则、槽位和格属于同一个形态模块、同一个 `PUT /morphology`，拆成两页后来回切换每次都要走未保存检查。同一页两个视图共用草稿，切换不打断编辑。
- **规则放在表格视图里编辑**：规则决定表之间的竞争，和槽位、试算放在一起才看得出效果；表格视图只显示摘要和跳转。
- **用缩进表示覆盖关系**：具体程度是偏序，"不规则古语名词"可以同时覆盖"不规则名词"和"古语名词"，多行规则的表还可能只被覆盖一部分，缩进画不出来；按具体程度重新排列卡片又会和表示平局先后的槽位内顺序混在一起。
- **规则标签改成逐项输入**：能保住导入数据里带分隔符的标签，但会和词条编辑器的标签输入不一致，而带分隔符的标签是标签输入的通用问题。规则这里只保证没改动的输入框原样保留。
- **分配试算直接用来源候选的摘要**：摘要不带每条释义的标签，无法按释义生成上下文。只为用户选中的那一条读取完整详情。
- **整行同存成行的属性**：新加的列会自动跟随，但要新增数据结构，并处理行属性与单格设置的优先级。Syncretism 本来按格表达，逐格存储即可，新列需要时再执行一次。
- **把模板页的撤销发展成全项目的历史记录**：模板页撤销只针对未保存的草稿；撤销已保存的修改、查看版本历史需要服务端记录每次写入，应建立在同步的操作日志上，不从草稿撤销扩展。
- **撤销删除用快照**：把整份草稿换回删除前的拷贝，会连删除之后在别处的修改一起丢掉。行列有稳定 ID，逆操作只需放回被删的行列和格。
- **撤销绑定 `Ctrl+Z`**：输入框里的 `Ctrl+Z` 是浏览器的文字撤销，两套撤销叠在同一个按键上，用户分不清撤销的是哪一个。
- **删除有内容的行列前弹确认**：草稿里的删除还没落盘，会丢词条数据的情况保存时已有确认弹窗（2.12）；每次删行都确认会打断编辑，撤销提示的代价更小。
- **悬停在行线上出现"+"插入**：要瞄准很细的位置，触屏上不可用；菜单插入已能覆盖。
- **删除数据和恢复默认都叫“清除”**：用户分不清哪个会丢数据。删除词条数据的操作写“删除”并用危险样式；只恢复到计算或继承结果的写“清除内容”“恢复继承”“恢复模板结果”。
- **休眠叠加层只在分析页统计**：用户在词条里看不到也删不掉，它们会一直留在数据里。
- **格的菜单只靠右键或长按**：右键对键盘和触屏不可见，长按与输入框的文字选择冲突。

**保存前影响**

- **请求体用完整草稿模块、做与 `PUT` 相同的校验**：表格视图里一个没改完的格就会让预览返回 400，而格与分配无关；每次防抖请求还要带上全部格。只发分配需要的槽位、表 ID 和规则。
- **只在点击“计算影响”时请求**：按标签组合聚合并缓存后，压力词典上第一次预览 1 万条约 0.1 秒、10 万条约 1–1.7 秒，之后每次约 15–25ms，自动计算没有必要再加一步操作。
- **逐词条解析、不聚合**：10 万条词典每次请求要读全部标签（约 1.5 秒）再逐条解析（约 0.4 秒），期间阻塞服务端其他请求。词条的上下文标签组合远少于词条数（压力词典 1 万条约 2,600 种，10 万条约 7,100 种）。
- **示例词条跳到词条页**：要经过未保存检查，打断规则编辑，而且词条页看不到草稿下的分配。载入分配试算能直接说明它为什么变化。
- **按释义列出变化**：预览比较合并后的生效表，与覆写、搜索投影的口径一致；某条释义改用另一张表、合并结果不变时，保存后详情的分组会变，但词条的变化表集合不变，不计入。
- **统计会变为未生效或重新生效的覆写**：保存后哪些叠加层休眠或恢复也有用，但要按组读取叠加层，口径也比“变化表改变”复杂。先只做生效表的增减。

**已知代价**

- **槽位容易被误认为旧的组**：只含一张表的槽位不显示为容器。标题旁的说明弹窗解释槽位内的竞争、并列生效和槽位间的叠加。转换后不建多表槽位，用户第一次接触多表槽位是自己主动拖进去的。
- **失去组标题**：依赖组名作为显示标题的词典，转换后标题落在表上。
- **一张子表的完整内容要沿链看才知道**：编辑时没有记录的格显示解析出的内容。
- **改动面大**：模板、词条、分析、搜索投影、写入计划，以及模板页、词条编辑器、详情三处界面都要改，模板页整体重做。靠转换契约和"转换前后每个词条的解析结果逐一相同"的测试兜底，界面分阶段落地。
- **分配预览的成本**：缓存建立前的第一次预览要读取所有自动模式词条的标签，10 万条词典约 1–1.7 秒，期间阻塞服务端；之后只按标签组合解析。模板保存和词条写入都会清除缓存，所以保存后第一次改规则又会慢一次。

## 4. 与其他计划的关系

- **[Definition Tag Specification](DEFINITION_TAG_SPEC.md)** 提供词条标签和释义标签，自动形态按 2.4 生成上下文、按 2.5 解析。
- **[Entry Incremental Save Plan](ENTRY_INCREMENTAL_SAVE_PLAN.md)** 的形态生成键使用合并后的生效表 ID 列表、lemma、模式与覆写。形态子记录比较使用表 ID。
- **第 3 阶段规则引擎**（交接文档路线图）：本计划只管"哪些表生效"和格的状态，不碰单元格规则语言。分配预览端点与路线图中的"应用前展示对整本词典的影响对比"方向一致，规则引擎可以扩展它。规则引擎计划的输入约束：
  - 保留按上下文分配、槽位内 elsewhere、槽位间叠加这一层；
  - 以后给规则行加上非标签条件（如词形）时，要同时定义这些条件的具体程度如何比较，并让 `explainAutomaticTables()` 能说明原因；
  - 跨变化类的不规则（2.8 末尾）、跨表引用和"取某格作词干"由规则引擎处理；
  - 需要按语法特征定位格时，给行和列加可选的特征标注（行"主格"标 {格: 主格}，列"复数"标 {数: 复数}），一格的特征是所在行与所在列特征之并；不把存储改成多维。
- **多级表头**（交接文档路线图）：作为行列上的显示分组，不改变格的寻址。本计划实施时守住三点，以便以后加入：格只按行列 ID 寻址；表头菜单按可继续加菜单项的方式实现；格名统一由 `morphologyCellLabel()` 生成。
- **第 3 阶段的"规则修改即时预览"**：可以在 2.13 的词形试算上扩展，不另起一套。
- **[Touch, Focus and Accessibility Plan](TOUCH_FOCUS_A11Y_PLAN.md)**：每个拖拽操作都有菜单入口。同一槽位内的卡片、槽位顺序和行列顺序另有 `Alt+方向键` 快捷操作。快捷键只在相应的控件聚焦时处理，跨槽位移动走菜单。格与表头的菜单在触屏上先点选再点 `⋯`。

## 6. 验收

- `node scripts/check-all.js`。
- **解析契约**：
  - 行内"且"、行间"或"、排除；
  - 单表槽位满足即生效、不同槽位叠加；
  - 槽位内更具体者胜出，带排除的行更具体；
  - 条件相同或互不包含的成立行，只要均未被其他成立行覆盖就同时生效；
  - 按释义生成上下文：没有标签的释义取词条标签，没有释义时只有一个上下文；各上下文结果合并去重；
  - 显示顺序只由槽位顺序和槽位内顺序决定；
  - 空规则不匹配；
  - 各条校验错误；
  - `explainAutomaticTables()` 的原因与 `resolveAutomaticTables()` 的结果一致。
- **格与继承契约**：
  - 2.7 的解析顺序：覆写的形式与不存在、沿链取第一条记录、到链顶还没填；
  - 多层继承；链顶表增删和调整行列时子表随之变化；
  - 同某格在覆写和继承之后解析：覆写来源格时引用格跟着变，覆写引用格时只对这个词断开；链式引用；目标不存在或还没填时的结果；
  - 叠好继承后才出现的引用循环被拒绝；
  - 只有"形式"生成搜索值；父表的格变化时子表的搜索投影随之重建；
  - 给链顶或现有子表新建父表后，新父表的自有模板格为空，原表及后代保留原有模板格、分配、坐标、解析结果和逐词覆写。新建父表与解除继承同次保存时，已有覆写跟随各自的行列映射。
  - 跨链追认和改换父表均按草稿顺序迁移模板格、引用和逐词覆写。改挂子树以外的覆写保持原坐标。后续重排按 ID 携带内容，往返迁移可以只改变已有覆写。映射重复提交会被表版本拦下。
  - 解除继承后，这张表及其后代的格、覆写和引用都换到新的行列 ID，解析结果不变；
  - 每条边界校验错误（继承循环、子表带行列、坐标越界、重复的格、字段与 `kind` 不符、引用自身）。
- **行列操作契约**：插入和调整顺序保持原有格值。删除行列会清除对应记录和直接指向它的引用。受影响的链顶格回到未填写，子表格恢复继承。只剩一行或一列时禁用对应的删除，导入时拒绝重复的行列 ID。
- **删除确认契约**：删除表（手动选择、叠加层、休眠叠加层、覆写）和删除行列（含后代子表上的覆写）时，未确认返回 409 且不写入任何数据。`details` 的计数与逐条比较一致，合法确认在同一事务里清除引用并删除。仍被继承的父表即使确认也返回 `morphology_table_has_children`。确认摘要与服务端重算结果不一致时（确认期间增删了引用），返回新的 409 摘要，整个旧确认不执行；只改了无关词条时确认照常执行。
- **转换契约**：用 `scripts/generate-morphology-test-dictionary.js`、`scripts/generate-stress-dictionary.js` 生成的词典（释义都没有标签）按旧模型解析一遍，转换后再解析一遍，每个词条生效的表格集合、显示顺序与单元格值逐一相同；覆写、手动选择、休眠叠加层、词条级组标题都保留。另用带释义标签的词条验证：每条释义得到的表，等于旧规则对"词条标签 ∪ 这条释义标签"的结果。
- **写入计划契约**：只改顺序或行列标签不触发分配变化和单元格重新生成；改规则或在槽位之间移动表，只重建受影响词条的投影；删除被引用的表、仍被继承的父表各返回对应的 409。
- **分配预览契约**：
  - 草稿与当前模板相同、或只改了顺序时 `changedEntryCount` 为 0；
  - 增减计数和示例与逐个词条比较的结果一致（含带释义标签、多上下文的词条）；有损失的已删表出现在 `lostByTable`，有增加的未保存新表出现在 `gainedByTable`，表级列表不含零计数；手动模式词条不计入；示例按词条顺序、至多 20 条；
  - 改了词条标签或释义标签后再预览，结果反映新标签（缓存已失效）；
  - 校验错误码与 `PUT /morphology` 相同（`slots` 不是数组、空槽位、规则行错误、重复 ID）；缺少槽位或表 ID 返回 400 `invalid_morphology_payload`；格的错误不影响预览；
  - 不写入任何数据，不推进 generation；
  - `morphologyAssignmentKey()`：规则顺序、行内标签顺序、首尾空白、重复的规则行、槽位与表的顺序不改变键；改标签大小写、在槽位之间移动表、增删表改变键。写入计划的分配变化判断与原实现结果相同。编辑过、尚未拆分的规则输入框（`allText`／`noneText`）经 `morphologyForSave()` 后改变键。
- **显示算法**覆盖合并区域和内接矩形的选择（竖列、横行、L 形、T 形、方块加一格、不连通区域、连续的不存在、混合覆写状态），以及按适用释义归组（全部共用、部分共用、某些上下文无匹配表）。
- **性能**：在压力词典上对比改动前后的模板保存、形态投影全量重建和形态分析耗时，并测量分配预览的耗时（1 万条和 10 万条，缓存建立前后各一次）。
- **阶段 3 界面**：
  - 只改顺序、标题、备注或格时不发请求；改规则、移动表、删表后停止编辑才发一次；连续输入时只有最后一次的结果显示；撤销回已保存的分配后影响条消失；改规则后 400ms 内放弃更改或离开，不再发出请求；
  - 结果显示后删掉草稿里有增加的新表，同时保留另一处分配改动：更新期间只剩总数和“正在更新”，不显示找不到标题的表或旧示例；
  - 规则有错误时影响条显示提示、不发请求，修正后恢复；
  - 点示例词条载入分配试算，试算与卡片的判定显示该词条在草稿下的结果；窄屏打开试算抽屉；

  - 中英文、长表名，320px、工作区切换阈值附近和 1280×610 下影响条与卡片的增减不挤压规则芯片。
- **阶段 2 界面**：按 `AGENTS.md` 的 UI 验收选维度，另外检查：
  - 结构视图与表格视图反复切换，草稿、选中的表和试算输入都保留，不触发未保存检查；
  - 滚动长槽位列表或长表时，页头吸顶并遮住滚过的内容，窄屏时标题滚走、只留控件。展开长试算结果或显示撤销提示时，右栏与表格列表避开页头。窄屏打开和关闭抽屉保留主区滚动位置，退出后焦点回到触发控件。
  - 离开模板页、切换词典、点词条数、点删除确认里的示例词条时，保存、放弃、取消各自的结果正确；取消确认或保存失败后可以继续编辑和撤销；
  - 撤销：删除行列后在别处改动再撤销，别处的改动保留；已保存的空白行删除后可撤销；被另写了内容的引用格不被覆盖；撤销会成环时提示冲突；撤销槽位里唯一的表，槽位和表都回到原位；“整行同…”覆盖后撤销恢复原来的格；

  - 合并区域在每套皮肤、明暗模式下看得出外轮廓（L 形、T 形、不连通区域）；只画行线的皮肤里横向合并可能看不出，必要时给区域加统一的淡底色；
  - 浏览器无障碍树里每个逻辑格、行列表头和“—”都有可访问名称，读屏按逻辑坐标逐格读出。

## 7. 决定记录

- 现行的"任一标签相同即匹配"必须改，不用子集或超集判断；改用可以自定义"且 / 或"的结构化规则，不做文本表达式（2026-10-23）。
- 去掉形态组，表格直接匹配词条并自动组合；需要竞争的表放进槽位，槽位内按 elsewhere 由更具体者胜出（2026-10-24）。
- 编辑界面以槽位面板、试算面板和影响范围为中心（2026-10-24）。
- 每张表属于一个槽位，新建表时自动建一个独立槽位（2026-10-24）。
- 不规则子类用显式表继承，子表的形状沿用父表（2026-11-20）。
- 匹配上下文按释义生成（2026-11-21）。词条详情按表的适用释义分组，共用表显示一次，组内按槽位及槽位内的表顺序排列（2026-11-22）。
- "不存在"在普通表、子表和逐词覆写三个层级都支持；普通表区分"不存在"和"还没填"，旧数据的空格按还没填转换（2026-11-21）。
- Syncretism 用"同某格"引用表示，详情把任意连通的区域合并显示，文字放在面积最大的内接矩形里（2026-11-21）。
- 行列使用稳定 ID，在表头菜单里插入、移动和删除，取代数字框加"应用尺寸"；不做多维特征空间，多级表头以后再加（2026-11-21）。
- 模板页的词形试算并进阶段 2（2026-11-21）。
