# Style Skin Plan

本文记录 Conlexicon 样式解耦后的文件边界、皮肤 token 契约和验收基线。S0 建立可替换皮肤基础；后续职责拆分又把皮肤拥有的几何值、经典皮肤和组件消费规则分离，过程均不得改变计算样式。

## 1. 文件边界

- `theme-classic.css`：经典皮肤完整的明暗语义色、材质、圆角和交互参数，以及经典候选缩略图；无皮肤、显式 `classic` 与未知皮肤值均由该文件提供默认回退。
- `theme-layered-glass.css` / `theme-liquid-glass.css`：各自完整定义同一套标准 token、必要的皮肤专属选择器和对应候选缩略图；不得隐式继承经典值。
- `styles.css`：布局、组件、状态、响应式规则和对皮肤 token 接口的消费；皮肤选择器只在此定义菜单、选项及缩略图公共框架，不得声明目标皮肤外观、皮肤 token 或主题材质字面量。

## 2. Token 层级

语义颜色以 `--ui-*` 命名，表达画布、文字、边框、强调、警告、危险和焦点等含义。材质角色以 `--material-*` 命名，分别表达 panel、control、inset、floating、mobile-bar、navigation、tooltip 和 overlay 的背景、边框、阴影与滤镜。标准 token 由三套皮肤分别完整拥有；token 名称是组件接口，值属于皮肤。

圆角接口保留 control、mobile-control、panel、floating 和 pill 五种角色，由每套皮肤在自身基础作用域中定义。当前三套皮肤继续使用等值的 `8px` 标准控件/面板/浮层、`10px` 移动控件和 `999px` 圆头，但契约不要求跨皮肤等值；更小的嵌套曲率、局部四角、严格圆形、液态玻璃导航专属层级及独立 Lab 几何继续留在自身组件边界，不为了消灭字面量扩张接口。

布局间距、虚拟列表尺寸、网格轨道、响应式断点和 z-index 不属于皮肤，不迁入共享 token；唯一例外是下面的词条详情分区分隔接口。`uiTheme` 仍只表达 light/dark，`uiSkin` 的公开取值和持久化协议不因文件拆分改变。

### 词条详情分区分隔接口（2026-10-01）

词条详情只保留一层外壳。释义、词源、衍生、形态和备注等分区共用同一套 DOM 和 `.display-section` 规则；释义条目、例句、释义备注和形态组不再各自加框，例句保留唯一的浅色底块，形态组之间只用细线分隔。各皮肤用不同的分隔方式保持区分度：

| 皮肤 | 分隔方式 | 悬浮 / 局部编辑反馈 |
| --- | --- | --- |
| 经典 | 带边框的分区卡片 | 边框转为强调色；编辑时边框加深并加焦点环 |
| 层叠玻璃 | 无边框半透明玻璃带，上沿 1px 内侧高光，带间留缝透出外壳 | 玻璃带变亮、高光加强；编辑时加强调色描边 |
| 液态玻璃 | 一整片玻璃，分区之间只有细线；分区向两侧外扩，使浅色底不贴字 | 浅色底；编辑时改为强调色浅底并加描边 |

分隔方式本身就是皮肤外观，因此分区的间距、内边距和外扩量作为例外进入皮肤 token：`--material-entry-detail-section-{gap,padding,bleed,surface,outline,edge,divider}`，悬浮和局部编辑状态各有 `-{hover,editing}-{surface,outline,edge}`，标题区下沿使用 `--material-entry-detail-header-divider`。共享规则只消费这些 token，不得为某个皮肤另写一套分区结构。悬浮与编辑反馈只作用于带 `data-edit-section` 的分区和词条标题区；标题区平时只有内容宽度的下沿分隔线，内容保持在外壳内容边缘；悬浮框向外透明外扩 12px（640px 及以下 10px，属布局值，不是皮肤 token）并以负外边距抵消，局部编辑时框与分区对齐并使用分区内边距；悬浮和编辑消费同一组 hover／editing token（2026-10-10）；不可局部编辑的衍生分区没有分区级反馈，内部链接、标签和按钮保持各自的控件状态。局部编辑时分区的编辑态是唯一容器：`.inline-partial-edit-form` 不绘制边框、底色或阴影，分区标题保持可见并附“编辑中”状态，只隐藏分区内容（2026-10-09）。完整编辑表单的五个分区同样使用 `.display-section` 并消费这组 token（不带 `data-edit-section`，因此没有分区悬浮反馈），标题区下沿使用 `--material-entry-detail-header-divider`，外壳间距使用分区间距 token。分区内重复的编辑条目（释义、形态组）不加框，条目间距与分隔线由 `--material-entry-editor-item-{gap,divider}` 提供，三套皮肤在明暗作用域分别定义（2026-10-10）。

`--material-entry-detail-section-background/-border` 仍是分区的稳定材质：经典和层叠玻璃的分区表面引用它们；液态玻璃的分区表面为透明，但输入字段继续借用这两个 token，不能为去掉分区底色而改写它们。不支持 blur、减少透明度路径下，层叠玻璃的玻璃带退为带细边框的实色分区；强制高对比路径使用系统色描边和 `Highlight` 状态。

### 控件颜色语义接口（2026-09-20）

共享组件通过 `data-control-tone` 声明语义：
neutral 使用唯一中性配方，必须省略 `data-control-emphasis`；
accent 与 danger 必须明确选择 outline、tinted 或 solid。契约按上述七种有效声明校验，
不将所有字段的笛卡尔积视为有效接口。新增配方需有明确用途与状态验证，不以是否已经迁移消费者作为唯一依据。
七种配方共用状态出口；未声明的组件继续走原有样式，包括菜单及文字操作的无底外观。
这是颜色、强调与交互阴影接口，不是 Q3 注册接口，不改变尺寸、布局、按压变换或业务行为。

| emphasis | 默认底色 / 边框 | 用途 |

| outline | 同皮肤 panel 中性底 / tone 色 | 描边操作 |
| tinted | tone 弱底 / 初始透明边框；文字用 tone 的 hover 色（accent 为 `--ui-accent-hover`，2026-10-11） | 弱强调／危险操作，已建来源链接与编辑态来源卡片 |

### 焦点（2026-10-11）

焦点只表示“键盘位置在这里”，不带语义色，也不随光学注册或质量等级变化。方案在控件对照页的候选中选定。

| token | 含义 | 值 |
| --- | --- | --- |
| `--ui-focus` | 键盘焦点环颜色，只用于 `outline`／`outline-color`（样式契约核对） | 各皮肤 `var(--ui-text)`，即中性墨色 |
| `--ui-highlight` | 原先借用焦点金色的暖色点缀：搜索命中高亮、质量“中等”标记底、分析图衍生词色与条形渐变 | 原金色值，外观不变 |
| `--ui-field-focus` | 文本框激活边框 | `var(--ui-accent-hover)`（明暗各自求值） |
| `--ui-field-focus-ring` | 文本框激活阴影 | 经典与层叠玻璃为 3px 淡外光晕；液态玻璃为“边缘提亮”：外沿亮线、上沿内高光、强调色内细边与内辉光，以及一层铺满内部的白色内阴影使玻璃变亮，不加外轮廓 |

规则：

1. **全局兜底**：`:where(:focus-visible) { outline: 2px solid var(--ui-focus); outline-offset: 2px; }`。零特异度是约定：任何组件焦点规则（含文本框的 `outline: none`）都优先于它，因此选择器不得加任何前缀。组件中与兜底相同的焦点规则已删除。
2. **导航上下文**：`.dictionary-panel` 内焦点环取 `--material-navigation-text`（经典与层叠玻璃为深色导航上的浅色环），目的地行内偏移 2px，避免被可滚动的导航列裁掉；皮肤不再各写导航焦点规则（样式契约核对）。
3. **滚动列表**：词条列表与语料列表内的焦点环内偏移，因为卡片贴着列表边缘，外偏移会被裁掉。
4. **文本框**：`:focus`（鼠标点进去也显示）用 `--ui-field-focus` 边框与 `--ui-field-focus-ring`，没有外轮廓。液态玻璃的这个 ring 含白色填充和内发光，只适合普通字段；语言文档编辑区占满整个面板，因此去掉 ring，改由外层面板显示 `--ui-field-focus` 边框。
5. **保留的例外**：排序与皮肤菜单项内偏移、来源移除按钮偏移 1px（这三条只声明 `outline-offset`，环本身来自兜底）；复选框自己画环，因为输入框共用的 `outline: none` 特异度高于兜底，并在指针操作时不显示；选中控件与文件导入在外层容器上显示内部输入的焦点（兜底无法表达）；右键菜单项与词汇网络面板用底色或描边、不画外轮廓；强制高对比下导航焦点用 `Highlight`。

焦点不走光学引擎：焦点须在 Q0–Q3 一致可见，贴图异步生成也不满足焦点的即时性。光学高光增强可留待 LQ-7 评估，只能叠加在焦点环之上。

### 工作页宽度（2026-10-30）

工作区本身不限宽。内容窄、控件多的工作页在 `.view` 上设上限并居中，这样标题对齐面板左缘，操作按钮对齐面板右缘，不会留在窗口两端；内容用得上宽度的页面（词条、语料库、形态表格等）保持铺满。标题位置因此随页面宽度变化，这是标题与内容保持一体的代价。

| 页面 | 上限 | 依据 |
| --- | --- | --- |
| 其他设置 | 1500px，1180px 及以下 820px | 两栏设置表单，窄屏为单栏 |
| 词典管理、标签管理 | 1200px | 两栏：列表或主栏，加 280–420px 的侧栏 |
| 形态函数、质量检查 | 900px | 单列表单或列表 |

宽度是布局值，不是皮肤 token。其余配置页尚未处理，见交接文档第 4 节。

### 拖动排序（2026-10-31）

所有拖动排序用同一种显示：被拖的项在原位变为 50% 不透明，2px 强调色插入线标出落点，放下时才移动。拖动过程中列表不变，所以按 `Esc`、拖出列表或放回原位都不改变顺序，也不算改动。不用实时移动和虚线占位。

纵向卡片列表用 `setupListDragSort()`：工具导航、词条分区、IPA 规则、形态表格和表格组都走这里，新的纵向排序也应接入它。线画在目标卡片之前的间隙中点，末尾画在列表之后。列表要声明 `position: relative`，卡片只在自己的父列表内移动，所以表格不能跨组。标签要跨区和换行，来源卡片是横向换行，这两处保留自己的落点判定，外观遵守同一规则。

跟手的拖动残影由浏览器生成，不单独设置；从把手起拖时残影只有把手。

每个拖动排序都要有键盘替代。`setupListDragSort()` 内置 `Alt`+`↑`／`↓`：聚焦把手（工具导航和词条分区的整张卡片就是把手）后按一次移动一位，到列表两端不再移动。移动的是相邻卡片，当前卡片不离开文档，焦点因此保留；移动后把手滚入视口并留出焦点环的空间。把手要声明 `aria-keyshortcuts`，并在 tooltip 或说明文字里写明快捷键。标签和来源卡片的按键见各自规范，压缩视图和来源卡片还支持 `←`／`→`。

### 开关（2026-10-25）

开关表示立即生效的开／关状态。在需要点“保存”才生效的表单里（如设置页），以及从一组项目里多选（如搜索字段表格）时，继续使用复选框。文字格式按钮（B／I／SC）、工具栏模式按钮（词根模式）和主题按钮仍然是切换按钮（2026-10-25 评估）。目前尚无产品界面使用开关，第一个使用者是快速录入的释义标签开关（[Definition Tag Plan](DEFINITION_TAG_PLAN.md) U4）。

- **结构**：`<input type="checkbox" role="switch" class="switch">`，使用原生复选框，因此可以直接参与表单、触发 `change`、用 Space 切换，禁用状态由浏览器处理。轨道就是输入框本身，滑块是它的 `::before`，并用 `currentColor` 绘制：输入框的文字色就是滑块色，控件对照页因此可以把“文字对比度”直接当作滑块与轨道的对比度来读。
- **标签**：开关总带可见文字，二选一：
  - 行内用 `<label class="switch-label">`，开关在前、文字在后；
  - 设置行用既有的 `.toggle-row`，文字在左、开关在右。

  整个标签都是点击目标，标签的悬浮与按下转发给开关；触屏（`pointer: coarse`）下标签行高至少 44px，轨道本身不放大。
- **状态**：只来自 `:checked`、`:disabled` 和 `aria-disabled="true"`，不使用类名。优先级为禁用、按下、悬浮、默认，开与关各有一套。按下时滑块向另一侧拉长 4px。禁用的开关仍要能看出是开着的。`aria-disabled` 只改变外观，使用方须自行取消 `click`（键盘 Space 也会派发 `click`）。需要 tooltip 说明禁用原因时用 `aria-disabled`，因为 `disabled` 的原生控件收不到鼠标事件。
- **配方**：配方输入是开关自己的局部变量 `--switch-*`（默认、hover、pressed、checked、checked-hover、checked-pressed、disabled、checked-disabled），共享规则把它们解析为 `--switch-current-{background,border,thumb}`。另有三项材质输入，在所有状态下不变：轨道内阴影 `--switch-track-shadow`、滑块光泽 `--switch-thumb-sheen`（叠在滑块色上的背景图层）和滑块阴影 `--switch-thumb-shadow`，默认都为 `none`。默认配方写在 `styles.css`，全部取自皮肤 token：
  - 关：透明轨道，`--ui-text-muted` 边框与滑块；
  - 关 · 悬浮：轨道为 `--material-inset-background`，边框与滑块为 `--ui-text`；
  - 开：`--ui-accent` 轨道，`--ui-canvas-bg` 滑块；悬浮时轨道为 `--ui-accent-hover`；
  - 开 · 禁用：沿用选中配方的禁用组合（`--ui-accent-soft` 底、`--ui-accent` 边框、`--ui-text-muted` 滑块）。

  开启时滑块取画布色而不是白色，是因为两套主题的 `--ui-accent-hover` 都朝远离画布色的方向变化，悬浮和按下时对比度只升不降；暗色下的白色滑块在强调色上约 2.8:1。经典与层叠玻璃使用默认配方。皮肤要定制外观时，在自身文件中以 `body[data-ui-skin=…] input[type="checkbox"].switch` 覆盖配方输入，不另写状态规则和绘制属性，并同时处理该皮肤的强制高对比路径。开关不新增标准 token。
- **液态玻璃**（2026-10-25）：开关做成玻璃质感，只覆盖配方输入，写在 `@media not (forced-colors: active)` 中，强制高对比时回到共享的系统色配方。
  - 关：半透明白色玻璃槽（浅色 34%，暗色 6%），上方有内阴影、下沿有亮线，看起来是嵌入的。悬浮时玻璃槽变亮；按下时轨道混入 `--ui-text`，像被按进去。
  - 开：轨道用与 solid 按钮同一种思路的强调色玻璃墨（浅色为 `--ui-accent` 混 20% 黑，覆盖率 80%／92%，按下时再混 10% 黑），滑块为白色（`--ui-text-on-solid`）。暗色的墨比 solid 按钮浅（同样混 20% 黑，覆盖率 76%／90%，按下时混 4% 白）：轨道边界要在暗色玻璃上保持 3:1，白色滑块也要在轨道上保持 3:1。
  - 滑块：上半部分有白色光泽渐变，下方有轻投影，看起来浮在轨道上。
  - 不加 backdrop 模糊：20px 高的轨道上看不出模糊效果，还会在玻璃父表面内多出一个 backdrop 根。
  - 减少透明度时，关闭的轨道改为画布色，开启的轨道改为不透明玻璃墨。
- **材质与光学**：开关属于行内控件，轨道没有外投影（轨道只有内阴影；液态玻璃滑块的轻投影最多超出轨道下沿约 1px），也不注册光学表面（引擎只登记带语义 tone 的 `button`／`label`），因此放在玻璃父表面内无需额外扁平化。
- **辅助模式**：强制高对比下使用 `forced-color-adjust: none` 和系统色（关为 `ButtonText`，开为 `Highlight` 加 `HighlightText`，禁用为 `GrayText`）。减少动态效果时去掉轨道和滑块的过渡。焦点沿用复选框规则：键盘操作时显示 2px `--ui-focus` 外环，指针操作时不显示。
- **尺寸**：轨道 36×20px（含 1px 边框），滑块 14px，四周留 2px。轨道宽度固定，不随父容器收缩：共享的 `input { max-width: 100% }` 对开关不适用，开关自己写死 `min-width` 和 `max-width`。尺寸和间距属于组件布局，不属于皮肤。

控件对照页在页面底、Q1 和 Q3 中各列出开与关两行（默认、悬浮、按下、焦点、禁用、实时），自检检查滑块与轨道对比度 ≥ 3、轨道边界与背后底色对比度 ≥ 3（禁用项除外），以及各状态之间的差异是否可见。“开关的标签”一节列出行内、英文、长文字、`aria-disabled`、`disabled` 和设置行样本，这些样本都可以实际操作。

## 4. 当前状态

当前代码边界已经完成：`styles.css` 只消费皮肤角色，不声明 `--ui-*`、`--material-*` 或 `--radius-*`，也不包含主题色字面量、组件级暗色分支和直接材质模糊/投影。经典、层叠玻璃和液态玻璃各自完整拥有同一套颜色、材质与圆角 token；无消费者的通用 warning soft、普通 tooltip muted、旧 dialog overlay 和预留网络标签 filter 已删除。

`scripts/check-style-contract.js` 持续验证：

1. 四张样式表必须按经典、层叠玻璃、液态玻璃、组件的顺序加载。
2. 三套皮肤必须完整定义全部标准 token；五种角色圆角必须各有组件消费者，但允许皮肤使用不同值。
3. 组件样式不得声明皮肤 token，也不得恢复旧别名、主题分支、目标皮肤预览或主题材质字面量。

新增皮肤必须使用独立且有作用域的文件完整定义标准 token；透明度、模糊、圆角、降级策略和性能验收仍由各皮肤规范负责。两套玻璃皮肤的具体边界分别见 `docs/LAYERED_GLASS_SKIN_SPEC.md` 和 `docs/LIQUID_GLASS_SKIN_SPEC.md`。

## 5. 普通控件材质职责收尾与视觉定稿（2026-10-01 计划，第 1 批已完成）

目标：普通控件只有一条外观链路，即“语义 → 皮肤配方 → 当前状态 → 最终绘制”。先理清各层职责，再集中调视觉，不再逐个按钮修补；架构清理、三套皮肤重设计和新光学效果不放在同一批。

| 层 | 负责 | 不负责 |
| --- | --- | --- |
| 组件类（`.primary-button` 等） | 尺寸、间距、图标排列、布局 | 按 primary／secondary 名字决定颜色和阴影 |
