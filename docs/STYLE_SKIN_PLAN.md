# Style Skin Plan

本文记录 Conlexicon 样式解耦阶段 S0 的边界、皮肤 token 契约和验收基线。S0 只建立可替换皮肤基础，不改变当前经典明暗主题的视觉，也不增加皮肤设置或持久化字段。

## 1. 文件边界

- `theme-tokens.css`：语义颜色、材质角色、少量可换肤几何值，以及 S0 迁移期间的旧 token 别名。
- `styles.css`：布局、组件、状态和响应式规则；完成 S0 后不得继续包含主题相关颜色或材质字面量。
- 当前不拆分其余组件 CSS。未来皮肤只能覆盖 token，不应向组件 DOM 添加 `glass` 等皮肤类。

## 2. Token 层级

语义颜色以 `--ui-*` 命名，表达画布、文字、边框、强调、警告、危险和焦点等含义。材质角色以 `--material-*` 命名，分别表达 panel、control、inset、floating、sticky、navigation、tooltip 和 overlay 的背景、边框、阴影与滤镜。圆角只保留 control、panel、floating 和 pill 四种角色。

布局间距、虚拟列表尺寸、网格轨道、响应式断点和 z-index 不属于皮肤，不迁入 `theme-tokens.css`。`uiTheme` 仍只表达 light/dark，不在 S0 中引入 skin 设置。

## 3. S0-1 基线与兼容边界

S0-1 已把原 `:root` 和 `body.dark-theme` 主题值迁入 `theme-tokens.css`，并在 `index.html` 中先于组件样式加载。现有 `--bg`、`--surface`、`--surface-2`、`--ink`、`--muted`、`--line`、`--accent*`、`--amber`、`--danger*`、`--focus` 和 `--shadow` 暂时作为别名保留，供后续按材质角色逐步替换；S0 完成时删除，不作为长期兼容 API。

由于自定义属性在声明所在元素上求值，定义于 `:root` 的派生别名不会因后代覆盖基础 token 而重新求值。暗色作用域因此必须在迁移期间显式重绑定派生材质和旧别名；完成旧别名删除后仍应让同一作用域内需要跟随主题的材质引用就地声明。

改动前后均以浏览器计算样式抽取以下关键角色：

| 角色 | 浅色背景 / 边框 | 暗色背景 / 边框 | 圆角 | 滤镜 |
| --- | --- | --- | --- | --- |
| 画布 | `#f4f6f2` | `#151a1d` | `0` | `none` |
| 导航 | `#22313a` | `#10181c` | `0` | `none` |
| 控件 | `#ffffff` / `#d8e0e8` | `#1f282d` / `#405057` | `8px` | `none` |
| 面板 | `#ffffff` / `#d8e0e8` | `#1f282d` / `#405057` | `8px` | `none` |
| 浮层 | `#ffffff` / `#d8e0e8` | `#1f282d` / `#405057` | `8px` | `none` |

浅色和暗色的 body、navigation、control、panel、floating 与筛选按钮计算样式在 S0-1 前后逐项一致。

## 4. 后续顺序

S0-2 已将组件中的文字、边框、强调/警告/危险状态和焦点环迁入 `--ui-*`；原 `--ink`、`--muted`、`--line`、`--accent*`、`--amber`、`--danger*` 与 `--focus` 引用及临时别名均已删除。警告标签和警告徽章按现有不同视觉语义保留独立 token，没有借迁移强行统一外观。明暗主题关键计算样式继续与 S0 前基线一致。

后续顺序：

1. 按组件角色迁移背景、阴影和滤镜到 `--material-*`。
2. 删除组件级暗色分支和主题相关硬编码值。
3. 删除剩余 `--bg`、`--surface*` 与 `--shadow` 别名，加入只允许 token 文件声明主题字面量的边界检查。
4. 完成中英文、明暗主题、关键宽度、菜单、弹窗和长文本浏览器验收。

液态玻璃或其他皮肤应在 S0 完成后，以独立且有作用域的 token 覆盖文件实现；透明度、模糊、降级策略和性能验收不属于 S0。
