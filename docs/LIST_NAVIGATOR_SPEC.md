# List Navigator Specification / 列表导航条规范

状态：现行规范。词条列表的普通模式与词根模式都由自定义导航条取代原生滚动条。本文记录导航条的交互、定位、加载与测高、分段和接口约定。概览接口的请求与响应以 [API Contract](API_CONTRACT.md) 的“列表概览”和 `/root-group-overview` 为准，本文只说明前端如何使用。

本规范由增强滚动条计划（2026-11-09 起草，2026-11-16 加入词根模式，2026-11-18 完成后删除）整理而来；计划中的决定编号（D1–D29）、实施过程和交互原型都在 Git 历史和 `CHANGELOG.md` 里。未实施的触屏快速拖动手柄见交接文档。

## 1. 范围与边界

- 接管的列表：词条列表的普通模式（含搜索和结构筛选）和词根模式。语料列表和质量页列表仍用原生滚动条，行高固定的语料列表保留浏览器自带的滚动锚定。
- 滚动仍由原生滚动容器完成：滚轮、触控板、触摸惯性、Windows 中键自动滚动和键盘滚动都由浏览器处理。导航条只换掉滚动条的显示和拖动方式，不自己实现滚动。
- 不做：
  - 位置标记，例如当前词条、质量问题、搜索命中或书签。当前词条用详情里的定位按钮。
  - 与当前排序无关的索引，例如按词形排序时显示日期索引。
  - 键盘跳到指定分段的快捷键。
  - 功能结果和质量结果筛选下的分段：这两种筛选只显示抓手，没有刻度和气泡文字。

## 2. 外观与交互

- **轨道与抓手**：竖向细线轨道加胶囊抓手。抓手长度 = 可见量 ÷ 总量，最小 32px。平时 3px 宽，悬停或拖动时变宽到 14px；可点击宽度为 20px（`--list-navigator-width`）。
- **拖动**：抓手紧跟指针，列表随后跟上。松手后抓手按列表的实际位置重新同步，列表不动。
- **点轨道空白处**：按比例跳转，可以接着拖动。指针停在导航条上时，滚轮照常滚动列表。
- **气泡**：拖动或悬停时在左侧浮出，叠在列表上方，不挤占布局。显示目标位置的分段名和序号：普通模式如“k”和“3,930 / 10,000”，词根模式如“k”和“37 / 1,204 组”。悬停而未拖动时，气泡预览点下去会跳到哪一段哪一处；触屏不触发预览。
- **刻度栏**：指针移到导航条上或开始拖动时浮出，盖在卡片右侧，不占列表宽度。刻度字号 13px，相邻刻度至少相隔 20px（实际至少一行字高）。栏宽按当前最宽的标签加 8px 计算。
  - 放不下时合并相邻小段，显示为“a–c”。
  - 整栏按刻度切成上下相接的块，每块占满栏宽。一块的范围就是这一段在轨道上实际占的范围：从本段起点到下一个刻度的起点，第一块和最后一块延伸到栏的两端；标签放在块的中间。除最后一块外每块至少 20px；最后一块延伸到栏底，最矮只有半个抓手，矮于 20px 时并入上一块。
  - 悬停一块时整块高亮，并提示段名和数量；点块内任意位置精确跳到该段的第一条（词根模式为该段第一个组的词根卡）。
- **刻度门槛**：数量少于 100 时只有抓手和气泡，没有刻度，刻度栏也隐藏。普通模式按结果条数算，词根模式按组数算。
- **时间分段**：按结果的时间跨度自动选粒度：60 天内按日，4 年内按月，更长按年。按用户本地时区划分。没有日期或日期无法识别的词条归入单独的“无日期”段。
- **正在更新**：列表处于“正在更新”（旧内容变淡）时，导航条随列表一起变淡。
- **皮肤与无障碍**：颜色 token 统一定义在 `styles.css`，由各皮肤的 `--ui-text` 与 `--ui-accent` 派生，需要时由皮肤覆盖。液态玻璃下用 CSS 材质，不注册光学表面。导航条设为 `aria-hidden`，不占 Tab 停靠点，不提供键盘操作，与原生滚动条相同；键盘和读屏用户通过列表内容和容器滚动导航（读屏行为是推断，未实测）。

## 3. 定位

### 3.1 布局与换算

导航条按布局单位定位，不按像素。布局是 `{ rows, offsets, total }`：

- `rows[r] = { start, count }`：每个虚拟行一项，`count` 是该行的权重，`start` 是之前各行权重之和。
- `offsets`：虚拟列表各行的像素位置（实测与估算高度的前缀和）。
- `total`：全部权重之和。

“`scrollTop` → 布局位置”在行内按像素比例插值；“布局位置 → `scrollTop`”是它的反函数。**不变量：在同一份布局上两者互为反函数**，权重可以是非整数。所以只要拖动期间布局不变，松手时从列表读出的位置就是指针给出的位置，抓手不会回跳。这条不变量由 `scripts/check-list-navigator.js` 测试。

拖动期间抓手只跟指针走，不读 `scrollTop`；松手后只把抓手同步到列表的实际位置，不移动列表。点轨道空白处只按比例跳转，不做精确对准；点刻度是离散跳转，先滚到估算位置，等所在窗加载完成，再用 `scrollVirtualListItemIntoViewStable` 对准该段第一行。

### 3.2 普通模式：按结果下标

每条词条权重为 1，布局位置就是结果下标；未加载的窗口占位行的 `count` 是该窗的条数。抓手位置 = 可见区第一条的下标 ÷ 总条数。

所有未测高的卡片用同一个估算高度（145px）。窗口加载时整页按原占位高度缩放，页内条目的分布与占位块内的均匀换算一致，所以拖到未加载的窗口时，加载前后同一滚动位置对应同一条，落点就是目标那一条。不要按卡片类别分别估算：页内分布与占位块不一致时，落点会差几条。

代价：用滚轮滚动时抓手按经过的条数移动，词条高矮不一时速度略有起伏，一屏内通常可以平均掉。

### 3.3 词根模式：按估算高度

每一行的权重是它的估算高度，与实测高度无关：

| 行 | 权重 |
| --- | --- |
| 未展开的词根卡 | 145 |
| 展开的词根卡 | 137 |
| 衍生行 | 44，组内最后一行 57 |
| 衍生词尚未读出的占位行 | 13 + 44n |

展开 n 个衍生词的组合计 150 + 44n。普通模式是它的特例（每行权重相同）。展开或收起一个组、点“全部展开／全部收起”都会改变总量，抓手的位置和长度随之变化，与内容变长时原生滚动条的表现一致；卡片量出真实高度不改变权重，抓手不漂。

未加载或已淘汰的窗口，权重由该窗的 `pageInfo.windowMetrics` 按当前展开状态算出，不取实测像素：

```text
权重 = groupCount × 145 + 展开组数 × 5 + 展开组的衍生词数 × 44
```

| 状态 | 展开组数 | 展开组的衍生词数 |
| --- | --- | --- |
| 全部展开（搜索与否） | `derivedGroupCount` | `derivedCount` |
| 手动模式、搜索中 | `matchedGroupCount` | `matchedGroupDerivedCount` |
| 手动模式、未搜索 | 0 | 0 |

再按展开记录加上手动展开的组、减去全部展开模式下手动收起的组。未加载窗的像素估算用同一公式。

**展开记录**：`词根 ID → { 组下标, 衍生词数, 命中衍生词数 }`，在组处于已加载窗时写入。组下标只对写入时的查询有效：搜索或排序变化后保留展开意图，组下标待该组在新查询中加载时重记；在此之前它所在的未加载窗权重少算或多算这一组，加载后总量变化一次。这是已知的不精确，不为它增加后端查询。

**气泡的组序号**：位置落在已加载的行时取该行的组下标，是精确的；落在未加载窗的占位内时按比例估算。手动模式下占位内各组权重相同，估算准确；全部展开或搜索时各组衍生词数不同，序号是近似值，指针停住、窗口加载后变为精确。

### 3.4 窗口加载与缩放

- 窗口加载时，先读出占位的当前高度，加载后让整窗的像素总高等于它，滚动位置不变时同一像素处还是原来那一行。
- 从未加载过的窗口，各行都是估算高度，整窗按“占位高度 ÷ 自然估算高度”缩放。
- 被淘汰后重新加载的窗口，量过的行直接用缓存的真实高度，只缩放没有缓存高度的行：缩放系数 = (占位高度 − 缓存高度之和) ÷ 无缓存行的自然估算之和。这样重载后整窗与占位等高。实测 1 万条压力词典中，拖回这样的窗口落点与目标相差不到 0.3 条；同一页内卡片高矮成片分布时，理论上仍可能差几条。
- 衍生词按组整组加载。占位行与加载后的各行合计等高、每行等高，占位行消失后 `scrollTop` 不变，同一像素处就是目标行。
- 不做“窗口加载时按结果下标恢复位置”：上面几条已经让落点准确，剩下的误差只来自重载窗口里的缓存高度。改它要动虚拟列表的公共路径，并在窗口加载时用程序设置 `scrollTop`，可能打断进行中的滚轮平滑滚动。词根模式实测误差都不到一条衍生行，所以不做；以后真实词典中出现超过一行的误差再议。

## 4. 加载与测高

- **拖动时的加载**：拖动期间每帧最多更新一次 `scrollTop`，并暂停窗口加载（普通模式的窗口、词根模式的窗口和衍生词请求）。指针停住 50ms 后放开加载，交给按可见范围加载的逻辑；放开后直到指针再次移动都不再暂停。松手时也放开。迟到的旧响应由请求编号丢弃，“最多保留 5 个已加载窗”的上限保证快速拖过大词典时不会全部加载。窗口大小为普通模式每窗 200 条，词根模式每窗 100 组。
- **立即测高**：虚拟列表渲染后，在绘制前用 ResizeObserver 测量新行的高度，按测量前的位置表记下视口顶部的行，更新高度后立即对准回去。每次渲染都按行 key 恢复锚点，包括滚动进行中的渲染（2026-11-16 起，原来滚动中不恢复）。窗口渲染每 50ms 最多一次。
- **关闭浏览器滚动锚定**：导航条接管的列表设 `overflow-anchor: none`。浏览器自带的锚定与上面的手动对准同时生效时会补偿两次，向上滚动时列表会上下闪。
- 不再有“滚动期间延迟应用新高度”：那是为了拖动原生滚动条时不扰动滑块，导航条按布局单位定位后已不需要，代码已于 2026-11-16 删除。

## 5. 分段与概览

### 5.1 概览的使用

- 指针第一次移进导航条时才请求概览，按查询 key（含词典版本）缓存，不并进首窗响应；不碰导航条的用户不必请求。少于 100 的结果也请求，因为气泡仍需要分段名。请求失败时抓手照常可用，只是没有刻度和气泡文字。
- 查询条件变化、列表处于“正在更新”时，导航条保持旧状态并随列表变淡；新首窗提交后丢弃旧概览，按需重新请求。保存词条后查询缓存的 generation 变化，概览随之失效，只在需要显示刻度时重新请求。
- 词根模式：概览以组为单位给出每段的 `start` 和 `count`，另带本段的四个合计（与 `windowMetrics` 同义）。前端把每段起点换算成权重：之前各段按 3.3 的公式累加，再按展开记录中组下标小于 `start` 的项修正。展开状态变化后重新换算刻度，不重新请求。
- 后端按排序顺序把结果切成“相邻且键相同”的段，不用 `GROUP BY`：导入的非 ISO 日期等情况下同一个键的结果不一定连续，按顺序切段时同一个键最多分成两段，起点仍然正确。
- 概览路径不放在 `/entries/`、`/root-groups/` 下，因为这两个前缀下已有以 ID 为路径段的接口，导入的词条 ID 格式不受限。

### 5.2 排序单位

分段用的“首字母”来自排序本身的切分规则，不由导航条决定。共享函数 `firstSortUnit()`（`lib/entry-overview-model.js`）返回词形的第一个排序单位，现在是 `normalizeText` 后的第一个码位，与 `sort_key` 的码位排序一致。限制：`ng` 这类二合字母、NFD 形式的组合附加符号不能作为一个字母；带附加符号的字母（如 `é`）排在 `z` 之后，以标点或数字开头的词形各成一段。这是现有排序的行为，不是导航条的缺陷。

词根组与普通模式用同一个排序：`compareEntryRecordsInSqlOrder()` 是 `sqlOrderClause()` 的内存版本。两种模式因此切出同样的分段。

以后做自定义字母表排序时，这两个排序函数和 `firstSortUnit()` 一起改；`sort_key` 届时可能变成按字母序号编码的排序键，所以分段不能依赖 `sort_key` 的原始内容。导航条本身不用改。

## 6. 隐藏原生滚动条

- 导航条接管的列表用 `scrollbar-width: none`（Chromium 121 起支持；桌面外壳 Electron 31 为 Chromium 126）。只是不画滚动条，滚动容器不变，虚拟列表与锚点恢复只读写 `scrollTop`。
- 始终隐藏，只要能滚动就显示导航条，避免原生滚动条时有时无导致列表宽度变化、卡片全部重新测高。
- 导航条是列表容器的兄弟元素，叠在它右侧，因为虚拟列表每次渲染都会删除容器中不属于当前窗口的子元素。列表的 `padding-right` 给导航条留出位置。
- 列表上下渐隐：遮罩在 `.entry-list` 上，`app.js` 的 `updateEntryListEdges()` 按能否继续滚动写 `data-fade-top`／`data-fade-bottom`。`virtualListNearestScrollTop()` 与 `stabilizeVirtualListItemScroll()` 通过 `virtualListEdgeInset()` 给词条列表留出渐隐高度，点刻度跳转也沿用这个边距，所以对准的那一行不会落在渐隐区里。
- 指针停在导航条上滚动时，滚轮事件到不了列表，需要转发：用非被动监听器取消默认行为（否则外层可滚动的祖先也会跟着滚），再用 `scrollBy` 转给列表，并按 `deltaMode` 把行、页单位换算成像素。

## 7. 模块与接口

- `lib/list-navigator.js`：换算函数（`indexAtScroll`、`scrollTopForIndex`）、抓手几何、刻度排布，以及浏览器控制器 `createListNavigator()`。控制器的选项：
  - `getLayout()`：当前布局；
  - `renderWindow()`：按当前 `scrollTop` 渲染虚拟列表窗口；
  - `setLoadsHeld(held)`：拖动期间暂停窗口加载；
  - `requestOverview()`：请求分段，结果通过 `setOverview()` 送回；
  - `jumpToSegment(bucket)`：点刻度时精确落到该段起点；
  - `formatCount(buckets)`：刻度提示里的数量文字；
  - `formatPosition(index)`：气泡里的位置文字；
  - `minThumb`、`loadDelay`、`tickThreshold`、`tickGap`（默认 32、50、100、20）。

  概览为 `{ size, buckets: [{ start, count, full, short }] }`：分段按结果顺序排列，`start`、`count` 用布局单位，`full` 和 `short` 是气泡和刻度的标签。`size` 达到门槛才显示刻度。布局单位和 `size` 代表什么由调用方决定，位置和数量的文字也由调用方生成。
- `lib/root-group-layout.js`：词根模式的行权重、窗口权重公式、展开记录修正和分段起点换算（`segmentStarts()`），由 `scripts/check-root-group-layout.js` 测试。
- `lib/entry-overview-model.js`：分段切分、时间粒度、时区边界和排序单位，由 `scripts/check-entry-overview.js` 测试。
- `app.js`：布局由 `entryListNavigatorRows()` 生成，概览的请求、缓存和刻度换算在 `requestEntryListOverview()`、`syncEntryListOverview()`，点刻度落位在 `jumpEntryListToSegment()`，气泡文字在 `entryListPositionText()`。
- 以后接入语料列表或质量页列表时，按第二个数据来源的需要调整控制器的接口，现在不预先适配。

## 8. 设计取舍

- **为什么按布局单位而不是像素定位**：像素来自估算和占位高度，测高后总长会变，自绘抓手直接镜像 `scrollTop ÷ scrollHeight` 会漂，刻度也无法稳定摆放。这正是原生滚动条拖动不跟手的原因。
- **为什么隐藏原生滚动条**：两者计算位置的方式不同，同时显示时会对不上。
- **词根模式为什么不用组下标或行下标**：按组下标，滚过一个展开了 300 条衍生词的组（约 13,200px）时抓手不动，拖动也到不了组内；按行下标（词根卡和衍生行各算 1），滚过词根卡时抓手比滚过衍生行慢三倍多，窗内分布也与占位的均匀换算对不上。
- **为什么概览单独请求**：并进首窗会拖慢首屏，而且只有显示刻度时才需要。前端只保留 5 个窗，算不出完整的分段。
- **索引为什么只跟随当前排序**：按词形排序时日期是乱序的，跳到某个日期找不到连续的位置；早先设想的“指针左偏显示首字母、右偏显示日期”手势也很难被发现。
- **没有采用等距字母索引**（类似手机通讯录，保留原生滚动条）：等距排列不反映各段大小和当前位置，时间排序下段数多也放不下。
- **没有在概览里返回每组的衍生词数**：可以让未加载窗内的组序号也精确，但 1 万组约 40KB；近似只出现在全部展开或搜索时的未加载窗内，停住 50ms 后即变精确。

## 9. 测试与验收

- Node 检查（都在 `node scripts/check-all.js` 中）：`check-list-navigator.js`（换算的互逆不变量、抓手几何、刻度合并与分块）、`check-root-group-layout.js`（权重公式、展开记录修正、分段起点）、`check-entry-overview.js`（排序单位、时间粒度、时区边界、按排序顺序切段与无日期段、仓库与路由的概览、两种模式的分段一致、非法时区）。
- 浏览器面板驱动不了原生滚动条，但导航条可以用模拟指针事件测拖动、点轨道和点刻度；落点误差用 1 万条压力词典测。
- 按 `AGENTS.md` 的 UI 验收检查项：中英文、明暗、三套皮肤、320／480／768／1024／1440px、长词形和大词典。真实鼠标滚轮、触控板惯性、触屏和读屏须人工确认，未完成的项记在交接文档。
