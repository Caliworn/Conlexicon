# Liquid Glass Skin Specification

状态：现行规范。本文规定液态玻璃皮肤的定位、材质层级、光学引擎、质量等级、性能边界与降级。产品停在 Q2（烘焙高光），完整折射只在 Lab 中使用；全量性能验收（LQ-7）待实施，见第 9 节。层叠玻璃的 Fluent 材质另见 [Layered Glass Skin Specification](LAYERED_GLASS_SKIN_SPEC.md)。

## 1. 身份与产品边界

- 用户可见名称：`液态玻璃 / Liquid Glass`；内部 ID：`liquid-glass`。经典皮肤作为默认与未知值回退。
- 皮肤样式在 `theme-liquid-glass.css`，只在 `body[data-ui-skin="liquid-glass"]` 下覆盖明暗材质。选择皮肤只改变外观和偏好，不重绘业务页面，也不影响未保存的编辑。
- 产品与 Lab 的分工：产品以 `refraction: false` 创建引擎，停在 Q2（见 8.10）：只烘焙并叠加边缘高光，不生成位移贴图和 SVG 滤镜。就绪表面的背景滤镜用各自的 `--liquid-glass-surface-filter`：两个窄屏抽屉（导航与词条列表）为 `blur(3px) saturate(1.06)`，其余烘焙高光表面为 `none`，因为这些表面背后只有页面渐变或静态面板，模糊和折射都看不出效果。完整折射是引擎默认值，只在 Lab 中使用；下文的折射、位移与 URL filter 描述适用于 Lab。
- 引擎只为导航（continuous）、列表搜索栏等工具栏（toolbar）和紧凑控件（relationship）注册表面；所有角色默认只做单次位移、不做 RGB 色散。内容外壳不使用背景滤镜，浮层和弹窗固定使用 CSS 材质（Q1）。
- 画质分 Q0–Q3 四级（见 8.10）。等待或生成失败为 Q1：只有 tint、边框、阴影和表面自己的背景滤镜，不生成贴图。辅助模式为 Q0，使用实色材质。

## 2. 设计目标

液态玻璃通过体积和光学变化建立自己的视觉层次。

1. 背景透过玻璃时应能看到方向性变化，而不只是均匀模糊。
2. 玻璃边缘同时表达厚度、镜面高光和内阴影。RGB 色散默认关闭，只作为代码中的可选项保留（8.4）。
3. 当前内容、导航和临时浮层必须保持清晰层级，不能把整个应用变成同一种透明卡片。
4. 高密度词典阅读、虚拟列表滚动和编辑操作仍然是产品基础，不以牺牲文字对比换取透明度。
5. 性能是光学效果的硬边界之一，但不是唯一评价标准；允许在少量聚焦表面使用更高成本效果。

公开实现参考 [archisvaze/liquid-glass](https://github.com/archisvaze/liquid-glass)。参考项目通过 SVG `feDisplacementMap` 或全屏 WebGL shader 建立折射；Conlexicon 只借鉴光学原理，不直接复制其全屏演示架构。

## 3. 与层叠玻璃的区别

| 维度 | 层叠玻璃 | 液态玻璃 |
| --- | --- | --- |
| 核心目标 | 云母色实底与分层卡片 | 连续玻璃、体积和方向性镜面 |
| 导航 | 随主题变化的实色云母 | 连续玻璃高光，窄屏抽屉使用轻微模糊 |
| 浮层 | 最前方的临时浮层使用 WinUI 风格的亚克力 | 产品浮层使用 CSS 材质 |
| 当前词条 | 带细边的实色外壳和独立分区卡片 | 连续磨砂外壳和分区细线 |
| 动态 | 控件反馈与短时浮层入场 | 静态环境光，高光沿表面几何烘焙 |
| 性能策略 | 克制、稳定优先 | 聚焦表面视觉优先，重复表面严格限流 |

两个皮肤不得共享含义不清的视觉规则。可以复用通用材质 token、皮肤选择器和全局偏好协议，但光学实现必须各自作用域化。

## 4. 材质层级

### 4.1 环境画布

- 浅色由冰青、珍珠白、淡紫和低饱和琥珀构成连续环境色场。
- 暗色由深海蓝黑、青绿冷光、弱紫和暗金构成。
- 环境色场的职责是为透明与未来折射提供可辨认背景，不作为独立装饰光球。
- 减少透明度、不支持 blur 和强制高对比时回退为单色画布。

### 4.2 稳定内容层

词条列表项、表格、分析卡片和编辑表单内部字段/分组保持近实色且无独立 backdrop blur（工具页面的卡片例外，见 8.6 节的内容外壳）。词条详情内部分区不再有底色和边框，只在一整片外壳内用细线分隔，悬浮时显示浅色底（见 [Style Skin Plan](STYLE_SKIN_PLAN.md) 的词条详情分区分隔接口）。它们可以消费带环境色的 panel/list-item/inset token 和更精细的内外阴影，但不得逐项加入折射；当前主编辑表单的单一 `#entryForm` 外壳属于下一节的聚焦对象例外。

### 4.3 连续导航与列表控制栏

桌面导航和移动抽屉使用半透明连续玻璃。移动应用栏不是玻璃表面：没有外壳，只有一条底部细分隔线，栏内按钮按紧凑控件注册。产品中导航是 Q2：中性 tint 加烘焙高光；移动抽屉另有 `blur(3px) saturate(1.06)`，桌面导航没有背景滤镜（见 8.6）。Lab 的 Q3 在此之上加几何折射。工具导航内部是同一玻璃上的平面列表行：idle 透明，hover 使用低透明中性状态底，active 使用无独立折射、无固定渐变和无外阴影的选择胶囊。展开栏、rail 和移动抽屉共享这一状态语言，不把每个工具项注册成玻璃表面。

词条列表工具栏的布局三套皮肤共用，见[应用外壳规范](APP_SHELL_SPEC.md#词条列表与工具栏三套皮肤共用)；液态玻璃只负责材质。搜索框是胶囊（`--entry-toolbar-radius: var(--radius-pill)`，表头按钮同样是胶囊），有一个无交互、`aria-hidden` 的 `toolbar` 滤镜叶节点（`.entry-mail-search-surface`）；请求 bezel `44px`、最大位移 `12px`、光学模糊 `3px`、饱和度 `1.06×`、最大贴图边长 `420px` 均复用现有角色；tint/外阴影复用移动应用栏材质，浅/暗 tint 均为 `0.34`。搜索框内的按钮使用透明平面材质，不新增逐控件光学。表头不是玻璃表面，是引擎的平面控件区（`FLAT_CONTROL_SCOPE` = `.entry-mail-tools`）：其中的按钮不注册逐控件光学，只用透明平面材质及状态/焦点反馈。三个弹层仍独立采样为 `floating`，其父容器不执行 filter、backdrop-filter 或裁切。Q1 使用同一 tint、边框、外阴影及 `3px / 1.06×` 普通滤镜；无 blur、减少透明度和强制高对比复用移动栏实色/系统色。搜索框表面复用尺寸观察、80ms 真实 resize 合并、在途去重和会话 LRU。

### 4.4 聚焦对象

当前词条详情 `.entry-display` 和完整编辑 `#entryForm` 外壳不使用背景滤镜（背后只有页面渐变，模糊后还会出现色带）；两者不会同时显示。保留原中性 tint（浅色 `0.30`、暗色 `0.34`）、边框和阴影，不进行模糊、位移、RGB 色散或光学镜面合成。两者在角色表中为 `focus / css`，不在引擎中注册，不生成贴图；辅助模式继续消费实色/系统色 token。详情分区透明、只用细线分隔，表单字段继续保持高不透明度；两者都没有独立 blur。Lab 的 focus 光学预设仍保留，供实验比较。

### 4.5 临时浮层

搜索设置、筛选、排序、皮肤选择器、来源建议、右键菜单、结构化 tooltip、质量问题 tooltip 和 toast 固定使用 CSS 材质：`5.5px` CSS blur、`1.12×` 饱和度及原 floating tint/边框/阴影，不注册光学表面，不进入烘焙高光或折射等级。它们面积小、以文字为主，背后通常是信息密集的词条列表，折射会把卡片边框和滚动条拉成错位接缝；随内容变化尺寸的 tooltip、候选和 toast 还几乎每次出现都要重新生成贴图，并从无贴图状态跳到折射状态。浮层内的按钮因此按紧凑控件注册。

信息/确认 modal 和大型词汇网络面板固定使用 CSS 材质：`7px` CSS blur、`1.08×` 饱和度及原 modal tint/边框/阴影，不注册光学表面，不生成贴图。它们是面积最大、承载文字的面板，背后是深色且基本静止的遮罩，折射收益最低、开销最高，每次打开还会从无贴图状态跳到折射状态；面板内的按钮因此按紧凑控件注册，与词条详情外壳内的按钮一致。`ROLE_DEFAULTS.modal` 保留，供 CSS 模糊参数和 Lab 预设使用。

### 4.6 控件

一般按钮、输入框和 select 使用微型玻璃体积：静止时有上缘高光和下缘暗边，hover 增强镜面，pressed 收紧外阴影并增加内压感，但不改变控件几何。工具导航行是连续导航表面的内容，不使用该逐控件体积；导航目的地、底部皮肤/主题/语言命令和收起按钮均不缩放或位移，分别通过 active tint 与稳定边界表达状态。底部命令只由间距和分隔线组成平面分组，不再形成导航卡片内部的第二层外壳；收起导航按钮作为独立命令保留轻量边界。控件均不独立启用 backdrop blur，避免大量小合成层。

## 5. 性能边界

- 禁止列表项、表格行、分析卡片、网络节点和普通输入控件逐项使用 backdrop blur 或折射。
- 同时可见原则上最多一个大面积 blur 和一个临时浮层。
- 不动画 `backdrop-filter`、SVG displacement scale 或大面积 box shadow。
- 隐藏浮层必须退出实际渲染。
- 20k 测试词典下虚拟列表渲染数量不得增加，滚动路径不得加入逐项样式写入。

## 6. 降级与可访问性

- 不支持 `backdrop-filter`：回退为对应层级实色表面。
- `prefers-reduced-transparency: reduce`：移除环境色场、透明、blur 和未来折射。
- `forced-colors: active`：使用系统 Canvas/ButtonFace/Highlight，并关闭装饰阴影。
- 文字、焦点、选中、危险和禁用状态不能仅依赖玻璃透明度表达。
- 正文和关键控件按最不利背景保持 WCAG AA 目标。

## 7. 明确不做

- 不覆盖或重命名层叠玻璃。
- 不把所有内容卡片变成独立玻璃。
- 不加入全屏 WebGL 持续渲染。
- 不使用设备方向、滚动视差或永不停歇的环境动画。
- 不用噪点、霓虹光晕和超大圆角代替真实材质层级。

## 8. 光学引擎

### 8.1 设计结论

光学引擎取代了早期的固定噪声滤镜（`feTurbulence`）、静态色边和指针光场（LQ-1–LQ-3，已从源码删除，过程见 Git 历史和 `CHANGELOG.md`）。既有 `liquid-glass` 皮肤 ID、全局偏好、token 契约、明暗主题、皮肤选择器和辅助模式协议保持不变。

设计结论：

1. 当前“不明显”的首要原因不是缺少照片，而是固定噪声位移与组件几何无关，无法形成沿真实圆角和边缘变化的厚度、法线与折射方向。
2. 单一噪声 filter 适合验证浏览器能力和降级链，不适合作为最终光学核心；最终路径必须按实际宽高、圆角和材质参数生成表面贴图。
3. Conlexicon 的消费者是多个原生 DOM 表面，首选逐表面的 SVG backdrop filter，而不是全屏 WebGL 画布。后者会引入页面背景同步、文字和输入控件合成、持续绘制及命中测试等额外系统，不应仅为了技术形式而采用。
4. 贴图生成不能占用交互主线程。正常路径使用 Worker，并在能力允许时使用 `OffscreenCanvas`；不支持时使用有界、可取消、分帧的主线程后备生成。
5. 性能约束决定生成、缓存和并发策略，但不把光学实现压缩为统一 blur；尚未建立正确坐标模型前，不用 CSS 假焦散补足观感。
6. Q3 折射之后串接 `13–30px` 的角色级普通 blur 会遮蔽位移边界；Q3 必须只使用动态 URL filter，并在位移前执行 `3–7px` 的角色化光学模糊。滤镜链之外的背景模糊由表面自己的 `--liquid-glass-surface-filter` 决定，Q3 就绪时被 URL filter 原子替换。

### 8.2 对参考项目的采用边界

全量方案充分采用 [archisvaze/liquid-glass](https://github.com/archisvaze/liquid-glass) 的核心技术路线，而不是只模仿名称或配色：

- 根据玻璃厚度、bezel 宽度、表面高度函数和折射率计算边缘折射轮廓。
- 根据元素宽高和圆角生成二维位移图，使位移方向跟随真实边缘法线。
- 独立生成法线/rim 图，并在运行期用统一光源矩阵合成镜面高光，而不是为每个方向重建贴图或用一个固定彩色 CSS 描边覆盖全部形状。
- 通过 SVG `feGaussianBlur`、`feImage`、`feDisplacementMap`、颜色处理和合成步骤采样元素背后的页面；模糊先于位移，避免内容表面直接透出下层文字轮廓。
- 在尺寸或形状发生有效变化时重建滤镜资源，而不是把同一噪声贴图拉伸到所有表面。

参考仓库是单块可拖动玻璃的演示，不提供 Conlexicon 所需的多表面注册、皮肤热切换、缓存、Worker、辅助模式、浮层生命周期和虚拟列表隔离。并且截至本设计冻结时没有在仓库根目录发现明确的许可文件，因此实施应采用独立实现：复用公开的图形学原理和浏览器管线，不逐行复制函数、常量或演示代码；设计文档与发布说明保留灵感来源。

### 8.3 模块边界

光学系统作为皮肤内部引擎存在，业务组件不得知道位移图、SVG 节点或滤镜参数。内部模块：

```text
lib/
  liquid-glass-geometry.js     纯几何、法线和折射轮廓计算
  liquid-glass-map-worker.js   位移图与法线/rim 图生成
  liquid-glass-engine.js       表面注册、滤镜资源、缓存和生命周期

theme-liquid-glass.css         材质分层、表面角色和降级
index.html                     隐藏 SVG defs 宿主与脚本加载
app.js                         仅接入皮肤启停和既有浮层生命周期
```

概念接口保持为应用内部能力，不新增公共 API 或偏好字段：

```js
liquidGlassEngine.activate();
liquidGlassEngine.register(element, role, options);
liquidGlassEngine.refresh(element);
liquidGlassEngine.unregister(element);
liquidGlassEngine.deactivate();
```

- `activate()` 扫描并注册稳定表面，建立能力检测和受控观察器。
- `register()` 只接受预定义角色；组件不能传入任意 SVG 或逐组件滤镜算法。
- `deactivate()` 必须断开 observer、取消未完成任务、撤销 object URL、删除内联属性和动态 filter。
- 不使用覆盖整个应用的 `MutationObserver`。虚拟列表会频繁增删节点，不能让词条滚动触发光学扫描；常驻但隐藏的菜单和 modal 在激活时一次注册，真正动态创建的少数表面通过现有创建入口显式注册。

共享层只有材质挂点、启停调用和资源清理，不改导航、tooltip、菜单或 modal 的业务语义，也不触及服务端、HTTP API、SQLite、词典模型、查询会话和虚拟列表算法。

### 8.4 光学模型

每个表面的资源由以下输入确定：

- 几何：内容盒宽高、四角半径、bezel 宽度和可见边缘厚度。
- 材质：近似折射率 `ior`、玻璃厚度、最大位移、边缘软化和镜面宽度。
- 角色：continuous、focus、floating、modal 或 micro。
- 输出：X/Y 位移图、X/Y 法线与 rim 图，以及滤镜安全扩展范围。

几何计算以到圆角矩形边界的有符号距离为基础，在完整 effective bezel 内使用与参考项目一致的 128 采样 convex-squircle 截面和 Snell 路径生成折射轮廓。外缘从 `1 / 128` 采样位置归一化，避免截面导数的奇点把有效折射压缩到最外数像素；轮廓必须连续衰减，外侧四分之一仍保持可见折射，中心边界归零。法线保持朝外用于环境 specular，位移则沿负法线从玻璃内侧取样，与参考实现的 `-normal × displacement` 方向一致，禁止把组件外侧背景整段拖入 rim。specular 使用同一完整 effective bezel，并按相同边缘进度连续衰减；不设置独立百分比限宽。四角按连续法线过渡，禁止使用与形状无关的随机波纹冒充液体。

圆角矩形的最近边法线在内部 medial axis 上会发生方向切换，分别截断水平/垂直影响也会留下可见的激活线。Q3 因此把“外轮廓距离”和“光学方向”分离：先按实际元素尺寸归一化四角半径，以精确 signed distance 决定 inside、edge distance 与 rim；最外层继续服从真实边界法线，随后用 quintic smootherstep 过渡到由四条边共同贡献、全支撑且解析连续的有理势场法线。位移图和 normal/rim 图必须消费同一个方向场，光学带外法线归零；不得再以硬截断 influence、最近边分区或贴图后模糊遮盖接缝。`effectiveBezel = min(requestedBezel, minDimension / 2 - guard)`，不让最小视觉圆角钳制整条直边；`guard` 至少为 `2px` 或一个贴图采样间距。continuous/focus/floating/modal 请求 bezel 为 `44/46/36/52px`。内容、菜单、tooltip、modal 和网络面板继续消费对应角色圆角；导航卡片使用液态皮肤私有的结构圆角，因为它表达的是跨展开、rail 和移动抽屉状态的导航容器，而不是共享 panel。Lab 的圆角滑杆仍是独立诊断输入，不受此约束。

桌面导航、rail 和移动抽屉现在都从视口边缘内缩，四条边均暴露于连续背景，因此与 focus、floating、modal 一样使用完整四边模型。若安全宽度不足 `4px`，表面稳定使用 Q1 普通 blur，不生成畸形贴图；尺寸变化期间立即解除旧几何滤镜并显示 Q1 材质，`ResizeObserver` 合并变化后再以稳定尺寸进入 Q3，禁止拉伸旧贴图伪装过渡。

位移图的 R/G 通道分别编码归一化 X/Y 偏移；第二张图的 R/G/B 分别编码 X 法线、Y 法线与 rim。光源方向不进入几何缓存键；当前产品路径使用默认环境光向量，内部 `setLightVector()` 能力保留给后续正确坐标模型，但应用不再从局部指针位置驱动全部表面。滤镜管线依次完成：

1. 对背景采样按角色执行 `3px` continuous、`4px` focus、`5.5px` floating 或 `7px` modal 光学模糊；诊断表面单独使用 `0.3px` 以观察位移。
2. 用几何位移图执行主体折射。
3. （可选，默认关闭）在外侧光学 rim 内对 R/G/B 使用略有差异的采样尺度并重新合成，形成依附边缘的窄幅色散；正文区域不出现彩边。
4. 进行轻度饱和度和亮度补偿，避免多次合成把画面洗灰。
5. specular 不在滤镜内：引擎把法线与当前光源向量点乘、经同一伽马曲线后乘以 rim 和强度，烘焙成一张带透明度的近白高光图（`bakeSpecularHighlight`），作为 `--liquid-glass-specular-layer` 背景图层画在 tint 之上。高光与背景无关，背景变化时不重算；只有光源改变（目前只有 Lab）才在主线程重新烘焙并替换图片。对近白高光，普通 alpha 叠加与 screen 混合的差异不超过约 6%。CSS 不补充 radial/conic 焦散、方向性 glint 或固定彩色边。

RGB 色散是可选项（`chromaticDispersion`），所有角色默认关闭，只有显式设为 `true` 才启用，开关进入资源键。`feDisplacementMap` 的实际偏移约为尺度 ×（通道值 − 0.5），贴图把位移编码在 ±0.5 内，所以绿通道最大偏移约等于 `maxDisplacement`；红、蓝尺度为绿的 1.06／0.94 倍，红蓝最大差约 0.12 × `maxDisplacement`：relationship 约 0.5px、continuous 约 1.4px、modal 约 1.9px、floating 约 2.6px。背景在折射前已按 σ 3–7px 模糊，即使背后是清晰的高对比边缘，彩边也只有局部对比的约 10–20%（推算，未实测），再被约 30% 的 tint 压低；默认渐变背景下基本不可见。色散却占大表面滤镜 12 个节点中的 8 个，关闭后只剩模糊、位移图、单次位移和饱和度 4 个节点。Lab 的折射组有色散开关，可在细节丰富的背景上对比。浏览器实测：各页面注册为 relationship 的表面高度均为 38–61px，桌面最宽 490px（其他设置“添加规则”），480px 宽度下多个主按钮和分段控件拉伸到约 420–444px，均仍是薄型控件。

色散不是常驻青紫描边。显式启用时，Q3 对 R/G/B 使用三组略有差异的位移尺度并重新合成，使彩边随边缘方向、背景内容和折射强度变化；等待、失败和 Q1 直接回到普通 blur，不再保留静态 CSS 色边。

### 8.5 前景与背景分层

玻璃表面的文字、图标、输入光标和焦点轮廓不得进入位移滤镜。每个正式表面采用一致分层：

```text
content / focus ring       清晰前景；backdrop-filter 不处理前景内容
rim highlight              预烘焙高光图（background-image），与背景无关
base tint                  角色级中性染色与最低可读底色（定位见 8.15）
surface backdrop-filter   Q3 URL 内依次执行角色化 blur 与单次 displacement（RGB 色散为可选项）
page background            被采样的环境内容
```

正式表面继续使用既有 DOM；没有为光学效果增加业务节点。`backdrop-filter` 直接作用于表面背景，不会折射文字和控件前景；方向性 specular 由法线/rim 图预烘焙为表面自身的背景图层，不新增伪元素或 DOM，也不使用 settle。

各等级通过同一个表面局部接口衔接：各正式消费者映射质量无关的 `--liquid-glass-surface-tint` 和角色化 `--liquid-glass-surface-filter`；`pending` / `fallback` 由一条统一规则消费 tint 与表面滤镜，Q2/Q3 的 `ready` 继续消费同一 tint 并叠加高光图，Q3 只把 filter 原子替换为 `--liquid-glass-optical-filter`。明暗主题中的来源 tint 使用 navigation、drawer、toolbar、focus、floating、tooltip 和 modal 等表面语义命名，不再以 `q3` 命名被 Q1/Q3 共享的值。组件边框和阴影本来就是两级共用材质，因此继续由组件角色 token 常驻，不在质量状态规则中重复声明。

### 8.6 表面角色与正式覆盖

引擎只为 `continuous`、`toolbar` 和 `relationship` 三个角色注册表面并烘焙高光（Lab 舞台另用 `diagnostic`）。内容外壳、浮层、弹窗和普通控件是纯 CSS 材质，不在引擎里登记角色，也没有光学默认值；表中按材质名列出，以便对照。Q3 贴图就绪后，光学滤镜会整个代替表面自己的背景滤镜，所以各角色的光学内模糊应与背景模糊一致，Q2 与 Q3 才只差折射：`toolbar` 和 `relationship`（紧凑控件）没有背景滤镜，光学内模糊为 0；`continuous` 的 3px 与移动抽屉一致，但桌面导航没有背景滤镜，两者共用一个角色，暂时无法同时对齐。

| 角色或材质 | 消费者 | 折射策略 | 动态策略 |
| --- | --- | --- | --- |
| `continuous` | 桌面浮动导航卡片、移动导航抽屉 | Lab：`3px` 光学模糊与完整四边折射。产品：移动导航抽屉为 `blur(3px)`，桌面导航无背景滤镜，只保留 tint 与 specular；桌面导航另有 `!important` 规则，以规避 Chrome 局部重绘时在其背景模糊上留下的方框边缘（原生与 SVG 模糊都会触发，只做位移不会） | 静态环境 specular；不跟随局部指针 |
| `toolbar` | 词条列表搜索框与工具栏背景、标签管理页搜索框、语料库搜索框 | 除光学内模糊外参数暂与 continuous 相同，可单独调整；光学内模糊为 0，与它没有背景滤镜一致，Q2 与 Q3 只差折射；产品无背景滤镜，只保留 tint（`--liquid-glass-toolbar-surface-tint`）、阴影与 specular | 同 continuous |
| 内容外壳（CSS） | 内容外壳（`data-surface="content-shell"`）：词条详情、完整编辑、语料详情面板，以及工具页面的卡片 | 无背景滤镜，只有 tint/边框/阴影 | CSS-only，无贴图、位移、色散或光学 specular |
| 浮层（CSS） | 搜索/筛选/排序/皮肤菜单、来源建议、右键菜单、全部结构化 tooltip/popover、toast | 固定 Q1：`5.5px` CSS blur、`1.12×` 饱和度及原 tint/边框/阴影 | CSS-only，无贴图、位移或光学 specular |
| 弹窗（CSS） | 信息/确认 modal、词汇网络主面板 | 固定 Q1：`7px` CSS blur、`1.08×` 饱和度及原 tint/边框/阴影 | CSS-only，无贴图、位移或光学 specular；遮罩不成为 Backdrop Root |
| 普通控件（CSS） | 按钮、输入框、select、chip | CSS/高光图表达微型体积，不逐个采样 backdrop | hover/pressed 改变光照和压力感 |

覆盖规则：

- 已注册表面由引擎写入 `data-liquid-glass-role`，皮肤 CSS 按这一属性消费角色材质；换出液态玻璃时，引擎移除角色、质量状态、滤镜引用和资源。注册表与样式契约共用同一份角色清单。

- 内容外壳是承载内容的页面级表面，用 `data-surface="content-shell"` 声明，当前覆盖词条详情、完整编辑、标签管理、其他设置、自动 IPA、形态函数、数据分析和质量检查。三套皮肤都定义 `--material-content-shell-*`（底色、边框、阴影、模糊）。`--material-entry-detail-*` 的同名四项取自外壳，移动端、分区和分隔线仍由详情接口定义。液态玻璃与层叠玻璃通过同一属性消费各自的外壳材质，经典工具卡片使用通用面板规则。新增内容外壳可直接加该属性。
- 形态结构视图的固定分配试算和表格属性复用内容外壳材质，窄屏抽屉使用 CSS 浮层材质。表卡片沿用词条卡片的 Q1 底色、边框和阴影，选中描边与试算色条叠加在卡片表面。槽位外框用边线标示分组。

- chip list、标签信息、rich tooltip 和质量问题详情 tooltip 都用浮层材质；材质施加在弹出的表面，而不是列表中的每个触发器。
- 词汇网络节点、词条列表项和表格行不是独立折射面，也没有独立模糊。它们通过所属的共享浏览器/面板背景获得环境关系，避免把连续内容切成几十个互相冲突的透镜。分析卡片同样不折射，但作为内容外壳使用 Q1 模糊：数量由页面决定，每个分析子页最多 4 张，不随词典规模增长。
- 通用控件的 `micro` 材质使用上缘镜面、下缘暗边、pressed 内压和焦点层，但不为每个按钮创建 backdrop filter。导航行与词条列表控制栏内部控件是平面材质例外；它们共享外壳光学，不额外模拟逐控件体积。
- 同一时刻可见的临时浮层都应取得正确材质，不再依赖手写 CSS selector 是否恰好覆盖；注册表和样式契约必须共享同一角色清单。

### 8.7 环境背景

照片不是液态玻璃成立的必要条件。正式背景使用可读、具有空间频率的产品化环境场，使折射在空状态、长文档和暗色主题中都可辨认：

- 三到四个尺度不同的低饱和色域，避免只有大块均匀渐变。
- 背景不绘制交叉纤维、网格或噪点等人为参照；折射可观察性来自连续色域、真实组件边界和专用诊断网格。
- 导航侧、内容焦点区和底部形成不同方向的亮度梯度，玻璃移动到不同位置时能够表现不同采样结果。
- 浅色继续使用冰青、珍珠、淡紫和少量暖色；暗色使用蓝黑、冷青、紫和暗金，但禁止霓虹光球、纯装饰噪点和持续漂移动画。
- 可在未来提供用户壁纸作为增强输入，但内置背景必须独立完成全部材质验收；不得用背景图片掩盖光学模型不足。

减少透明度、不支持 backdrop filter 和强制高对比时，环境纹理与透明材质一起关闭，回到稳定实色主题。

### 8.8 运动、光源与表面张力

- 当前液态玻璃不调度局部指针光照；默认环境光向量稳定驱动全部 SVG specular，避免把某个元素的局部坐标错误解释为跨表面的统一方向。
- 文档级 pointermove 监听器维护 tooltip 可见性。液态玻璃的高光由表面几何与环境光生成。
- 动态几何资源成功后原子提交，不再运行 `forming → settled` 生命周期，也不以伪元素缩放、opacity 或假 glint 模拟材质形成。
- 后续若恢复动态光源，必须先定义屏幕空间到统一光源空间的坐标模型，并继续保证不重新生成几何贴图、不动画 displacement scale、blur 半径或大面积阴影。
- meniscus bridge 是可选后续项，未实装；不得在没有稳定锚点和裁切验证时扩展到任意卡片。
- `prefers-reduced-motion` 下保留当前无动画的静态几何折射；减少透明度与强制高对比则连静态折射一起关闭。

### 8.9 生成、缓存和尺寸生命周期

- 生命周期恢复由引擎统一处理：Q3 激活时观察 hidden/class/style 属性变化，仅将影响已注册表面的祖先或表面加入逐帧合并检查；可见性恢复不依赖 ResizeObserver。几何 transitionend/transitioncancel 后检查最终参数；仍有相关过渡运行时等待其结束，最终状态取消额外 resize 防抖。无动画的状态变化同样有效；transform/opacity 动画不触发重建。关闭引擎时移除观察器、事件和待处理帧。
- Q3 资源解析统一覆盖注册、重新显示、参数更新和 resize：相同当前资源不写状态；精确缓存命中同步领取并替换，先保留目标引用再释放旧引用，不经过 pending。仅连续 resize 的缓存/在途任务均未命中时等待 80ms；等待或失败使用 Q1，不拉伸旧几何。现有精确参数键、32MiB 会话 LRU、提交时几何/注册/会话校验及换肤清理继续保留，不预生成尺寸档位。
- Worker 接收纯数值参数并返回 `ImageBitmap`、Blob 或可被 SVG `feImage` 使用的资源；不得把 DOM 传入 Worker。
- 缓存键只描述最终光学输出，使用规范化后的精确宽高、圆角、统一 `effectiveBezel`、厚度、IOR、最大位移、specular、光学模糊、饱和度、有效形状参数和贴图尺寸，不包含表面角色名或 DOM 身份。键与生成输入保持一致，不再只对键作近似量化；不同小数几何使用独立资源，不让输出取决于首次生成者。角色只负责解析参数，得到相同有效参数时继续共享在途任务和缓存；请求 bezel 若收束为相同有效几何也应共享资源。缓存只存在于当前页面内存，皮肤停用或页面关闭即清空，不使用持久化版本字段。
- 贴图分辨率按视觉尺寸和设备像素比决定，并设角色级上限；高 DPI 不需要无限增长。优先保证 rim 的采样密度，中心可以低频表示。每次资源生成只建立一份有界高密度折射轮廓 LUT，并在逐像素循环中插值，避免为两张贴图重复执行 convex-squircle/Snell 幂运算；几何与贴图生成仍为单遍 `O(mapWidth × mapHeight)`，不增加贴图后模糊或临时全图缓冲。
- 使用按字节预算的 LRU，而不是只按元素数量缓存；资源被淘汰或皮肤停用时撤销 object URL 并移除无消费者的 filter。
- `ResizeObserver` 只观察已注册表面的 border-box。注册、观察回调和生成统一读取不受 transform 影响的布局尺寸：resolved CSS 宽高按 box-sizing 补齐 padding/border，保留小数值；无布局盒或脱离 DOM 的表面视为零尺寸。首次同尺寸回报直接忽略，缩放入场不被误判为 resize。表面从隐藏的 `0×0` 恢复时立即查询会话 LRU，缓存命中不经过 resize 延迟；只有两个非零尺寸之间的真实变化才释放活动滤镜、暂回 Q1 并以 `80ms` 合并连续请求，显式刷新取消被替代的计时器。
- 隐藏、注销和参数失效统一更新 generation 并释放表面引用；资源提交前同时复核会话、注册记录身份、generation、连接状态、当前可见性与资源键。即使布局或 visibility 变化尚未被观察器通知，旧结果也不能标为 ready；完成但暂时无消费者的资源仍可留在预算内 LRU，供相同几何重新打开时使用。
- 隐藏表面不生成高分辨率资源。打开或等待精确资源时为 Q1，保持对应组件的 tint 与背景滤镜；生成成功后叠加烘焙高光（Q3 另原子切换为内含角色化光学模糊的动态 URL filter）；失败同样停在 Q1，不得闪白或短暂丢失边界。
- 不存在空闲永久动画循环；帧只用于资源生成、尺寸合并和既有非液态交互，液态玻璃不因指针或资源提交安排装饰帧。

### 8.10 质量等级与降级

质量不是简单的“开/关”，而是保持同一视觉语言的四级路径：

| 等级 | 条件 | 效果 |
| --- | --- | --- |
| Q3 折射 | 引擎以默认的 `refraction: true` 创建（目前只有 Lab），且浏览器支持 URL backdrop filter | Q2 加上动态 URL filter 的几何折射，可选 RGB 色散；滤镜链不含模糊，模糊仍由表面自己的 `--liquid-glass-surface-filter` 决定 |
| Q2 烘焙高光 | 产品默认；Lab 在不支持 URL backdrop filter 时也落到这一级 | 中性 tint 加预烘焙静态环境 specular；Worker 只生成并编码高光图，不生成位移图，也不保留法线/边缘图 |
| Q1 CSS 边缘 | 内容层（内容外壳、浮层、弹窗、富 tooltip、词条卡片、排序卡片和形态表卡片）固定在这一级；引擎表面在贴图尚未生成、生成失败或安全 bezel 小于 `4px` 时也处于 Q1 | 内容层：tint、边框、外阴影，加上由 `--liquid-glass-edge-panel`（大面板三层）或 `--liquid-glass-edge-card`（卡片两层）画出的内阴影边缘。锐利亮边的透明度：大面板 0.5，卡片 0.35（用户要求）。引擎表面目前只有 tint、边框、阴影和背景滤镜，没有 CSS 边缘：它们的阴影来自多个可能为 `none` 的变量，无法直接叠加，待阴影接口整理后再接入 |
| Q0 辅助实色 | 减少透明度或强制高对比 | 实色材质、系统色和明确边界，引擎不启动 |

光源方向只在皮肤里定义一次：`--liquid-glass-light-x` 与 `--liquid-glass-light-y`（当前 `-0.55`、`-0.84`，即左上方）。CSS 边缘的内阴影偏移按 `calc(光源分量 × -长度)` 计算；引擎启动时读取同两个变量作为烘焙高光的光源，Lab 等没有这两个变量的页面使用引擎默认值。高光强度不同步，CSS 边缘与烘焙高光分别按表面调整。模糊不属于任何等级，而是各表面的材质属性（当前只有窄屏抽屉、浮层和弹窗使用）。法线/边缘图的生成代码保留给 Q3 和将来的动态光源，Q2 下暂时停用；光源固定时 Q2 不需要它。能力检测只区分 Q0、Q2、Q3：Q2 不检测浏览器能力，单个表面的贴图失败由该表面落到 Q1；只有 Q3 检查 URL backdrop filter。CSS 中画高光的就绪规则同时匹配 Q2 和 Q3，不放在 URL `@supports` 内；只有 Q3 的折射滤镜规则在 `@supports` 内。

能力检测只决定可用上限，不依据设备名称或用户代理猜测性能。若运行期出现持续长任务、资源生成失败或显存压力，可以按表面从 Q3 降到 Q2/Q1，但必须记录可诊断原因，不能静默让同类浮层随机呈现不同材质。

### 8.11 验收标准

视觉验收必须至少确认：

- 不使用背景照片时，组件边界和色域边界在玻璃 rim 内产生与圆角法线一致的弯折；中心区域不出现随机水波或可辨识的下层正文。
- 全边表面的相邻活跃采样法线连续，corner-to-center medial line 不得形成高梯度斜线；内缩导航的四条暴露边均形成连续 rim，不再假定任何边与屏幕连接。
- 同一表面在不同宽高和圆角下具有一致的视觉厚度，而不是纹理被拉伸。
- 正文、图标、输入光标和焦点环保持清晰，不被 backdrop 位移。
- 浅色/暗色、中英文、长词典名/标签/tooltip、320/480/768/1024/1440px 全部通过。
- 搜索、筛选、来源建议、右键菜单、皮肤菜单、全部结构化 tooltip、toast、modal、网络面板、导航、当前词条和当前主编辑表单具有明确但不同的角色强度。
- 减少动态、减少透明度、强制高对比和不支持滤镜的浏览器走正确等级，不残留 URL filter 或 object URL；触摸/粗指针不会创建液态玻璃指针状态，因为当前产品路径不启用局部光源调度。

工程验收必须至少确认：

- 20k 词典的虚拟列表渲染数量、查询和滚动窗口不因皮肤改变；滚动路径没有逐卡片注册、贴图生成或同步样式测量。
- 共享指针帧不得写入液态玻璃 CSS 变量或光源矩阵；当前液态玻璃只承担资源与尺寸生命周期，不形成指针驱动的持续长任务。
- 重复打开/关闭浮层、resize、明暗切换和皮肤切换后，Worker 任务、observer、filter 节点、object URL 与缓存字节回到预算内。
- 对几何函数建立确定性测试：中心接近零位移、相对边位移方向相反、四角连续、非法 IOR/尺寸安全钳制、同缓存键输出一致。
- 执行所有改动 JavaScript 的 `node --check`、`node scripts/check-all.js`、`git diff --check`，并完成真实 Chromium 浏览器验收；自动化截图不能替代对折射方向和合成层的人工判断。

### 8.12 不进入共享模块的内容

以下能力必须留在液态玻璃引擎内部，不能散落到组件事件处理器或通用主题 token 中：

- IOR、厚度、bezel、位移尺度和贴图分辨率。
- SVG filter 节点、`feImage` 资源和 RGB 色散管线。
- Worker 协议、LRU、object URL 与 generation token。
- Q3/Q2/Q1 光学质量选择和运行期故障降级。
- RGB 位移比例、默认环境光矩阵、specular 强度、未来动态光源坐标模型和可选 meniscus bridge 几何。

共享模块只负责表达“这个元素是什么表面角色”和“皮肤已经启用或停用”。这使全量效果可以大胆迭代，同时把对现有业务、数据和组件结构的影响限制在可替换的适配层。

### 8.13 独立 Liquid Glass Lab

- `liquid-glass-lab.html` 是由现有静态服务器直接提供的独立开发页，只有生产 Product Engine 一条渲染路径，默认装载 Continuous 参数；它不进入主应用导航，不读取或写入词典、界面偏好、`data/`、Web Storage 或任何 `/api/` 端点。它复用生产的 `liquid-glass-geometry.js`、Worker、`liquid-glass-engine.js`、动态 SVG registry 与会话 LRU，不维护第二份算法。
- 表面几何由宽度、高度、圆角和超椭圆指数驱动，初始为可容纳示例文字的 `420×200px`、`60px` 圆角和指数 `2`（与产品一致的传统圆角）；“共享表面几何”默认展开。宽度和高度下限为 `24px`，可以调到按钮尺寸。示例文字各档都是中文“示例文字”，按表面尺寸分四档：宽 ≥ 240px 且高 ≥ 140px 为面板（一行大字，字号按表面的容器查询单位计算，不跟视口；内边距按短边的 16% 取 18–44px），否则宽 ≥ 200px 为单行（工具栏胶囊、toast、tooltip），再窄为居中的按钮文字，宽度小于 56px 时不显示；舞台工具栏的“示例文字”开关可以整体隐藏。单行和按钮档在产品外观下使用夹具的字体、字号、字重和左右内边距，所以紧凑控件在 Lab 里与真实按钮一致。超椭圆角保留直边：指数 `2` 规范化到 Round 快速路径并复用其缓存和贴图字节，更大的值启用超椭圆角。Lab 把指数 n 换算为 CSS `corner-shape: superellipse(log₂ n)`，所以 n = 2 等于 `round`，n = 4 等于 `squircle`。圆角上限只取短边的一半。浏览器不支持 `corner-shape` 时指数锁定为 2。Q3 只保留法线原始字节，供改光源时重新烘焙。
- 预设只装载引擎注册的 continuous、toolbar、relationship 三个角色的默认值，实际 Lab 表面固定注册为不参与产品表面映射的 `diagnostic` 角色；预设放在三组光学参数上方，填写烘焙高光组（光源强度除外）和折射组的参数，以及 Neutral Lab 的中性 tint，不改光源角度和光源强度；手动调参后变为 Custom，重新选择预设即恢复。面板顺序为共享表面几何、光学质量、外观、光学参数预设、光源、烘焙高光、折射；窗口宽度 ≥ 1360px（参数栏在舞台旁）或 681–980px（参数栏在舞台下）时分两列，各节先排满第一列再排第二列。“光源”只有角度，同时转动产品 CSS 边缘（Q1）和烘焙高光；“烘焙高光（Q2 及以上）”为请求 bezel、specular 强度、光源强度和贴图上限；背景模糊和背景饱和度放在外观里：它们是表面自己的背景滤镜，Q1 和 Q2 都用，Q3 贴图就绪后改用折射组的光学内模糊和饱和度，与产品相同；Neutral Lab 默认 3px、1.06×，即产品导航的值，选产品外观时换成该表面的产品值，回到 Neutral Lab 时恢复，手调后状态行显示“产品值 → Lab 值”。tint 滑条放在外观里，名为“tint 不透明度”：Neutral Lab 下调 Lab 自己的中性 tint（预设与明暗切换写入的也是它）；选产品外观时显示该表面计算底色的不透明度，拖动后用 `rgb(from <产品底色> r g b / α)` 只改不透明度、保留产品颜色，改光源、等级或明暗时保留，换外观时回到产品值，回到 Neutral Lab 时恢复当时预设的中性 tint；“折射（仅 Q3）”为厚度、IOR、最大位移、光学内模糊、饱和度和 RGB 色散开关（生产角色均为关闭；三路比例沿用引擎固定值）。厚度、IOR 和最大位移仍进入贴图缓存键，所以在 Q2 下调它们会重新生成贴图但画面不变；只生成完整四边轮廓。
- 舞台提供连续色场、高对比网格、色带和大号文字四种诊断参照；仓库分发五张具有明确 Unsplash 或 Pexels 使用许可的背景，逐张作者、原始页面和许可记录见 `THIRD_PARTY_NOTICES.md`。图片只在选中时加载，不进入产品皮肤。舞台下方可展开生产位移图与法线/rim 图，默认折叠。Q3、Q2、Q1 用三段按钮切换：结构与产品的分段控件相同（一条带边框的按钮组、段间分隔线、选中段实色），颜色用 Lab 自己的变量，键盘用方向键、Home、End 切换；切换时保留几何、参数预设和外观选择；只有 Q3 生成诊断贴图。
- “外观”只有一个下拉框，默认 Neutral Lab（Lab 自己的中性 tint、边框、阴影与文字色），其余选项为产品表面角色、工具栏胶囊和七种紧凑控件配方。选择产品角色时通过 1024px/480px 两个隔离 iframe 以探针模式加载控件对照页 `control-gallery.html?probe`（探针模式不运行光学引擎、关闭动画与过渡），按当前 Q1／Q2／Q3 状态写入夹具的光学角色、`data-liquid-glass-optics` 与空光学滤镜，并把 Lab 的光源方向写入探针的 `--liquid-glass-light-x/y`，使产品 CSS 边缘随光源滑杆与烘焙高光一起转向；镜像 Navigation、drawer、工具栏胶囊（toolbar）、查看/编辑 Focus、floating、rich/quality tooltip、toast、modal、network 以及七种紧凑控件配方（relationship）的计算 tint、边框、完整阴影和文字色。夹具结构只在对照页维护一份（都在“材质角色表面”一节：表面角色固定为 220×120px 的空外壳；工具栏胶囊和七种紧凑控件是保持产品尺寸的尺寸夹具，按钮统一写“示例文字”，所以七种配方宽高相同），Lab 不维护第二份结构或主题值；夹具缺失时报错并恢复 Neutral Lab，状态行附带失败原因。以 `file://` 打开时浏览器不允许读取探针文档，产品角色选项直接停用，页面顶部说明需从本地服务打开。选择产品外观会联动：导航和抽屉、工具栏胶囊、紧凑控件切到各自的 Continuous／Toolbar／Relationship 预设，但当前为 Custom 时保留手动参数；等级也切到产品实际使用的一档：导航、抽屉、工具栏胶囊和紧凑控件为 Q2，内容外壳、浮层、弹窗等纯 CSS 表面为 Q1（产品中没有烘焙高光），之后可以手动切到 Q3 看折射；Neutral Lab 不改等级。背景滤镜也换成该表面的产品值，读夹具计算后的 `backdrop-filter`，所以桌面导航的 `none !important` 也算在内（桌面导航为无，移动抽屉为 3px）；探针不写光学滤镜变量，Q3 状态下的引擎夹具回退到自己的背景滤镜，读到的仍是它；只支持模糊加饱和度，出现其他滤镜函数时报错并恢复 Neutral Lab。共享几何换成该表面的典型尺寸和夹具的产品圆角：产品面板没有固定高度，典型尺寸按 `styles.css` 的产品宽度和常见内容高度估计（如导航 280×640、modal 760×480、toast 360×56），超出舞台时缩小，之后仍可调整；工具栏胶囊和紧凑控件取尺寸夹具的实际宽高和圆角，并锁定宽高、圆角和超椭圆指数（指数回到 2），光学参数仍可调整，切回 Neutral Lab 或其他表面后解锁。外观下方只有 tint、边框、阴影三个图层开关，只旁路最终层；开关是一行三个的整块切换块，整块可点，开启时强调色描边、浅强调底并在左侧打勾，原生复选框隐藏在块上供键盘和读屏使用。正式样式不可用时明确恢复 Neutral Lab。预览卡片可在舞台范围内拖动，拖动只更新合帧后的 transform，不重建几何资源；窄屏时实际宽度按舞台净宽收束。
- 放大镜：舞台工具栏勾选“放大镜”后，舞台上出现直径 240px（窄屏 180px）的圆形镜片，倍数可选 2×、4×、8×，初始位于表面左上角（默认光源一侧）。点击或拖动舞台空白处移动镜片，镜片停在原处，便于一边调参一边看局部；拖动表面仍拖动表面。镜片内是背景和玻璃表面的放大副本，不是屏幕像素的放大：副本逐个复制真实表面的属性（尺寸、外观、拖动位置、引擎写入的光学状态、高光图和滤镜引用），不另行注册引擎表面；照片场景改变时重建背景副本。副本按放大后的尺寸重新绘制，所以 CSS 边缘和边框保持锐利，烘焙高光图被插值放大，能看出它的实际分辨率。镜片带 `filter`，成为 backdrop root，副本的背景滤镜只采样镜片内的放大背景。
- Lab 的 `color-scheme` 跟随自身明暗主题。系统减少透明度时关闭 backdrop filter 与透明底色，使用当前 Lab 主题的实色 panel/text token；强制颜色模式使用 `Canvas` / `CanvasText`。两种模式启用期间 Product Engine 重新探测为 Q0，诊断贴图停止生成；偏好解除后按当前参数恢复。
- SDF Baseline 与本机 Reference Baseline 已经删除，SDF 不再作为生产候选（性能不可接受）；早期对照结论见 `docs/archive/LIQUID_GLASS_RESEARCH.md`。交互状态（悬浮、按下、焦点）的对照在控件对照页，Lab 只镜像默认状态。

### 8.14 浮动连续导航卡片

- `.dictionary-panel` 是唯一的 `continuous` 导航表面，但桌面展开态与 rail 都从视口左、上、下内缩，工作区恢复为全宽画布并只为实际内容保留安全左内边距。页面连续色场延伸到卡片下方，文字和业务控件不被导航覆盖；导航使用完整四边几何、主题感知 regular tint、Q1/Q0 降级和既有运行期资源生命周期。
- 工具行是透明 idle、低透明 hover 与单色 active 胶囊，没有常态渐变、边框层级和多层内外阴影；active 只以状态 tint 和单色图标强调表达当前目的地。pressed 不位移，也不模拟被压入独立玻璃，键盘焦点使用独立的内侧焦点环。
- 皮肤、主题和语言命令复用现有 `.utility-actions` DOM，容器只有顶部分隔线和布局，不绘制嵌套背景、外框或 backdrop filter；内部单元透明且只在 hover、展开或 pressed 时显示状态底。收起按钮保持独立小型命令。
- 移动导航抽屉同样从视口边缘内缩并使用四边模型；窄屏复用原抽屉、遮罩、焦点和导航协议，不把全部目的地压入底部 tab bar。经典和层叠玻璃的布局、材质和按压反馈不受影响。
- 展开/rail 或响应式尺寸变化期间，旧贴图立即退出，尺寸稳定后一次重建；减少动态关闭导航与工作区位移 transition，减少透明度、无 backdrop filter 和强制颜色继续沿 Q0/Q1 路径工作。样式契约保护“单一内缩光学容器、四边几何、全宽环境画布、平面工具行、active 无组件假渐变、导航行无逐项 backdrop filter 和尺寸变化不拉伸旧贴图”的结构边界，不冻结具体透明度、间距、圆角或时长。

### 8.15 tint 与玻璃感（2026-11-02 定案）

2026-11-02 用户确认以下定位，tint 不再是视觉定稿和 U4 的前置决定：

- **继续用静态中性叠色**：每个正式表面末层仍是角色级的均匀 tint（8.5 的 `base tint` 层），不做 `feComponentTransfer` 明暗压缩。明暗压缩的价值是压低对比时保留背景纹理，而默认背景只有柔和渐变，几乎没有纹理可保留。这一点是推断，没有在默认背景上实测。
- **大面板不追求透镜感**：modal、词汇网络面板和全部 floating 浮层是磨砂面板，固定使用 Q1，磨砂感主要来自模糊，tint 决定透出多少背景，也就是通透度和文字可读性。内容外壳（词条详情、完整编辑和工具页卡片）背后只有页面渐变，不用模糊，只靠 tint、边框和阴影成形：用户 2026-11-02 对比后认为这样更好，模糊后的渐变反而会出现色带。
- **tint 是普通数值**：在视觉定稿时按表面调整，标准是文字对比度和观感，对比度按 `STYLE_SKIN_PLAN.md` 4.1 节的控件对照页验收。可以用 `scripts/liquid-glass-tint-probe.js` 试值：在液态玻璃皮肤下粘贴到浏览器控制台，按比例缩放 7 个角色表面的 tint，刷新或点“关闭”即恢复。它切换主题时会保存偏好，应在临时数据目录下使用。
- **不提供照片背景选项**：材质、对比度和玻璃感都以默认渐变背景判断。Lab 和探针里的照片只是调试素材。

产品不使用折射（见第 1 节），保留下来的表面都有边缘高光。Apple 系统材质的观察记录已移入 `docs/archive/LIQUID_GLASS_RESEARCH.md`。

## 9. 待实施：LQ-7 全量性能与资源验收

- 完成视觉矩阵、性能基准、内存/URL 资源泄漏、快速换皮肤和长时间浮层开关测试。
- 复核大量临时表面、连续 resize、缓存压力和低端设备下的质量上限；不得恢复已经删除的固定噪声或双引擎路径。
- 完成后更新 README、CHANGELOG 和正式覆盖清单。

**性能上限**：网页拿不到元素背后已渲染的像素，WebGL／WebGPU 着色器无法读取这些内容，折射真实 DOM 只能走 `backdrop-filter: url()` 加 SVG 滤镜。只要光学表面背后的内容变化（滚动、展开、动画），浏览器就会对每个可见表面重新执行整条滤镜链，中间结果无法缓存。成本大致是“可见光学表面面积 × 滤镜节点数 × 背景变化频率”。算法优化只能减少节点、面积和表面数量，不能改变这一结构。

**待实测的优化候选**（按预期收益排序，逐项对比后决定；高光移出背景滤镜和去掉 RGB 色散两项已完成，现状见 8.4）：

1. **模糊改用原生 `blur()`**：以 `backdrop-filter: blur(Npx) url(#filter)` 串联代替滤镜内的 `feGaussianBlur`。Chromium 原生背景模糊有降采样优化，通常更便宜。需对比边缘处理（当前 `edgeMode="duplicate"`）和模糊、折射顺序变化带来的画面差异。改用原生模糊不能解决桌面导航的方框残影：2026-11-02 用户实测，两种模糊都会触发。
2. **减少同时存在的光学表面**：2026-09-27 代码审查记录的三个风险：词根模式虚拟列表滚动时逐个注册／注销折叠按钮表面、`body` 级 subtree MutationObserver、注销后重新观察全部祖先链。评估大列表内的折叠按钮是否需要独立折射。
3. **去掉 PNG 编码**：贴图在 Worker 中编码为 PNG 再交给 `feImage` 解码，只发生在首次出现或尺寸变化时，收益最小；只有频繁 resize 时才值得处理。

**测量方法**：固定一个背景持续变化的场景，例如在导航和若干紧凑控件下滚动词条列表；用 Chrome Performance 记录帧耗时与 GPU 耗时；每次只改变一项，与当前版本对比。第 1 项取决于画面是否可接受。
