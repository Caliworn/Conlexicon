# Liquid Glass Skin Specification

本文冻结 Conlexicon 液态玻璃皮肤的视觉语言、材质分工、首版参数方向、降级边界和验收要求。它不改变 `docs/STYLE_SKIN_PLAN.md` 定义的通用皮肤契约；运行期接入只增加全局皮肤选择及其紧凑切换控件，不重构业务组件 DOM。

## 1. 状态与适用范围

- 状态：LG-1–LG-3 首版与验收、LG-4A 透明度强化和 LG-4B 静态光学层已完成；LG-4C.1 局部指针光照与词条详情聚焦玻璃处于受限试行，LG-4D 滚动适应仍为可选后续。
- 用户可见名称：`液态玻璃 / Liquid Glass`。
- 内部 ID：`liquid-glass`；经典皮肤 ID 为 `classic`。
- 经典明暗主题继续作为默认皮肤和所有降级路径的可靠基线。
- `uiSkin` 作为全局界面偏好保存在 `data/index.json`，与词典级设置和 SQLite schema 无关；`localStorage` 只镜像已知皮肤值用于首屏预着色，服务端状态仍是权威来源。

本规范中的层级、适用范围、禁用范围和降级原则是稳定约束。颜色、透明度、模糊和阴影表中的数值是首版目标值，可以在浏览器和性能验收后小幅调整，但不得改变角色语义。

## 2. 公开参考

设计参考以下公开规范，但 Conlexicon 不追求逐像素复制任何原生平台：

- [Apple Human Interface Guidelines: Materials](https://developer.apple.com/design/human-interface-guidelines/materials)：Liquid Glass 是控件和导航构成的功能层，不应铺满内容层，并应克制使用。
- [Meet Liquid Glass, WWDC25](https://developer.apple.com/videos/play/wwdc2025/219/)：材质通过透光、边缘、阴影、环境适应和交互反馈建立层级；`clear` 只适合媒体丰富背景和高对比前景。
- [Applying Liquid Glass to custom views](https://developer.apple.com/documentation/swiftui/applying-liquid-glass-to-custom-views)：动态形变和融合依赖专门容器，过多独立玻璃效果会降低渲染性能。
- [Microsoft Acrylic material](https://learn.microsoft.com/windows/apps/design/style/acrylic)：模糊材质适合临时表面和覆盖式辅助界面，不应层层叠放；必须提供不透明降级并保护文字对比度。

这些来源提供原则而非 Web 实现配方。Conlexicon 的实际实现必须服从高密度词典工具的可读性、重复操作效率和现有 token 边界。

## 3. 核心视觉语言

液态玻璃皮肤采用“稳定内容层 + 玻璃功能层”模型：

1. 词条、表格、分析结果和编辑表单是内容，不是玻璃陈列品。
2. 导航、sticky 工具栏、移动顶部栏和临时浮层可以浮在内容之上并透出环境。
3. 液态感来自透光、边缘高光、厚度阴影和短促反馈。画布可以使用最多两层连续、低对比的线性环境色场，让透明材质有可感知的背景；不得使用离散光球、大圆角、发光或大面积透明。
4. 强调色只表达选择和主要动作；警告、危险、焦点继续保留独立颜色语义。
5. 默认只使用较厚的 regular 风格。Conlexicon 没有适合 clear glass 的媒体背景，首版不提供 clear 变体。

## 4. 层级与组件归属

### 4.1 内容层

以下表面保持不透明或接近不透明，不启用明显 `backdrop-filter`：

- 页面画布和主内容区。
- 词条列表项和编辑表单。词条详情仅允许下述单一聚焦对象例外。
- 数据分析卡片、质量结果、文档编辑器和语料内容。
- 形态表格、普通表格、输入区域和嵌套内容块。
- entry browser 的常驻桌面列表面板；移动端列表抽屉也应以可读性优先，不把整列词条置于强模糊材质上。

`panel`、`inset`、`list-item` 和 `browser` 属于这一层。它们可以带轻微环境色和边缘高光，但不能产生“每张卡片各自一块玻璃”的效果。

词条查看态允许一个受限例外：当前唯一 `.entry-display` 可以作为聚焦对象使用低透明度、固定 blur 和两层静态线性反射；词形、IPA、词性、标签与操作直接位于这一外壳，不再嵌套基础信息卡。释义、词源、衍生词、形态和备注等内部区块必须使用接近实色且无 blur 的 `entry-detail-section`，以稳定长文本阅读。该例外不得扩展到词条列表、编辑表单、分析卡片或其他重复对象，也不得参与 LG-4C 指针响应。

### 4.2 功能玻璃层

以下表面允许使用真正的透明和背景模糊：

- 全局工具导航；移动端覆盖导航比固定桌面导航更能体现透光。
- 移动顶部应用栏和确实覆盖滚动内容的 sticky 工具栏。
- 搜索设置、筛选菜单、下拉菜单、右键菜单和来源建议。
- modal、确认弹窗和其他短时浮层面板。
- 富 tooltip；普通短 tooltip 和 toast 继续使用高对比实色。

同一时刻应尽量只有导航或 sticky 表面、一个打开的 floating 表面在执行明显模糊。overlay 负责压低背景，不再叠加另一层大面积模糊。

### 4.3 控件

普通按钮、输入框和 select 使用带透色的 `control` 材质，但默认不独立启用 blur。主要动作可以使用强调色染色；不能给所有控件同一种彩色玻璃，否则会破坏动作层级。标签和分段选中项可以使用 pill，普通矩形控件继续使用紧凑圆角。

控件镜面高光遵循统一状态规则：静止时保留可辨认的迎光上缘，hover 时增强并扩展为较浅的第二层内反射，pressed 时收紧外阴影并降低高光。浅色材质通过亮上缘与微暗下缘共同建立对比，不能只把白色透明度推至上限；暗色材质使用更高可见度但仍受控的白色内反射。内容控件、实色动作和导航控件分别消费自己的 shadow token，不得让通用 `secondary-button` 状态泄漏到连续导航。

## 6. 材质角色参数

| 角色 | 背景方向 | Blur | 视觉要求 |
| --- | --- | --- | --- |
| `panel` | 浅色约 82%，暗色约 84% 不透明度 | `none` | 稳定内容底面，只透出环境色，不使用光学渐变 |
| `entry-detail` | 浅色约 70%，暗色约 74%；窄屏约 78%/82% | 桌面 `18px`，窄屏 `12px` | 单一当前词条的聚焦外壳；两层静态反射，不参与指针响应 |
| `entry-detail-section` | 浅色约 92%，暗色约 93% | `none` | 详情内部稳定阅读底面，不层叠 blur |
| `control` | 约 70% | `none` | 清晰输入边界；依靠边缘与阴影表达厚度 |
| `inset` | 约 84% | `none` | 比 panel 稍深，承载表格和嵌套输入 |
| `list-item` | 约 86% | `none` | 大量重复渲染时保持安静和低成本 |
| `browser` | 约 84% | `none` | 词条列表保持稳定，不与每个列表项形成模糊叠层 |
| `floating` | 浅色约 58%，暗色约 56% | `28px` | 两层静态线性反射、明确边缘和厚度阴影 |
| `sticky` | 浅色约 62%，暗色约 60% | `22px` | 仅用于真正覆盖滚动内容的表面 |
| `mobile-bar` | 约 60% | `26px` | 两层静态反射和稳定底色并存 |
| `navigation` | 不透明深色底面 | `none` | 桌面展开栏和窄轨占据独立布局列，以稳定对比为先；保留双层反射和指针镜面 |
| `navigation-drawer` | 浅色约 89%，暗色约 72% | `24px` | 移动覆盖抽屉透出被覆盖内容，以独立材质角色表达悬浮关系 |
| `tooltip` | 普通提示使用高对比实色；结构化标签/列表浮窗使用有限透明 | 普通提示 `none`，结构化浮窗 `18px` | 短提示以可读性优先；承载多行标签身份的 rich tooltip 可消费有界玻璃材质 |
| `overlay` | 中性暗幕 | `none` | 降低背景竞争，不使用彩色雾化 |

`backdrop-filter` 可以同时使用轻微 `saturate()`，但不得把背景颜色推至高饱和。LG-4B 允许 navigation、mobile-bar、sticky 和 floating 的背景 token 使用两层不对称、低对比线性反射；不得改成噪点纹理、彩色光斑、径向光球或离散渐变装饰。固定画布环境色场和静态光学层都必须在减少透明度或强制高对比模式下移除。

桌面导航与移动抽屉必须分场景处理：桌面导航位于独立网格列，没有需要透出的正文，因此使用不透明底面并关闭大面积 backdrop blur；移动抽屉真实覆盖正文，继续使用 `navigation-drawer` 的有限透明和 blur。两者共享文字、控件、高光、静态线性反射及 LG-4C 指针响应，不得为了材质拆分复制导航 DOM。

浮层阴影应同时表达悬浮高度和玻璃厚度：外部使用柔和深阴影，box shadow 内部只允许微弱顶部高光；背景中的两层静态线性反射负责不对称镜面变化。面板阴影显著弱于浮层。禁止霓虹描边和大面积发光。

## 7. 几何与排版

- 保留 `8px` 的 control、panel 和 floating 主圆角；移动端紧凑控件可以继续使用现有 `10px`。
- pill 只用于标签、状态和适合胶囊语义的选中项。
- 皮肤不得改变布局间距、虚拟列表尺寸、网格轨道、断点、字号层级或 z-index。
- 不为表现液态感增大卡片间距、标题字号或导航宽度。
- 连续导航或工具栏使用一个完整材质表面，不能把每个按钮包成互相贴合的独立玻璃块。

## 8. 交互与动效

- Hover：提高少量背景不透明度或边缘亮度，不缩放控件。
- Pressed：轻微压低亮度并收紧阴影，不使用弹跳。
- 菜单和浮层：`120–160ms` 淡入，可伴随最多 `3px` 位移。
- 承载局部 `backdrop-filter` 面板的全屏遮罩不得动画祖先 `opacity`，以免建立 Backdrop Root 并阻断面板采样页面；遮罩淡入应改为动画 `background-color`，面板自身只动画位移或缩放。
- Focus：继续使用明确焦点环，不能只依赖玻璃高光。
- `prefers-reduced-motion: reduce` 下移除位移和形变，只保留必要的即时状态变化。
- 不实现动态折射、设备方向响应或相邻形状融合。LG-4C.1 保持基础材质固定，只允许在限定的指针响应表面内使用低透明度局部光场；不模拟透镜形变，也不把径向渐变用于装饰性光球。

## 9. 可访问性与降级

- 正文和关键控件必须在最不利背景下保持可读；常规文字至少满足 WCAG AA 对比度目标。
- 不支持 `backdrop-filter`、透明效果被关闭、高对比模式或性能降级模式下，所有玻璃角色回退为相同层级的实色表面。
- 降级不得改变布局、点击区域、边框语义或信息层级。
- `forced-colors` 下不保留装饰性阴影和透色，优先服从系统颜色。
- 任何可点击状态不能只靠透明度变化表达；选中、危险和禁用状态继续使用颜色、边框、图标或文字中的至少两种信号。

## 10. 性能约束

- 禁止对词条卡片、分析卡片、表格行或单元格逐项使用 `backdrop-filter`。
- 同时可见的明显 blur 表面原则上不超过两个常驻表面加一个临时浮层。
- 不动画 `blur()`、`backdrop-filter` 或大面积 box shadow。
- 关闭浮层后必须移除其实际渲染，而不是只把透明度设为零后继续参与合成。
- 320px 移动端、20k 测试词典和虚拟列表滚动必须纳入性能验收；出现持续掉帧时首先减少 blur 面积和层数，而不是降低文字对比度。

## 11. 实施阶段

### LG-1：Token-only 原型（已完成）

- `theme-liquid-glass.css` 使用 `body[data-ui-skin="liquid-glass"]` 和组合暗色作用域覆盖现有 token。
- 原型不修改组件 DOM，不增加动态光学层；经典皮肤继续作为默认状态。
- 现有材质角色足以表达首版，没有扩展通用 token 契约。
- 不支持 backdrop blur、减少透明度和强制高对比时均提供作用域内降级。

### LG-2：运行期接入（已完成）

- `uiSkin` 独立于 light/dark，允许 `classic` 与 `liquid-glass`，由 `/api/preferences` 持久化。
- 经典皮肤保持默认；读取未知或失效皮肤 ID 时回退到经典皮肤，写入未知 ID 时返回结构化错误。
- 导航底部提供紧凑皮肤切换按钮；皮肤和明暗主题可以组合，切换只更新外观与本地化标签，不重置页面或未保存编辑。

### LG-3：验收与增强评估（已完成）

- 已完成可访问性、降级、性能和完整 UI 验收。
- 第一轮视觉辨识度修正允许加入连续画布环境色场，并加强导航、控件、面板和浮层的边缘高光；不得因此把内容卡片改为逐项模糊。
- 独立评估后，首版不加入动态折射、形状融合或设备方向响应：它们需要额外渲染层或持续更新，不能改善高密度词典操作的主要反馈，还会扩大性能、降级和可访问性边界。
- 指针镜面响应限定在连续导航、搜索/筛选浮层、对话框、modal 和大型词汇网络面板；不得应用到词条列表、表格、分析卡片或词汇网络节点。实现必须由一个全局监听器按帧合并更新，并在触摸、减少动态、减少透明度和强制高对比模式下停用。
- 词条详情的聚焦对象玻璃是静态、单实例材质试验：外壳与基础信息共享一个表面，内部栏目保持无 blur 的高不透明度分区；窄屏提高底色不透明度并降低 blur，经典皮肤仍使用原有实色材质。

### LG-4A：透明度与材质层级强化（已完成）

- panel、list-item、browser、inset 和 control 降低不透明度，使连续画布环境色能够透入内容层；这些重复或稳定内容表面仍不启用 backdrop blur，也不加入光学渐变。
- floating、mobile-bar、sticky 和 navigation 进一步降低底色不透明度并提高有界 blur；内容阴影同步收弱，功能浮层继续保持更强厚度。
- 绿色/红色实体动作、普通控件和连续导航内控件使用不同的中性阴影层级；经典皮肤和禁用、ghost、菜单行、tabs 保持无外投影。

### LG-4B：静态光学层（已完成）

- navigation、mobile-bar、sticky 和 floating 使用两层不对称低对比线性反射叠加透明底色，建立静态镜面变化，不增加组件 DOM 或伪元素层级。
- 搜索设置、筛选菜单、来源建议、右键菜单、dialog、modal 和词汇网络面板通过共享 floating token 自动消费同一光学层。
- 不支持 blur、减少透明度和强制高对比路径继续覆盖为实色；LG-4B 不包含指针跟随、滚动适应、动态折射或形状融合。

### LG-4C.1：局部点光与边缘响应（试行）

- 连续导航及当前打开的搜索/筛选浮层、dialog 和 modal 保持 LG-4B 基础材质固定，只叠加一片以光标为中心、没有清晰亮点的宽幅弱光场；光标进入距边缘 `72px` 的范围后，再在最近边缘局部显示短而柔和的高光。大型词汇网络面板只使用更弱、更宽的点光，不显示边缘高光。
- 全局 `pointermove` 只记录当前允许表面和坐标，实际样式写入通过 `requestAnimationFrame` 合并为每帧最多一次；局部坐标量化到 `0.5%`，四边衰减值量化到 `0.02`。指针离开表面时光照在 `150ms` 内淡出；窗口失焦、页面隐藏、切换经典皮肤或进入降级模式时清理全部临时样式。
- 触摸输入、`prefers-reduced-motion: reduce`、`prefers-reduced-transparency: reduce` 和 `forced-colors: active` 不启用该效果。五个有界径向层仅服务当前活动表面的点光与四边局部响应，不得扩展成装饰性光球；实现不改变 blur 数量、组件 DOM、布局或持久化状态。

## 12. 验收清单

- 中文和英文。
- 浅色和暗色主题。
- 320、480、768、1024、1440px。
- 长词典名、长词条、长标签、长筛选名和形态表格。
- 导航、移动抽屉、sticky 工具栏、筛选菜单、搜索设置、右键菜单、modal、tooltip 和 toast。
- 普通、hover、pressed、focus、selected、disabled、warning 和 danger 状态。
- `backdrop-filter` 不可用、减少动态效果、高对比和实色降级。
- 大词典虚拟滚动、连续打开浮层和主题/皮肤切换时无明显合成抖动。

### 12.1 LG-3 验收记录

### 12.3 LG-4C 与导航分场景验收记录

- 浅色和暗色桌面导航均使用不透明 `rgb` 底面且 `backdrop-filter: none`；打开搜索或筛选浮层时只新增 1 个 floating blur。LG-4C.1 的局部点光和近边缘高光仍会在桌面导航上更新，不依赖背景透光。
- 320px 浅色与暗色移动抽屉分别保留约 89% 与 72% 的底色以及 `blur(24px)`；抽屉宽度保持 276px，页面没有横向溢出。移动顶部栏和抽屉同时出现时，明显 blur 表面仍有界为 2 个。
- 指针在导航与允许的 floating 表面之间移动时只保留一个活动标记；切换经典皮肤会立即清理临时坐标。自动化环境不能提供逐帧合成耗时，发布前人工滚动观察项继续保留。
