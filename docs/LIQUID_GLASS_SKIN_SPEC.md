# Liquid Glass Skin Specification

本文记录 Conlexicon 液态玻璃皮肤的定位、材质层级、光学方案、性能边界与分批实施计划。它与已经完成的“层叠玻璃 / Layered Glass”并列，不替代或扩写既有皮肤语义。

## 1. 状态与身份

- 生命周期恢复由引擎统一处理：Q3 激活时观察 hidden/class/style 属性变化，仅将影响已注册表面的祖先或表面加入逐帧合并检查；可见性恢复不依赖 ResizeObserver。几何 transitionend/transitioncancel 后检查最终参数；仍有相关过渡运行时等待其结束，最终状态取消额外 resize 防抖。无动画的状态变化同样有效；transform/opacity 动画不触发重建。关闭引擎时移除观察器、事件和待处理帧。
- Q3 资源解析统一覆盖注册、重新显示、参数更新和 resize：相同当前资源不写状态；精确缓存命中同步领取并替换，先保留目标引用再释放旧引用，不经过 pending。仅连续 resize 的缓存/在途任务均未命中时等待 80ms；等待或失败使用 Q1，不拉伸旧几何。现有精确参数键、32MiB 会话 LRU、提交时几何/注册/会话校验及换肤清理继续保留，不预生成尺寸档位。
- 当前状态：LQ-1–LQ-6 已完成并完成第一优先级光学校正、可读性修正与圆角法线连续性修正；正式 continuous 表面（导航、移动顶栏、列表搜索栏与工具栏背景）和紧凑 relationship 控件在 Q3 使用角色化光学模糊、受安全 bezel 约束的几何滤镜和预烘焙的静态环境 specular 层，所有角色默认只做单次位移、不做 RGB 色散，micro 保持无逐控件 backdrop 采样的 CSS 体积材质；focus、modal 与 floating（后两者 2026-10-02 起）固定使用 Q1。LQ-7 已完成候选 1、2（高光拆层、去色散；2026-10-02 色散改为全部角色默认关闭），其余待实测。
- 用户可见名称：`液态玻璃 / Liquid Glass`。
- 内部 ID：`liquid-glass`。
- 经典皮肤继续作为默认与未知值回退；`layered-glass` 继续保持已经冻结的层叠玻璃边界。
- LQ-2 的固定噪声滤镜与 LQ-3 的五层指针光场只保留为历史阶段记录；LQ-6 已从产品源码移除两条旧视觉路径。Q3 就绪表面只使用动态 URL filter，在滤镜内部先按角色模糊背景采样，再执行几何折射（RGB 色散默认关闭，见 13.4）；静态环境 specular 是滤镜外的独立预烘焙背景层；不叠加外部 Q1 blur。等待或生成失败退回 Q1：沿用同角色 Q3 的 tint、光学模糊、饱和度、边框和阴影参数，但不生成贴图，也不执行位移、RGB 色散或 specular。辅助模式继续使用实色材质。Q2 定义保持不变，其必要性等待单独讨论。

## 2. 设计目标

液态玻璃不是“更透明的层叠玻璃”，而是一套视觉优先、具有明确体积和光学变化的独立皮肤：

1. 背景透过玻璃时应能看到方向性变化，而不只是均匀模糊。
2. 玻璃边缘同时表达厚度、镜面高光和内阴影。RGB 色散默认关闭，只作为代码中的可选项保留（13.4）。
3. 当前内容、导航和临时浮层必须保持清晰层级，不能把整个应用变成同一种透明卡片。
4. 高密度词典阅读、虚拟列表滚动和编辑操作仍然是产品基础，不以牺牲文字对比换取透明度。
5. 性能是光学效果的硬边界之一，但不是唯一评价标准；允许在少量聚焦表面使用更高成本效果。

公开实现参考 [archisvaze/liquid-glass](https://github.com/archisvaze/liquid-glass)。参考项目通过 SVG `feDisplacementMap` 或全屏 WebGL shader 建立折射；Conlexicon 只借鉴光学原理，不直接复制其全屏演示架构。

## 3. 与层叠玻璃的区别

| 维度 | 层叠玻璃 | 液态玻璃 |
| --- | --- | --- |
| 核心目标 | 稳定内容层与功能玻璃层 | 明确折射、体积和方向性镜面 |
| 导航 | 无 blur 实色底面 | 半透明连续玻璃，允许单层大面积 blur |
| 浮层 | blur、边缘和限定指针点光 | 光学模糊、高强度几何折射与环境 specular |
| 当前词条 | 单一静态反射外壳 | 可读中心、宽 rim 的尺寸感知几何折射 |
| 动态 | 低透明度局部光照 | 当前使用静态环境光；动态光源待坐标模型复评 |
| 性能策略 | 克制、稳定优先 | 聚焦表面视觉优先，重复表面严格限流 |

两个皮肤不得共享含义不清的视觉规则。可以复用通用材质 token、皮肤选择器和全局偏好协议，但光学实现必须各自作用域化。

## 4. 材质层级

### 4.1 环境画布

- 浅色由冰青、珍珠白、淡紫和低饱和琥珀构成连续环境色场。
- 暗色由深海蓝黑、青绿冷光、弱紫和暗金构成。
- 环境色场的职责是为透明与未来折射提供可辨认背景，不作为独立装饰光球。
- 减少透明度、不支持 blur 和强制高对比时回退为单色画布。

### 4.2 稳定内容层

词条列表项、表格、分析卡片和编辑表单内部字段/分组保持近实色且无独立 backdrop blur。词条详情内部分区不再有底色和边框，只在一整片外壳内用细线分隔，悬浮时显示浅色底（见 [Style Skin Plan](STYLE_SKIN_PLAN.md) 的词条详情分区分隔接口）。它们可以消费带环境色的 panel/list-item/inset token 和更精细的内外阴影，但不得逐项加入折射；当前主编辑表单的单一 `#entryForm` 外壳属于下一节的聚焦对象例外。

### 4.3 连续导航与列表控制栏

桌面导航、移动应用栏和移动抽屉使用半透明连续玻璃。Q3 对单实例连续表面使用受限分辨率的几何折射，在动态 URL filter 内先执行 `3px` 光学模糊，再叠加角色级中性 tint；Q1 使用相同的 continuous tint、`3px` blur、`1.06×` 饱和度、边框和阴影，只省略贴图与方向性光学。工具导航内部是同一玻璃上的平面列表行：idle 透明，hover 使用低透明中性状态底，active 使用无独立折射、无固定渐变和无外阴影的选择胶囊。展开栏、rail 和移动抽屉共享这一状态语言，不把每个工具项注册成玻璃表面。

液态玻璃独立启用 Mail 布局：桌面摘要列表最大宽度 `340px`，详情获得剩余空间；移动端保留原抽屉。搜索框撑满列表宽度；下方工具胶囊按可见按钮的内容宽度伸缩，最大不超过列表，空间不足时在内部换行。两者各有一个无交互、`aria-hidden` 的 `continuous` 滤镜叶节点（`.entry-mail-search-surface`、`.entry-mail-tools-surface`）。请求 bezel `44px`、最大位移 `12px`、光学模糊 `3px`、饱和度 `1.06×`、最大贴图边长 `420px` 均复用现有角色；tint/外阴影复用移动应用栏材质，浅/暗 tint 均为 `0.34`，常态轮廓消费 `--radius-pill`。词根扩展态半径上限为单行胶囊的 `24px`，避免窄屏两行工具栏变成端部过圆的椭圆。

搜索框只含放大镜、输入和清空；工具胶囊按搜索设置、筛选、排序、词根模式、临时展开/收起操作、新建排列；展开与收起紧邻词根模式，新建始终位于最后，DOM 与键盘顺序保持一致。排序触发器是通用的上下双箭头图标，不再用图标表达当前状态，当前状态由 tooltip、读屏标签和菜单勾选表达；菜单是三套皮肤共用的排序菜单（`lib/entry-sort-control.js`），按“排序依据 / 顺序”两组平面文字行勾选。词根模式在同一玻璃工具栏中追加展开/收起操作，窄屏在同一表面内部换行；当前筛选状态在胶囊之外保留文字。搜索设置/筛选面板默认宽 `340px`，排序菜单宽 `240px`，最大宽度为视口减 `24px`；弹层按触发器位置固定定位，必要时避让视口边界，宽度不继承胶囊。父容器不执行 filter、backdrop-filter 或裁切，弹层仍独立采样为 `floating`。按钮和输入不新增逐控件光学，使用透明平面材质及状态/焦点反馈。Q1 使用同一 tint、边框、外阴影及 `3px / 1.06×` 普通滤镜；无 blur、减少透明度和强制高对比复用移动栏实色/系统色。双表面复用尺寸观察、80ms 真实 resize 合并、在途去重和会话 LRU。

布局所有权：`lib/entry-workspace-layout.js` 中的皮肤到布局映射目前只有液态玻璃启用 `mail`，通过 `data-entry-layout` 驱动共享布局规则；材质留在皮肤文件。控制器移动原节点并保存原位置，不复制表单、事件或业务状态；退出 Mail 时恢复排序控件（标准布局下为文字触发器）及原控件顺序。其他皮肤未来可独立选择该布局，但必须补验其材质与无障碍路径；当前经典和层叠玻璃外观与交互保持原状。布局变化需清理虚拟列表的测高缓存，即使移动端宽度未变；保留虚拟滚动和词条摘要显示配置。不新增布局偏好、Finder 实现或数据协议。

Mail 的三个工具栏弹层在该布局启用时直接移动到 `document.body`，使用 `.entry-workspace-menu` 的 fixed 定位和 `--layer-floating-menu`；不增加覆盖视口的宿主容器，不提升 sticky 列表或工具栏的层级。节点及其表单状态/事件保持不变，退出 Mail 后按原位置锚点恢复。外部点击判定同时检查触发器和弹层；Escape 可在焦点离开弹层后关闭并返回触发器。滚动和 resize 只重新定位，Tab/失焦不关闭；用户执行选择、应用或取消，切换到其他菜单/皮肤，或隐藏所属工作区时正常清理。

### 4.4 聚焦对象

当前词条详情 `.entry-display` 和完整编辑 `#entryForm` 外壳固定使用 Q1；两者不会同时显示。保留原中性 tint（浅色 `0.30`、暗色 `0.34`）、边框和阴影，通过 CSS 使用 `4px` blur 与 `1.09×` 饱和度，不进行位移、RGB 色散或光学镜面合成。两者在角色表中为 `focus / css`，不参与引擎自动或显式 mapped 注册，不生成贴图或占用 Q3 缓存；辅助模式继续消费实色/系统色 token。详情分区透明、只用细线分隔，表单字段继续保持高不透明度；两者都没有独立 blur。Lab 的 focus 光学预设仍保留，供实验比较。

### 4.5 临时浮层

搜索设置、筛选、排序、皮肤选择器、来源建议、右键菜单、结构化 tooltip、质量问题 tooltip 和 toast 自 2026-10-02 起固定使用 Q1：`5.5px` CSS blur、`1.12×` 饱和度及原 floating tint/边框/阴影，不注册光学表面。它们面积小、以文字为主，背后通常是信息密集的词条列表，折射会把卡片边框和滚动条拉成错位接缝；随内容变化尺寸的 tooltip、候选和 toast 还几乎每次出现都要重新生成贴图并从 Q1 跳到 Q3。浮层内的按钮因此按紧凑控件注册。

信息/确认 modal 和大型词汇网络面板自 2026-10-02 起与词条详情外壳一样固定使用 Q1：`7px` CSS blur、`1.08×` 饱和度及原 modal tint/边框/阴影，不注册光学表面，不生成贴图。它们是面积最大、承载文字的面板，背后是深色且基本静止的遮罩，折射收益最低、开销最高，每次打开还会从 Q1 跳到 Q3；面板内的按钮因此按紧凑控件注册，与词条详情外壳内的按钮一致。`ROLE_DEFAULTS.modal` 保留，供 Q1 参数和 Lab 预设使用。

### 4.6 控件

一般按钮、输入框和 select 使用微型玻璃体积：静止时有上缘高光和下缘暗边，hover 增强镜面，pressed 收紧外阴影并增加内压感，但不改变控件几何。工具导航行是连续导航表面的内容，不使用该逐控件体积；导航目的地、底部皮肤/主题/语言命令和收起按钮均不缩放或位移，分别通过 active tint 与稳定边界表达状态。底部命令只由间距和分隔线组成平面分组，不再形成导航卡片内部的第二层外壳；收起导航按钮作为独立命令保留轻量边界。控件均不独立启用 backdrop blur，避免大量小合成层。

## 5. LQ-1 token-only 基线

LQ-1 使用现有 token 契约，不增加组件 DOM，也不加入专用运行期光学脚本：

- `theme-liquid-glass.css` 只在 `body[data-ui-skin="liquid-glass"]` 下覆盖明暗材质。
- 画布提供连续环境色场。
- navigation、navigation-drawer、mobile-bar、floating、overlay-panel 和 entry-detail 按 continuous/focus/floating/modal 角色消费与 Q3 一致的 tint、blur、饱和度、边框与阴影；Q1 不包含任何贴图或方向性光学。
- control 使用静态多层反射，但不使用 blur。
- panel、list-item、browser 和 inset 不执行 backdrop blur。
- 不支持 blur、减少透明度和强制高对比时提供同层级实色降级。
- 选择皮肤只改变外观和偏好，不重绘业务页面或影响未保存编辑。

LQ-1 是与 Q3 外观参数对齐的普通玻璃基线：continuous 为 `3px / 1.06×`、focus 为 `4px / 1.09×`、floating 为 `5.5px / 1.12×`、modal 为 `7px / 1.08×`。它用于没有动态 URL filter 时保留一致的层级和可读性，但不伪造折射率、bezel、位移、色散或镜面效果。

## 6. LQ-2 静态光学引擎（历史，已由 LQ-6 移除）

LQ-2 曾由页面级隐藏 SVG 定义提供两个可复用 filter：

- `soft`：位移 scale 为 `6`，用于当前词条外壳、移动顶部栏和大型词汇网络面板，保留较多内容清晰度。
- `strong`：位移 scale 为 `14`，用于当前打开的小型菜单、modal，以及 chip list、标签信息和 rich 三种结构化 app tooltip，提供更明显的方向变化。

该阶段基线滤镜使用固定 seed 的低频 `feTurbulence`、`feDisplacementMap`、轻微 Gaussian blur 和饱和度修正，CSS 以内侧约 `1px` 的青/紫分离表达色散。LQ-6 完成后，固定 filter、`feTurbulence`、静态 fallback 变量和青紫 inset 色边均已从产品源码删除；隐藏 SVG 只保留空的动态 registry 宿主。

SVG 折射由 `@supports` 作为渐进增强：浏览器不接受 URL backdrop filter 时继续使用 LQ-1 的普通 blur；减少透明度和强制高对比模式显式关闭折射与色散边缘。LQ-2 本身不在运行期重建滤镜，不使用 Canvas，不监听尺寸、滚动或指针，也没有空闲动画循环；这一限制只描述既有基线，已被第 13 节的 LQ-4 全量设计取代为后续方向。

首版不采用全屏 WebGL，原因是它需要持续渲染、背景纹理同步和额外生命周期管理，而 Conlexicon 的主要消费者是有限数量的 DOM 表面。LQ-1–LQ-3 因阶段边界没有按组件尺寸动态生成 Canvas 位移图；现有视觉复评已经确认固定噪声滤镜无法充分表达实体边缘和方向性折射，因此 LQ-4 起正式改用按表面几何生成的位移图与高光图。

## 7. LQ-3 动态焦散（历史，已由 LQ-6 替换）

- allowlist 仅包含当前打开的搜索设置、筛选、来源建议、右键菜单、皮肤选择器、modal 和大型词汇网络面板；当前词条、移动顶栏、tooltip、列表项、分析卡片、表格行和网络节点不响应指针。
- 指针中心产生宽而柔和的局部焦散，距边缘 `72px` 内增强最近边缘高光；四个边缘 glint 与一个中心焦散共同组成五层有界径向光场。
- 色散仍由 LQ-2 的约 `1px` 内侧青/紫边承担，动态 glint 只轻微改变迎光边缘，不形成霓虹描边。
- tooltip 可见性与两套玻璃光效共用一个文档级 `pointermove` 监听器；调度器只为当前皮肤安排一次 `requestAnimationFrame`，另一皮肤的临时状态立即清理。
- 指针离开目标后以 `180ms` 退出并删除 data attribute 与六个坐标变量；空闲时不存在持续动画循环。
- 触摸、非精细指针、减少动态、减少透明度和强制高对比模式关闭动态焦散；皮肤切换、窗口失焦、resize、页面隐藏与 pointer cancel 都会清理状态。

LQ-6 已删除上述五层 CSS 光场、四边距离变量和 `data-liquid-glass-pointer` 状态。LQ-6 初版加入的单层局部焦散、CSS glint、局部指针调度和表面形成 settle 后续也在第一优先级光学校正中删除；当前液态玻璃不再参与共享 pointer dispatcher，只保留 SVG 内由默认环境光向量驱动的 specular。

## 8. 性能边界

- 禁止列表项、表格行、分析卡片、网络节点和普通输入控件逐项使用 backdrop blur 或折射。
- 同时可见原则上最多一个大面积 blur、一个折射聚焦对象和一个临时浮层。
- 不动画 `backdrop-filter`、SVG displacement scale 或大面积 box shadow。
- 隐藏浮层必须退出实际渲染。
- 移动端降低 entry-detail 和 mobile-bar 的 blur；大型网络面板不使用 `strong` 折射。
- 20k 测试词典下虚拟列表渲染数量不得增加，滚动路径不得加入逐项样式写入。

## 9. 降级与可访问性

- 不支持 `backdrop-filter`：回退为对应层级实色表面。
- `prefers-reduced-transparency: reduce`：移除环境色场、透明、blur 和未来折射。
- `forced-colors: active`：使用系统 Canvas/ButtonFace/Highlight，并关闭装饰阴影。
- 文字、焦点、选中、危险和禁用状态不能仅依赖玻璃透明度表达。
- 正文和关键控件按最不利背景保持 WCAG AA 目标。

## 13. LQ-4–LQ-7 全量光学重构

### 13.1 设计结论与替代关系

本节是液态玻璃的正式后续设计及当前实现记录。文档保留 LQ-1–LQ-3 的历史验收背景，但 LQ-6 已在产品源码中完全取代固定 `feTurbulence`、静态色边和旧指针光场。既有 `liquid-glass` 皮肤 ID、全局偏好、token 契约、明暗主题、皮肤选择器和辅助模式协议保持不变。

独立复评后的结论如下：

1. 当前“不明显”的首要原因不是缺少照片，而是固定噪声位移与组件几何无关，无法形成沿真实圆角和边缘变化的厚度、法线与折射方向。
2. 单一噪声 filter 适合验证浏览器能力和降级链，不适合作为最终光学核心；最终路径必须按实际宽高、圆角和材质参数生成表面贴图。
3. Conlexicon 的消费者是多个原生 DOM 表面，首选逐表面的 SVG backdrop filter，而不是全屏 WebGL 画布。后者会引入页面背景同步、文字和输入控件合成、持续绘制及命中测试等额外系统，不应仅为了技术形式而采用。
4. 贴图生成不能占用交互主线程。正常路径使用 Worker，并在能力允许时使用 `OffscreenCanvas`；不支持时使用有界、可取消、分帧的主线程后备生成。
5. 性能约束决定生成、缓存和并发策略，但不得再次把光学实现压缩为统一 blur。高质量设备应获得完整折射、色散和镜面；尚未建立正确坐标模型前，不用 CSS 假焦散补足观感。
6. Q3 折射之后串接 `13–30px` 的角色级普通 blur 会遮蔽位移边界；Q3 必须只使用动态 URL filter，并在位移前执行 `3–7px` 的角色化光学模糊。外部普通 blur 仅属于独立的 Q1 路径。

### 13.2 对参考项目的采用边界

全量方案充分采用 [archisvaze/liquid-glass](https://github.com/archisvaze/liquid-glass) 的核心技术路线，而不是只模仿名称或配色：

- 根据玻璃厚度、bezel 宽度、表面高度函数和折射率计算边缘折射轮廓。
- 根据元素宽高和圆角生成二维位移图，使位移方向跟随真实边缘法线。
- 独立生成法线/rim 图，并在运行期用统一光源矩阵合成镜面高光，而不是为每个方向重建贴图或用一个固定彩色 CSS 描边覆盖全部形状。
- 通过 SVG `feGaussianBlur`、`feImage`、`feDisplacementMap`、颜色处理和合成步骤采样元素背后的页面；模糊先于位移，避免内容表面直接透出下层文字轮廓。
- 在尺寸或形状发生有效变化时重建滤镜资源，而不是把同一噪声贴图拉伸到所有表面。

参考仓库是单块可拖动玻璃的演示，不提供 Conlexicon 所需的多表面注册、皮肤热切换、缓存、Worker、辅助模式、浮层生命周期和虚拟列表隔离。并且截至本设计冻结时没有在仓库根目录发现明确的许可文件，因此实施应采用独立实现：复用公开的图形学原理和浏览器管线，不逐行复制函数、常量或演示代码；设计文档与发布说明保留灵感来源。

### 13.3 模块边界

光学系统作为皮肤内部引擎存在，业务组件不得知道位移图、SVG 节点或滤镜参数。建议的内部模块如下：

```text
lib/
  liquid-glass-geometry.js     纯几何、法线和折射轮廓计算
  liquid-glass-map-worker.js   位移图与法线/rim 图生成
  liquid-glass-engine.js       表面注册、滤镜资源、缓存和生命周期

theme-liquid-glass.css         材质分层、表面角色和降级
index.html                     隐藏 SVG defs 宿主与脚本加载
app.js                         仅接入皮肤启停和既有浮层生命周期
```

概念接口保持为应用内部能力，不新增公共 API 或偏好字段：

```js
liquidGlassEngine.activate();
liquidGlassEngine.register(element, role, options);
liquidGlassEngine.refresh(element);
liquidGlassEngine.unregister(element);
liquidGlassEngine.deactivate();
```

- `activate()` 扫描并注册稳定表面，建立能力检测和受控观察器。
- `register()` 只接受预定义角色；组件不能传入任意 SVG 或逐组件滤镜算法。
- `deactivate()` 必须断开 observer、取消未完成任务、撤销 object URL、删除内联属性和动态 filter。
- 不使用覆盖整个应用的 `MutationObserver`。虚拟列表会频繁增删节点，不能让词条滚动触发光学扫描；常驻但隐藏的菜单和 modal 在激活时一次注册，真正动态创建的少数表面通过现有创建入口显式注册。

预计约 80% 的实现位于上述液态玻璃专用模块和样式中。共享层只增加材质挂点、启停调用和资源清理，不改导航、tooltip、菜单或 modal 的业务语义，也不触及服务端、HTTP API、SQLite、词典模型、查询会话和虚拟列表算法。

### 13.4 光学模型

每个表面的资源由以下输入确定：

- 几何：内容盒宽高、四角半径、bezel 宽度和可见边缘厚度。
- 材质：近似折射率 `ior`、玻璃厚度、最大位移、边缘软化和镜面宽度。
- 角色：continuous、focus、floating、modal 或 micro。
- 输出：X/Y 位移图、X/Y 法线与 rim 图，以及滤镜安全扩展范围。

几何计算以到圆角矩形边界的有符号距离为基础，在完整 effective bezel 内使用与参考项目一致的 128 采样 convex-squircle 截面和 Snell 路径生成折射轮廓。外缘从 `1 / 128` 采样位置归一化，避免截面导数的奇点把有效折射压缩到最外数像素；轮廓必须连续衰减，外侧四分之一仍保持可见折射，中心边界归零。法线保持朝外用于环境 specular，位移则沿负法线从玻璃内侧取样，与参考实现的 `-normal × displacement` 方向一致，禁止把组件外侧背景整段拖入 rim。specular 使用同一完整 effective bezel，并按相同边缘进度连续衰减；不设置独立百分比限宽。四角按连续法线过渡，禁止使用与形状无关的随机波纹冒充液体。

圆角矩形的最近边法线在内部 medial axis 上会发生方向切换，分别截断水平/垂直影响也会留下可见的激活线。Q3 因此把“外轮廓距离”和“光学方向”分离：先按实际元素尺寸归一化四角半径，以精确 signed distance 决定 inside、edge distance 与 rim；最外层继续服从真实边界法线，随后用 quintic smootherstep 过渡到由四条边共同贡献、全支撑且解析连续的有理势场法线。位移图和 normal/rim 图必须消费同一个方向场，光学带外法线归零；不得再以硬截断 influence、最近边分区或贴图后模糊遮盖接缝。`effectiveBezel = min(requestedBezel, minDimension / 2 - guard)`，不让最小视觉圆角钳制整条直边；`guard` 至少为 `2px` 或一个贴图采样间距。continuous/focus/floating/modal 请求 bezel 为 `44/46/36/52px`。内容、菜单、tooltip、modal 和网络面板继续消费对应角色圆角；导航卡片使用液态皮肤私有的结构圆角，因为它表达的是跨展开、rail 和移动抽屉状态的导航容器，而不是共享 panel。Lab 的圆角滑杆仍是独立诊断输入，不受此约束。

桌面导航、rail、移动应用栏和移动抽屉现在都从视口边缘内缩，四条边均暴露于连续背景，因此与 focus、floating、modal 一样使用完整四边模型。若安全宽度不足 `4px`，表面稳定使用 Q1 普通 blur，不生成畸形贴图；尺寸变化期间立即解除旧几何滤镜并显示 Q1 材质，`ResizeObserver` 合并变化后再以稳定尺寸进入 Q3，禁止拉伸旧贴图伪装过渡。

位移图的 R/G 通道分别编码归一化 X/Y 偏移；第二张图的 R/G/B 分别编码 X 法线、Y 法线与 rim。光源方向不进入几何缓存键；当前产品路径使用默认环境光向量，内部 `setLightVector()` 能力保留给后续正确坐标模型，但应用不再从局部指针位置驱动全部表面。滤镜管线依次完成：

1. 对背景采样按角色执行 `3px` continuous、`4px` focus、`5.5px` floating 或 `7px` modal 光学模糊；诊断表面单独使用 `0.3px` 以观察位移。
2. 用几何位移图执行主体折射。
3. （可选，默认关闭）在外侧光学 rim 内对 R/G/B 使用略有差异的采样尺度并重新合成，形成依附边缘的窄幅色散；正文区域不出现彩边。
4. 进行轻度饱和度和亮度补偿，避免多次合成把画面洗灰。
5. specular 不在滤镜内：引擎把法线与当前光源向量点乘、经同一伽马曲线后乘以 rim 和强度，烘焙成一张带透明度的近白高光图（`bakeSpecularHighlight`），作为 `--liquid-glass-specular-layer` 背景图层画在 tint 之上。高光与背景无关，背景变化时不重算；只有光源改变（目前只有 Lab）才在主线程重新烘焙并替换图片。对近白高光，普通 alpha 叠加与原 screen 混合的差异不超过约 6%；层序由 tint 之下改为 tint 之上，高光略亮，需目视确认。CSS 不补充 radial/conic 焦散、方向性 glint 或固定彩色边。

RGB 色散是可选项（`chromaticDispersion`），2026-10-02 起所有角色默认关闭，只有显式设为 `true` 才启用，开关进入资源键。`feDisplacementMap` 的实际偏移约为尺度 ×（通道值 − 0.5），贴图把位移编码在 ±0.5 内，所以绿通道最大偏移约等于 `maxDisplacement`；红、蓝尺度为绿的 1.06／0.94 倍，红蓝最大差约 0.12 × `maxDisplacement`：relationship 约 0.5px、continuous 约 1.4px、modal 约 1.9px、floating 约 2.6px。背景在折射前已按 σ 3–7px 模糊，即使背后是清晰的高对比边缘，彩边也只有局部对比的约 10–20%（推算，未实测），再被约 30% 的 tint 压低；默认渐变背景下基本不可见。色散却占大表面滤镜 12 个节点中的 8 个，关闭后只剩模糊、位移图、单次位移和饱和度 4 个节点（全局超椭圆外形另加 2 个裁切节点）。Lab 升级为材质工作台时再接入开关，用于在细节丰富的背景上对比。2026-10-01 浏览器实测：各页面注册为 relationship 的表面高度均为 38–61px，桌面最宽 490px（其他设置“添加规则”），480px 宽度下多个主按钮和分段控件拉伸到约 420–444px，均仍是薄型控件。

色散不是常驻青紫描边。显式启用时，Q3 对 R/G/B 使用三组略有差异的位移尺度并重新合成，使彩边随边缘方向、背景内容和折射强度变化；等待、失败和 Q1 直接回到普通 blur，不再保留静态 CSS 色边。

### 13.5 前景与背景分层

玻璃表面的文字、图标、输入光标和焦点轮廓不得进入位移滤镜。每个正式表面采用一致分层：

```text
content / focus ring       清晰前景；backdrop-filter 不处理前景内容
rim highlight              预烘焙高光图（background-image），与背景无关
base tint                  角色级中性染色与最低可读底色（替代方向见 13.19）
surface backdrop-filter   Q3 URL 内依次执行角色化 blur 与单次 displacement（RGB 色散为可选项）
page background            被采样的环境内容
```

正式表面继续使用既有 DOM；没有为光学效果增加业务节点。`backdrop-filter` 直接作用于表面背景，不会折射文字和控件前景；方向性 specular 由法线/rim 图预烘焙为表面自身的背景图层，不新增伪元素或 DOM，也不使用 settle。

Q1 与 Q3 通过同一个表面局部接口衔接：各正式消费者映射质量无关的 `--liquid-glass-surface-tint` 和角色化 `--liquid-glass-surface-q1-filter`；`pending` / `fallback` 由一条统一规则消费 tint 与普通 blur，`ready` 继续消费同一 tint，只把 filter 原子替换为 `--liquid-glass-optical-filter`。明暗主题中的来源 tint 使用 navigation、drawer、mobile-bar、focus、floating、tooltip 和 modal 等表面语义命名，不再以 `q3` 命名被 Q1/Q3 共享的值。组件边框和阴影本来就是两级共用材质，因此继续由组件角色 token 常驻，不在质量状态规则中重复声明。

### 13.6 表面角色与正式覆盖

| 角色 | 消费者 | 折射策略 | 动态策略 |
| --- | --- | --- | --- |
| `continuous` | 桌面浮动导航卡片、移动浮动应用栏与导航抽屉、词条列表控制栏背景 | `3px` 光学模糊；所有内缩容器使用完整四边折射 | 静态环境 specular；不跟随局部指针 |
| `focus` | 当前词条详情外壳、当前主编辑聚焦面 | 固定 Q1：`4px` CSS blur、`1.09×` 饱和度及原 tint/边框/阴影 | CSS-only，无贴图、位移、色散或光学 specular |
| `floating` | 搜索/筛选/排序/皮肤菜单、来源建议、右键菜单、全部结构化 tooltip/popover、toast | 固定 Q1（2026-10-02 起）：`5.5px` CSS blur、`1.12×` 饱和度及原 tint/边框/阴影 | CSS-only，无贴图、位移或光学 specular |
| `modal` | 信息/确认 modal、词汇网络主面板 | 固定 Q1（2026-10-02 起）：`7px` CSS blur、`1.08×` 饱和度及原 tint/边框/阴影 | CSS-only，无贴图、位移或光学 specular；遮罩不成为 Backdrop Root |
| `micro` | 按钮、输入框、select、chip | CSS/高光图表达微型体积，不逐个采样 backdrop | hover/pressed 改变光照和压力感 |

覆盖规则：

- chip list、标签信息、rich tooltip 以及实际可见数量有界的质量问题详情 tooltip 都归入 `floating`；折射施加在弹出的表面，而不是列表中的每个触发器。
- toast 只在 `.show` 可见周期内显式注册为 `floating`，隐藏、换皮肤或辅助媒体变化时立即注销或重建对应质量路径；常驻隐藏节点不保留角色、observer 或活动资源引用，已生成几何资源只允许留在受字节预算约束的 LRU 中供后续复用。
- 词汇网络节点、词条列表项、表格行和分析卡片仍不是独立折射面。它们通过所属的共享浏览器/面板背景获得环境关系，避免把连续内容切成几十个互相冲突的透镜。
- 通用控件的 `micro` 材质使用上缘镜面、下缘暗边、pressed 内压和焦点层，但不为每个按钮创建 backdrop filter。导航行与词条列表控制栏内部控件是平面材质例外；它们共享外壳光学，不额外模拟逐控件体积。
- 同一时刻可见的临时浮层都应取得正确材质，不再依赖手写 CSS selector 是否恰好覆盖；注册表和样式契约必须共享同一角色清单。

### 13.7 环境背景

照片不是液态玻璃成立的必要条件。正式背景使用可读、具有空间频率的产品化环境场，使折射在空状态、长文档和暗色主题中都可辨认：

- 三到四个尺度不同的低饱和色域，避免只有大块均匀渐变。
- 背景不绘制交叉纤维、网格或噪点等人为参照；折射可观察性来自连续色域、真实组件边界和专用诊断网格。
- 导航侧、内容焦点区和底部形成不同方向的亮度梯度，玻璃移动到不同位置时能够表现不同采样结果。
- 浅色继续使用冰青、珍珠、淡紫和少量暖色；暗色使用蓝黑、冷青、紫和暗金，但禁止霓虹光球、纯装饰噪点和持续漂移动画。
- 可在未来提供用户壁纸作为增强输入，但内置背景必须独立完成全部材质验收；不得用背景图片掩盖光学模型不足。

减少透明度、不支持 backdrop filter 和强制高对比时，环境纹理与透明材质一起关闭，回到稳定实色主题。

### 13.8 运动、光源与表面张力

- 当前液态玻璃不调度局部指针光照；默认环境光向量稳定驱动全部 SVG specular，避免把某个元素的局部坐标错误解释为跨表面的统一方向。
- 共享文档级 pointer dispatcher 继续服务 tooltip 可见性和层叠玻璃，但不写入液态玻璃 CSS 坐标、data attribute 或光源矩阵。
- 动态几何资源成功后原子提交，不再运行 `forming → settled` 生命周期，也不以伪元素缩放、opacity 或假 glint 模拟材质形成。
- 后续若恢复动态光源，必须先定义屏幕空间到统一光源空间的坐标模型，并继续保证不重新生成几何贴图、不动画 displacement scale、blur 半径或大面积阴影。
- meniscus bridge 仍是可选后续项，本批未实装；不得把它视为 LQ-6 完成条件，也不得在没有稳定锚点和裁切验证时扩展到任意卡片。
- `prefers-reduced-motion` 下保留当前无动画的静态几何折射；减少透明度与强制高对比则连静态折射一起关闭。

### 13.9 生成、缓存和尺寸生命周期

- Worker 接收纯数值参数并返回 `ImageBitmap`、Blob 或可被 SVG `feImage` 使用的资源；不得把 DOM 传入 Worker。
- 缓存键只描述最终光学输出，使用规范化后的精确宽高、圆角、统一 `effectiveBezel`、厚度、IOR、最大位移、specular、光学模糊、饱和度、有效形状参数和贴图尺寸，不包含表面角色名或 DOM 身份。键与生成输入保持一致，不再只对键作近似量化；不同小数几何使用独立资源，不让输出取决于首次生成者。角色只负责解析参数，得到相同有效参数时继续共享在途任务和缓存；请求 bezel 若收束为相同有效几何也应共享资源。缓存只存在于当前页面内存，皮肤停用或页面关闭即清空，不使用持久化版本字段。
- 贴图分辨率按视觉尺寸和设备像素比决定，并设角色级上限；高 DPI 不需要无限增长。优先保证 rim 的采样密度，中心可以低频表示。每次资源生成只建立一份有界高密度折射轮廓 LUT，并在逐像素循环中插值，避免为两张贴图重复执行 convex-squircle/Snell 幂运算；几何与贴图生成仍为单遍 `O(mapWidth × mapHeight)`，不增加贴图后模糊或临时全图缓冲。
- 使用按字节预算的 LRU，而不是只按元素数量缓存；资源被淘汰或皮肤停用时撤销 object URL 并移除无消费者的 filter。
- `ResizeObserver` 只观察已注册表面的 border-box。注册、观察回调和生成统一读取不受 transform 影响的布局尺寸：resolved CSS 宽高按 box-sizing 补齐 padding/border，保留小数值；无布局盒或脱离 DOM 的表面视为零尺寸。首次同尺寸回报直接忽略，缩放入场不被误判为 resize。表面从隐藏的 `0×0` 恢复时立即查询会话 LRU，缓存命中不经过 resize 延迟；只有两个非零尺寸之间的真实变化才释放活动滤镜、暂回 Q1 并以 `80ms` 合并连续请求，显式刷新取消被替代的计时器。
- 隐藏、注销和参数失效统一更新 generation 并释放表面引用；资源提交前同时复核会话、注册记录身份、generation、连接状态、当前可见性与资源键。即使布局或 visibility 变化尚未被观察器通知，旧结果也不能标为 ready；完成但暂时无消费者的资源仍可留在预算内 LRU，供相同几何重新打开时使用。
- 隐藏表面不生成高分辨率资源。打开或等待精确资源时继续使用对应组件的 Q1 普通材质 blur，生成成功后原子切换为内含角色化光学模糊的动态 URL filter；失败同样保留普通 blur，不得闪白或短暂丢失边界。
- 不存在空闲永久动画循环；帧只用于资源生成、尺寸合并和既有非液态交互，液态玻璃不因指针或资源提交安排装饰帧。

### 13.10 质量等级与降级

质量不是简单的“开/关”，而是保持同一视觉语言的四级路径：

| 等级 | 条件 | 效果 |
| --- | --- | --- |
| Q3 完整光学 | URL backdrop filter、Worker/Canvas 和正常透明度可用 | 仅动态 URL filter：角色化光学模糊、几何折射；滤镜外叠加预烘焙静态环境 specular 与中性 tint |
| Q2 缓存光学 | 生成受限但存在相同几何缓存资源 | 复用量化尺寸的几何贴图与统一光源合成，保留真实位移 |
| Q1 基线玻璃 | URL filter、Canvas 或贴图生成不可用，或单个表面安全 bezel 小于 `4px` | 与 Q3 同角色的 tint、blur、饱和度、边框和阴影；无贴图、位移、RGB 色散、specular 或 CSS 彩色 rim |
| Q0 辅助实色 | 减少透明度、强制高对比或 backdrop filter 不可用 | 实色材质、系统色和明确边界，无折射/色散 |

能力检测只决定可用上限，不依据设备名称或用户代理猜测性能。若运行期出现持续长任务、资源生成失败或显存压力，可以按表面从 Q3 降到 Q2/Q1，但必须记录可诊断原因，不能静默让同类浮层随机呈现不同材质。

#### LQ-7：全量性能与资源验收

- 完成视觉矩阵、性能基准、内存/URL 资源泄漏、快速换皮肤和长时间浮层开关测试。

- 更新 README、CHANGELOG、阶段交接和正式覆盖清单。

**性能上限（2026-10-01 分析）**：网页拿不到元素背后已渲染的像素，WebGL／WebGPU 着色器无法读取这些内容，折射真实 DOM 只能走 `backdrop-filter: url()` 加 SVG 滤镜。只要光学表面背后的内容变化（滚动、展开、动画），浏览器就会对每个可见表面重新执行整条滤镜链，中间结果无法缓存。成本大致是“可见光学表面面积 × 滤镜节点数 × 背景变化频率”。算法优化只能减少节点、面积和表面数量，不能改变这一结构。

**待实测的优化候选**（均未测量，按预期收益排序，由 LQ-7 逐项对比后决定）：

1. **（已完成 2026-10-01）高光移出背景滤镜**：边缘高光只取决于表面法线和光源，与背景无关；正式应用的光源固定（`setLightVector` 只有 Lab 调用），但目前高光链仍在 `createFilter` 的背景滤镜内，约占半条链，每次背景变化都重算。可以在生成贴图时烘焙成带透明度的高光图，用普通 CSS 背景叠加（例如伪元素）；Lab 调光源时重新烘焙。
2. **（已完成 2026-10-01）紧凑表面去掉 RGB 色散**：`relationship` 角色最大位移 4px，三路系数 2.12／2.0／1.88 换算后红蓝相差约 0.5px（原记“约 1px”有误，见 13.4），肉眼难辨；只做 1 次 `feDisplacementMap` 并省掉通道拆分与 screen 合并。2026-10-02 起大表面也默认关闭色散，见 13.4。
3. **模糊改用原生 `blur()`**：以 `backdrop-filter: blur(Npx) url(#filter)` 串联代替滤镜内的 `feGaussianBlur`。Chromium 原生背景模糊有降采样优化，通常更便宜。需对比边缘处理（当前 `edgeMode="duplicate"`）和模糊、折射顺序变化带来的画面差异。
4. **减少同时存在的光学表面**：即本节记录的待实测风险，包括词根模式虚拟列表滚动时逐个注册／注销折叠按钮表面、`body` 级 subtree MutationObserver、注销后重新观察全部祖先链。评估大列表内的折叠按钮是否需要独立折射。
5. **去掉 PNG 编码**：贴图在 Worker 中编码为 PNG 再交给 `feImage` 解码，只发生在首次出现或尺寸变化时，收益最小；只有频繁 resize 时才值得处理。

**测量方法**：固定一个背景持续变化的场景，例如在导航和若干紧凑控件下滚动词条列表；用 Chrome Performance 记录帧耗时与 GPU 耗时；每次只改变一项，与当前版本对比。预期第 1、2 项收益最明显，第 3 项取决于画面是否可接受。

**SDF 不再作为候选**（2026-10-01）：SDF 曾尝试接入正式表面，性能不可接受，已完全放弃，不再作为生产替换选项或 LQ-7 前提。相关代码、检查、Lab 路径和 README 说明已于同日删除，见 13.17。

### 13.12 验收标准

视觉验收必须至少确认：

- 不使用背景照片时，组件边界和色域边界在玻璃 rim 内产生与圆角法线一致的弯折；中心区域不出现随机水波或可辨识的下层正文。
- 全边表面的相邻活跃采样法线连续，corner-to-center medial line 不得形成高梯度斜线；内缩导航的四条暴露边均形成连续 rim，不再假定任何边与屏幕连接。
- 同一表面在不同宽高和圆角下具有一致的视觉厚度，而不是纹理被拉伸。
- 正文、图标、输入光标和焦点环保持清晰，不被 backdrop 位移。
- 浅色/暗色、中英文、长词典名/标签/tooltip、320/480/768/1024/1440px 全部通过。
- 搜索、筛选、来源建议、右键菜单、皮肤菜单、全部结构化 tooltip、toast、modal、网络面板、导航、当前词条和当前主编辑表单具有明确但不同的角色强度。
- 减少动态、减少透明度、强制高对比和不支持滤镜的浏览器走正确等级，不残留 URL filter 或 object URL；触摸/粗指针不会创建液态玻璃指针状态，因为当前产品路径不启用局部光源调度。

工程验收必须至少确认：

- 20k 词典的虚拟列表渲染数量、查询和滚动窗口不因皮肤改变；滚动路径没有逐卡片注册、贴图生成或同步样式测量。
- 共享指针帧不得写入液态玻璃 CSS 变量或光源矩阵；当前液态玻璃只承担资源与尺寸生命周期，不形成指针驱动的持续长任务。
- 重复打开/关闭浮层、resize、明暗切换和皮肤切换后，Worker 任务、observer、filter 节点、object URL 与缓存字节回到预算内。
- 对几何函数建立确定性测试：中心接近零位移、相对边位移方向相反、四角连续、非法 IOR/尺寸安全钳制、同缓存键输出一致。
- 执行所有改动 JavaScript 的 `node --check`、`node scripts/check-all.js`、`git diff --check`，并完成真实 Chromium 浏览器验收；自动化截图不能替代对折射方向和合成层的人工判断。

### 13.13 不进入共享模块的内容

以下能力必须留在液态玻璃引擎内部，不能散落到组件事件处理器或通用主题 token 中：

- IOR、厚度、bezel、位移尺度和贴图分辨率。
- SVG filter 节点、`feImage` 资源和 RGB 色散管线。
- Worker 协议、LRU、object URL 与 generation token。
- Q3/Q2/Q1 光学质量选择和运行期故障降级。
- RGB 位移比例、默认环境光矩阵、specular 强度、未来动态光源坐标模型和可选 meniscus bridge 几何。

共享模块只负责表达“这个元素是什么表面角色”和“皮肤已经启用或停用”。这使全量效果可以大胆迭代，同时把对现有业务、数据和组件结构的影响限制在可替换的适配层。

### 13.19 待验证方向：tint 与玻璃感（2026-10-01，未实施）

本节记录待在 Lab 中验证的方向，不改变当前契约。关于 Apple 的描述来自公开的设计规范、API 文档和对系统表现的观察；Apple 没有公开内部实现（见 `docs/archive/LIQUID_GLASS_RESEARCH.md`）。

**Apple 的做法**：

- 默认的 regular 玻璃随下方内容自适应：背景亮处压暗、暗处提亮，必要时在浅色与深色外观间切换，以保证前景可读。它有“底”，但这是逐区域、随背景变化的明暗压缩，背景纹理大体保留，不是统一叠加的半透明颜色。
- clear 玻璃几乎完全透明，规范只建议用于鲜艳的照片或视频背景，并要求在下方加压暗层保证可读性。
- SwiftUI API 中的 `tint` 是给个别控件染强调色、表达语义（如主按钮），不是所有玻璃的默认底色。
- 系统推出后可读性受到较多批评，后来增加了让玻璃更不透明的外观选项：透明度与可读性的取舍，Apple 同样靠“更不透明”解决，只是交给用户选择。

**本项目现状（已确认）**：每个正式表面末层都是静态、均匀的中性 tint（13.5 的 `base tint` 层）：详情与编辑外壳浅色 `0.30`、暗色 `0.34`，Mail 工具栏与移动顶栏 `0.34`，Lab 的 continuous 预设为 `0.52`／`0.56`；折射前还先按角色模糊 `3–7px`。约 50% 的叠色会把背景明暗对比削去一半，边缘几像素的折射和色散被压住，表面读作磨砂面板而不是有厚度的透镜。

**tint 不是唯一原因**：2026-10-01 的临时测试中，把 Lab 背景 `interior.jpg` 作为应用背景、材质参数完全不变，玻璃感就明显增强。其他因素：

1. 背景是柔和渐变，缺少可被折射的细节，这可能是比 tint 更大的因素；
2. 玻璃用于导航卡片、详情外壳等大面积、承载文字的面板。Apple 主要把玻璃用于小尺寸浮动控件和工具栏，面积越大、文字越多，越需要更高的不透明度；
3. 模糊发生在折射之前，背景先被糊掉，位移失去参照；
4. 高光是静态的，缺少随内容或交互变化的光线。

**待验证方向**：

1. **明暗压缩代替叠色**：在滤镜链中用 `feComponentTransfer` 收窄背景亮度范围（提亮最暗处、压暗最亮处），同时大幅降低 tint，必要时接近 0，使前景背后的对比度下降而纹理和折射保留。静态参数做不到 Apple 的逐区域动态自适应，但比统一叠色更接近。可与 LQ-7 候选“高光移出背景滤镜”一并考虑：高光移出后滤镜链中正好有空间。
2. **按表面类型区分**：小尺寸浮动控件和工具栏使用低 tint、弱模糊，追求玻璃感；大面积承载文字的面板保持较高不透明度，或明确定位为磨砂面板而不是透镜。词条详情外壳和（2026-10-02 起）modal、词汇网络面板及全部 floating 浮层已按磨砂面板处理，固定使用 Q1；Q3 只保留给背景平静的导航、列表工具栏背景和紧凑控件。
3. **验证方法**：在 Lab 中以 `interior.jpg` 等细节丰富的背景对照“当前 tint”“tint 为 0”“明暗压缩加低 tint”三组设置，分别记录玻璃感与前景对比度；前两组用现有 tint 滑杆即可完成，不需要改代码。在真实应用中可以用 `scripts/liquid-glass-tint-probe.js`：在液态玻璃皮肤下把它粘贴到浏览器控制台，右下角会出现临时控制条，可以按比例缩放 7 个角色表面的 tint（×1／×0.6／×0.3／×0），轮换 Lab 背景照片，切换明暗主题。它在运行时读取当前皮肤的 tint 原值，不保存数值副本；刷新或点“关闭”即恢复，不进入应用和 `check-all`。主题切换会经由应用保存偏好，应在临时数据目录下使用。前景对比度最终仍按 `STYLE_SKIN_PLAN.md` 第 5 节的控件对照页验收。

**关联事项**：照片背景作为正式选项时，可读性问题与本节直接相关；本节结论应在 `STYLE_SKIN_PLAN.md` 第 5 节的视觉定稿批次中落地，不在材质职责收尾批次中改变 tint。
