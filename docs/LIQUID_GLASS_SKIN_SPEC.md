# Liquid Glass Skin Specification

本文记录 Conlexicon 液态玻璃皮肤的定位、材质层级、光学方案、性能边界与分批实施计划。它与已经完成的“层叠玻璃 / Layered Glass”并列，不替代或扩写既有皮肤语义。

## 1. 状态与身份

- 当前状态：LQ-1–LQ-6 已完成；正式 continuous、focus、floating 与 modal 表面使用几何滤镜、真实 RGB rim、统一光源 specular 与形成 settle，micro 保持无逐控件 backdrop 采样的 CSS 体积材质。LQ-7 尚未实施。
- 用户可见名称：`液态玻璃 / Liquid Glass`。
- 内部 ID：`liquid-glass`。
- 经典皮肤继续作为默认与未知值回退；`layered-glass` 继续保持已经冻结的层叠玻璃边界。
- LQ-2 的固定噪声滤镜与 LQ-3 的五层指针光场只保留为历史阶段记录；LQ-6 已从产品源码移除两条旧视觉路径。Q3 使用统一光学合成，等待或生成失败退回 LQ-1 普通 blur，辅助模式继续使用实色材质。

## 2. 设计目标

液态玻璃不是“更透明的层叠玻璃”，而是一套视觉优先、具有明确体积和光学变化的独立皮肤：

1. 背景透过玻璃时应能看到方向性变化，而不只是均匀模糊。
2. 玻璃边缘同时表达厚度、镜面高光、内阴影和轻微色散。
3. 当前内容、导航和临时浮层必须保持清晰层级，不能把整个应用变成同一种透明卡片。
4. 高密度词典阅读、虚拟列表滚动和编辑操作仍然是产品基础，不以牺牲文字对比换取透明度。
5. 性能是光学效果的硬边界之一，但不是唯一评价标准；允许在少量聚焦表面使用更高成本效果。

公开实现参考 [archisvaze/liquid-glass](https://github.com/archisvaze/liquid-glass)。参考项目通过 SVG `feDisplacementMap` 或全屏 WebGL shader 建立折射；Conlexicon 只借鉴光学原理，不直接复制其全屏演示架构。

## 3. 与层叠玻璃的区别

| 维度 | 层叠玻璃 | 液态玻璃 |
| --- | --- | --- |
| 核心目标 | 稳定内容层与功能玻璃层 | 明确折射、体积、色散和焦散 |
| 导航 | 无 blur 实色底面 | 半透明连续玻璃，允许单层大面积 blur |
| 浮层 | blur、边缘和限定指针点光 | 高强度几何折射、RGB rim、统一 specular 与局部焦散 |
| 当前词条 | 单一静态反射外壳 | 清晰中心、宽 rim 的尺寸感知几何折射 |
| 动态 | 低透明度局部光照 | 跨表面统一光源向量、glint 与资源提交 settle |
| 性能策略 | 克制、稳定优先 | 聚焦表面视觉优先，重复表面严格限流 |

两个皮肤不得共享含义不清的视觉规则。可以复用通用材质 token、皮肤选择器和全局偏好协议，但光学实现必须各自作用域化。

## 4. 材质层级

### 4.1 环境画布

- 浅色由冰青、珍珠白、淡紫和低饱和琥珀构成连续环境色场。
- 暗色由深海蓝黑、青绿冷光、弱紫和暗金构成。
- 环境色场的职责是为透明与未来折射提供可辨认背景，不作为独立装饰光球。
- 减少透明度、不支持 blur 和强制高对比时回退为单色画布。

### 4.2 稳定内容层

词条列表项、表格、分析卡片、编辑表单和详情内部分区保持近实色且无独立 backdrop blur。它们可以消费带环境色的 panel/list-item/inset token 和更精细的内外阴影，但不得逐项加入折射。

### 4.3 连续导航

桌面导航、移动应用栏和移动抽屉使用深色半透明连续玻璃。Q3 对单实例连续表面使用受限分辨率的几何折射；Q1 保留普通背景模糊、低对比反射和厚度阴影，以控制大面积合成成本。

### 4.4 聚焦对象

当前唯一词条详情外壳是内容层中的单实例例外。它使用更透明的多层反射、有界 blur、清晰中心和沿真实圆角法线变化的几何折射。详情内部分区继续保持高不透明度和无 blur。

### 4.5 临时浮层

搜索设置、筛选、皮肤选择器、来源建议、右键菜单、结构化 tooltip 和 modal 是当前视觉最强的玻璃表面。它们通过透明底色、饱和度、内外阴影、较强几何位移、真实 RGB rim 和运行期 specular 表达材质。

大型词汇网络面板只允许普通 blur 或低强度折射，不与小型菜单使用相同位移强度。

### 4.6 控件

按钮、输入框和 select 使用微型玻璃体积：静止时有上缘高光和下缘暗边，hover 增强镜面，pressed 收紧外阴影并增加内压感。控件不独立启用 backdrop blur，避免大量小合成层。

## 5. LQ-1 token-only 基线

LQ-1 使用现有 token 契约，不增加组件 DOM，也不加入专用运行期光学脚本：

- `theme-liquid-glass.css` 只在 `body[data-ui-skin="liquid-glass"]` 下覆盖明暗材质。
- 画布提供连续环境色场。
- navigation、navigation-drawer、mobile-bar、floating、overlay-panel 和 entry-detail 使用不同透明度、blur 与阴影层级。
- control 使用静态多层反射，但不使用 blur。
- panel、list-item、browser 和 inset 不执行 backdrop blur。
- 不支持 blur、减少透明度和强制高对比时提供同层级实色降级。
- 选择皮肤只改变外观和偏好，不重绘业务页面或影响未保存编辑。

LQ-1 的作用是验证色彩、层级、透明度、可读性和运行期边界，为真实折射建立稳定基线；它不是最终效果。

## 6. LQ-2 静态光学引擎（历史，已由 LQ-6 移除）

LQ-2 曾由页面级隐藏 SVG 定义提供两个可复用 filter：

- `soft`：位移 scale 为 `6`，用于当前词条外壳、移动顶部栏和大型词汇网络面板，保留较多内容清晰度。
- `strong`：位移 scale 为 `14`，用于当前打开的小型菜单、modal，以及 chip list、标签信息和 rich 三种结构化 app tooltip，提供更明显的方向变化。

该阶段基线滤镜使用固定 seed 的低频 `feTurbulence`、`feDisplacementMap`、轻微 Gaussian blur 和饱和度修正，CSS 以内侧约 `1px` 的青/紫分离表达色散。LQ-6 完成后，固定 filter、`feTurbulence`、静态 fallback 变量和青紫 inset 色边均已从产品源码删除；隐藏 SVG 只保留空的动态 registry 宿主。

SVG 折射由 `@supports` 作为渐进增强：浏览器不接受 URL backdrop filter 时继续使用 LQ-1 的普通 blur；减少透明度和强制高对比模式显式关闭折射与色散边缘。LQ-2 本身不在运行期重建滤镜，不使用 Canvas，不监听尺寸、滚动或指针，也没有空闲动画循环；这一限制只描述既有基线，已被第 13 节的 LQ-4 全量设计取代为后续方向。

首版不采用全屏 WebGL，原因是它需要持续渲染、背景纹理同步和额外生命周期管理，而 Conlexicon 的主要消费者是有限数量的 DOM 表面。LQ-1–LQ-3 因阶段边界没有按组件尺寸动态生成 Canvas 位移图；现有视觉复评已经确认固定噪声滤镜无法充分表达实体边缘和方向性折射，因此 LQ-4 起正式改用按表面几何生成的位移图与高光图。

## 7. LQ-3 动态焦散（历史，已由 LQ-6 替换）

- allowlist 仅包含当前打开的搜索设置、筛选、来源建议、右键菜单、皮肤选择器、modal 和大型词汇网络面板；当前词条、移动顶栏、tooltip、列表项、分析卡片、表格行和网络节点不响应指针。
- 指针中心产生宽而柔和的局部焦散，距边缘 `72px` 内增强最近边缘高光；四个边缘 glint 与一个中心焦散共同组成五层有界径向光场。
- 色散仍由 LQ-2 的约 `1px` 内侧青/紫边承担，动态 glint 只轻微改变迎光边缘，不形成霓虹描边。
- tooltip 可见性与两套玻璃光效共用一个文档级 `pointermove` 监听器；调度器只为当前皮肤安排一次 `requestAnimationFrame`，另一皮肤的临时状态立即清理。
- 指针离开目标后以 `180ms` 退出并删除 data attribute 与六个坐标变量；空闲时不存在持续动画循环。
- 触摸、非精细指针、减少动态、减少透明度和强制高对比模式关闭动态焦散；皮肤切换、窗口失焦、resize、页面隐藏与 pointer cancel 都会清理状态。

LQ-6 已删除上述五层 CSS 光场、四边距离变量和 `data-liquid-glass-pointer` 状态。当前实现沿用单监听器、逐帧合并与清理边界，但改为统一光源向量、单层局部焦散、白色方向性 glint、运行期 specular 矩阵和表面形成 settle。

## 8. 性能边界

- 禁止列表项、表格行、分析卡片、网络节点和普通输入控件逐项使用 backdrop blur 或折射。
- 同时可见原则上最多一个大面积 blur、一个折射聚焦对象和一个临时浮层。
- 不动画 `backdrop-filter`、SVG displacement scale 或大面积 box shadow。
- 隐藏浮层必须退出实际渲染。
- 移动端降低 entry-detail 和 mobile-bar 的 blur；大型网络面板不使用 `strong` 折射。
- 20k 测试词典下虚拟列表渲染数量不得增加，滚动路径不得加入逐项样式写入。

## 9. 降级与可访问性

- 不支持 `backdrop-filter`：回退为对应层级实色表面。
- `prefers-reduced-transparency: reduce`：移除环境色场、透明、blur 和未来折射。
- `forced-colors: active`：使用系统 Canvas/ButtonFace/Highlight，并关闭装饰阴影。
- 文字、焦点、选中、危险和禁用状态不能仅依赖玻璃透明度表达。
- 正文和关键控件按最不利背景保持 WCAG AA 目标。

## 10. 实施阶段

### LQ-1：运行期与 token-only 基线（已完成）

- 注册 `liquid-glass`，加入双语名称、皮肤预览、首屏预着色和偏好持久化。
- 新增独立明暗 token 文件及三类降级。
- 更新 API、README、设计文档和样式契约。

### LQ-2：静态 SVG 折射（已完成）

- 增加固定、页面级的 `soft` / `strong` SVG filter。
- 只接入 entry-detail、mobile-bar、当前小型浮层、modal 与低强度 network panel。
- Chromium 使用真实折射；URL filter 不可用、减少透明度和强制高对比时保留对应降级。

### LQ-3：动态焦散与完整验收（已完成）

- 增加限定指针响应、中心焦散与近边缘 glint，不改变 SVG displacement scale、blur 或大阴影。
- 完成中文/英文、浅色/暗色、320/480/768/1024/1440px、浮层层级和键盘焦点验收。
- 完成只读 20k 虚拟列表窗口与滚动验收，不向真实 `data/` 写入测试数据。

## 11. 验收记录

- Chromium 实测小型筛选浮层写入归一化 `x/y` 与四边距离，计算样式含一个中心焦散和四个边缘 glint；离开目标并关闭浮层后 `180ms` 内 data attribute 和内联坐标全部删除。
- chip list、标签信息和 rich 三种结构化 app tooltip 统一消费 `strong` SVG 折射及青紫色散边缘，但因 `pointer-events: none` 继续不进入动态焦散 allowlist；减少透明度和强制高对比模式会清除其折射与色散。
- 大型词汇网络使用暗色 `0.065` 的低强度焦散和 `460px` 半径，同时继续使用 LQ-2 `soft` 折射；切换到层叠玻璃后液态临时状态立即归零，切回时也没有层叠玻璃残留。
- 中英文、浅色/暗色及 320、480、768、1024、1440px 均无页面横向溢出；键盘聚焦皮肤入口时 `:focus-visible` 保持成立且不创建指针状态。
- 只读 20k 响应视图在 1440px 初始渲染 7 张词条卡片，在 320px 初始渲染 9 张；移动列表滚动 `1200px` 后渲染量为 13，仍保持有界。词条卡片没有 backdrop blur，也没有液态指针属性。
- 自动化可以确认调度、清理、可见渲染量和滚动窗口，但不能给出可靠逐帧 GPU 合成耗时；发布前如需设备级结论，仍应在目标低端设备上连续滚动并观察性能面板。

## 12. 明确不做

- 不覆盖或重命名层叠玻璃。
- 不把所有内容卡片变成独立玻璃。
- 不加入全屏 WebGL 持续渲染。
- 不使用设备方向、滚动视差或永不停歇的环境动画。
- 不用噪点、霓虹光晕和超大圆角代替真实材质层级。

## 13. LQ-4–LQ-7 全量光学重构

### 13.1 设计结论与替代关系

本节是液态玻璃的正式后续设计及当前实现记录。文档保留 LQ-1–LQ-3 的历史验收背景，但 LQ-6 已在产品源码中完全取代固定 `feTurbulence`、静态色边和旧指针光场。既有 `liquid-glass` 皮肤 ID、全局偏好、token 契约、明暗主题、皮肤选择器和辅助模式协议保持不变。

独立复评后的结论如下：

1. 当前“不明显”的首要原因不是缺少照片，而是固定噪声位移与组件几何无关，无法形成沿真实圆角和边缘变化的厚度、法线与折射方向。
2. 单一噪声 filter 适合验证浏览器能力和降级链，不适合作为最终光学核心；最终路径必须按实际宽高、圆角和材质参数生成表面贴图。
3. Conlexicon 的消费者是多个原生 DOM 表面，首选逐表面的 SVG backdrop filter，而不是全屏 WebGL 画布。后者会引入页面背景同步、文字和输入控件合成、持续绘制及命中测试等额外系统，不应仅为了技术形式而采用。
4. 贴图生成不能占用交互主线程。正常路径使用 Worker，并在能力允许时使用 `OffscreenCanvas`；不支持时使用有界、可取消、分帧的主线程后备生成。
5. 性能约束决定生成、缓存和并发策略，但不得再次把光学实现压缩为统一 blur。高质量设备应获得完整折射、色散、镜面和焦散。

### 13.2 对参考项目的采用边界

全量方案充分采用 [archisvaze/liquid-glass](https://github.com/archisvaze/liquid-glass) 的核心技术路线，而不是只模仿名称或配色：

- 根据玻璃厚度、bezel 宽度、表面高度函数和折射率计算边缘折射轮廓。
- 根据元素宽高和圆角生成二维位移图，使位移方向跟随真实边缘法线。
- 独立生成法线/rim 图，并在运行期用统一光源矩阵合成镜面高光，而不是为每个方向重建贴图或用一个固定彩色 CSS 描边覆盖全部形状。
- 通过 SVG `feImage`、`feDisplacementMap`、颜色处理和合成步骤采样元素背后的页面。
- 在尺寸或形状发生有效变化时重建滤镜资源，而不是把同一噪声贴图拉伸到所有表面。

参考仓库是单块可拖动玻璃的演示，不提供 Conlexicon 所需的多表面注册、皮肤热切换、缓存、Worker、辅助模式、浮层生命周期和虚拟列表隔离。并且截至本设计冻结时没有在仓库根目录发现明确的许可文件，因此实施应采用独立实现：复用公开的图形学原理和浏览器管线，不逐行复制函数、常量或演示代码；设计文档与发布说明保留灵感来源。

### 13.3 模块边界

光学系统作为皮肤内部引擎存在，业务组件不得知道位移图、SVG 节点或滤镜参数。建议的内部模块如下：

```text
lib/
  liquid-glass-geometry.js     纯几何、法线和折射轮廓计算
  liquid-glass-map-worker.js   位移图与法线/rim 图生成
  liquid-glass-engine.js       表面注册、滤镜资源、缓存和生命周期

theme-liquid-glass.css         材质分层、表面角色和降级
index.html                     隐藏 SVG defs 宿主与脚本加载
app.js                         仅接入皮肤启停和既有浮层生命周期
```

概念接口保持为应用内部能力，不新增公共 API 或偏好字段：

```js
liquidGlassEngine.activate();
liquidGlassEngine.register(element, role, options);
liquidGlassEngine.refresh(element);
liquidGlassEngine.unregister(element);
liquidGlassEngine.deactivate();
```

- `activate()` 扫描并注册稳定表面，建立能力检测和受控观察器。
- `register()` 只接受预定义角色；组件不能传入任意 SVG 或逐组件滤镜算法。
- `deactivate()` 必须断开 observer、取消未完成任务、撤销 object URL、删除内联属性和动态 filter。
- 不使用覆盖整个应用的 `MutationObserver`。虚拟列表会频繁增删节点，不能让词条滚动触发光学扫描；常驻但隐藏的菜单和 modal 在激活时一次注册，真正动态创建的少数表面通过现有创建入口显式注册。

预计约 80% 的实现位于上述液态玻璃专用模块和样式中。共享层只增加材质挂点、启停调用和资源清理，不改导航、tooltip、菜单或 modal 的业务语义，也不触及服务端、HTTP API、SQLite、词典模型、查询会话和虚拟列表算法。

### 13.4 光学模型

每个表面的资源由以下输入确定：

- 几何：内容盒宽高、四角半径、bezel 宽度和可见边缘厚度。
- 材质：近似折射率 `ior`、玻璃厚度、最大位移、边缘软化和镜面宽度。
- 角色：continuous、focus、floating、modal 或 micro。
- 输出：X/Y 位移图、X/Y 法线与 rim 图，以及滤镜安全扩展范围。

几何计算以到圆角矩形边界的有符号距离为基础，在 bezel 区域构造平滑高度函数并求局部法线；折射方向由空气到玻璃再回到空气的近似 Snell 路径得到。中心区域保持低位移，边缘在可控宽度内快速弯折，四角按连续法线过渡，禁止使用与形状无关的随机波纹冒充液体。

位移图的 R/G 通道分别编码归一化 X/Y 偏移；第二张图的 R/G/B 分别编码 X 法线、Y 法线与 rim。光源方向不进入几何缓存键，指针移动只更新现有 filter 的颜色矩阵和强度函数。滤镜管线依次完成：

1. 对背景采样做极轻的预软化，抑制高频 aliasing。
2. 用几何位移图执行主体折射。
3. 在外侧光学 rim 内对 R/G/B 使用略有差异的采样尺度并重新合成，形成真实依附边缘的窄幅色散；正文区域不出现彩边。
4. 进行轻度饱和度和亮度补偿，避免多次合成把画面洗灰。
5. 将法线与统一光源向量点乘，和 rim 相乘后生成白色 specular，再以 screen 模式叠加；CSS 只补充一层局部焦散和方向性白色 glint。

色散不是常驻青紫描边。当前 Q3 对 R/G/B 使用三组略有差异的位移尺度并重新合成，使彩边随边缘方向、背景内容和折射强度变化；等待、失败和 Q1 直接回到普通 blur，不再保留静态 CSS 色边。

### 13.5 前景与背景分层

玻璃表面的文字、图标、输入光标和焦点轮廓不得进入位移滤镜。每个正式表面采用一致分层：

```text
content / focus ring       清晰前景；backdrop-filter 不处理前景内容
specular layer (::after)   白色方向性 glint 与形成 settle，pointer-events: none
surface backdrop-filter   URL RGB displacement + 角色级普通 blur
base tint                  透明染色、单层局部焦散与最低可读底色
page background            被采样的环境内容
```

正式表面继续使用既有 DOM；没有为光学效果增加业务节点。`backdrop-filter` 直接作用于表面背景，不会折射文字和控件前景，`::after` 只画有界 rim glint。伪元素保持 `pointer-events: none`、继承圆角并用 mask 限定在边缘，避免遮挡正文或焦点交互。

### 13.6 表面角色与正式覆盖

| 角色 | 消费者 | 折射策略 | 动态策略 |
| --- | --- | --- | --- |
| `continuous` | 桌面导航、移动应用栏、移动导航抽屉 | 大面积、中等强度、低频几何折射；单实例 | 指针只改变光照，不重建几何 |
| `focus` | 当前词条详情外壳、当前主编辑聚焦面 | 清晰中心、明显但较宽的边缘折射 | 缓慢跟随环境光向量，不跟随滚动抖动 |
| `floating` | 搜索/筛选/皮肤菜单、来源建议、右键菜单、全部结构化 tooltip/popover | 最强边缘厚度、清楚色散和局部放大 | 精细指针焦散、近边缘 glint、打开时短暂光学 settle |
| `modal` | 信息/确认 modal、词汇网络主面板 | 中强折射、更宽 rim、更稳定的中心区域 | 只在面板范围响应；遮罩不成为 Backdrop Root |
| `micro` | 按钮、输入框、select、chip | CSS/高光图表达微型体积，不逐个采样 backdrop | hover/pressed 改变光照和压力感 |

覆盖规则：

- chip list、标签信息、rich tooltip 以及实际可见数量有界的质量问题详情 tooltip 都归入 `floating`；折射施加在弹出的表面，而不是列表中的每个触发器。
- 词汇网络节点、词条列表项、表格行和分析卡片仍不是独立折射面。它们通过所属的共享浏览器/面板背景获得环境关系，避免把连续内容切成几十个互相冲突的透镜。
- 控件的 `micro` 材质不是视觉降级：它使用明确的上缘镜面、下缘暗边、pressed 内压和焦点层，但不为每个按钮创建 backdrop filter。
- 同一时刻可见的临时浮层都应取得正确材质，不再依赖手写 CSS selector 是否恰好覆盖；注册表和样式契约必须共享同一角色清单。

### 13.7 环境背景

照片不是液态玻璃成立的必要条件。正式背景使用可读、具有空间频率的产品化环境场，使折射在空状态、长文档和暗色主题中都可辨认：

- 三到四个尺度不同的低饱和色域，避免只有大块均匀渐变。
- 一层非常弱的等高线/细网格或纤维方向纹理，为位移提供可观察参照；其对比度必须低于正文和组件边界。
- 导航侧、内容焦点区和底部形成不同方向的亮度梯度，玻璃移动到不同位置时能够表现不同采样结果。
- 浅色继续使用冰青、珍珠、淡紫和少量暖色；暗色使用蓝黑、冷青、紫和暗金，但禁止霓虹光球、纯装饰噪点和持续漂移动画。
- 可在未来提供用户壁纸作为增强输入，但内置背景必须独立完成全部材质验收；不得用背景图片掩盖光学模型不足。

减少透明度、不支持 backdrop filter 和强制高对比时，环境纹理与透明材质一起关闭，回到稳定实色主题。

### 13.8 运动、焦散与表面张力

- 指针移动只更新光源向量、中心焦散和迎光边缘权重，不重新生成几何贴图，也不动画 displacement scale。
- 继续复用单一文档级 pointer dispatcher 和每帧一次写入；坐标以 CSS 变量传递，离开、失焦、resize、页面隐藏和换皮肤立即或短时淡出清理。
- 动态几何资源提交使用约 `240ms` 的材质形成过程：边缘 glint 从轻微收束状态稳定；只动画 opacity、transform 和小范围光照变量，不动画 blur 半径、大面积阴影或 displacement scale。
- meniscus bridge 仍是可选后续项，本批未实装；不得把它视为 LQ-6 完成条件，也不得在没有稳定锚点和裁切验证时扩展到任意卡片。
- `prefers-reduced-motion` 下取消 settle、bridge 形变和指针跟随，但保留静态几何折射；减少透明度与强制高对比则连静态折射一起关闭。

### 13.9 生成、缓存和尺寸生命周期

- Worker 接收纯数值参数并返回 `ImageBitmap`、Blob 或可被 SVG `feImage` 使用的资源；不得把 DOM 传入 Worker。
- 缓存键至少包含量化后的宽高、圆角、bezel、厚度、IOR、最大位移、角色和贴图版本。宽高默认按约 `4px` 量化，圆角和 bezel 使用更细粒度，不能让小 tooltip 因过度量化明显变形。
- 贴图分辨率按视觉尺寸和设备像素比决定，并设角色级上限；高 DPI 不需要无限增长。优先保证 rim 的采样密度，中心可以低频表示。
- 使用按字节预算的 LRU，而不是只按元素数量缓存；资源被淘汰或皮肤停用时撤销 object URL 并移除无消费者的 filter。
- `ResizeObserver` 只观察已注册表面。连续 resize 期间复用最近资源并合并请求，尺寸稳定后再生成精确贴图；旧任务通过 generation token 丢弃。
- 隐藏表面不生成高分辨率资源。打开或等待精确资源时继续使用对应组件的普通材质 blur，生成成功后原子提交动态 filter；失败同样保留普通 blur，不得闪白或短暂丢失边界。
- 不存在空闲永久动画循环；只在打开过渡、指针活动或资源提交期间安排帧。

### 13.10 质量等级与降级

质量不是简单的“开/关”，而是保持同一视觉语言的四级路径：

| 等级 | 条件 | 效果 |
| --- | --- | --- |
| Q3 完整光学 | URL backdrop filter、Worker/Canvas 和正常透明度可用 | 几何折射、RGB rim 色散、高光图、焦散和限定 settle |
| Q2 缓存光学 | 生成受限但存在相同几何缓存资源 | 复用量化尺寸的几何贴图与统一光源合成，保留真实位移 |
| Q1 基线玻璃 | URL filter、Canvas 或贴图生成不可用 | LQ-1 普通 blur 和稳定材质边界，无固定 SVG filter 或 CSS 彩色 rim |
| Q0 辅助实色 | 减少透明度、强制高对比或 backdrop filter 不可用 | 实色材质、系统色和明确边界，无折射/色散 |

能力检测只决定可用上限，不依据设备名称或用户代理猜测性能。若运行期出现持续长任务、资源生成失败或显存压力，可以按表面从 Q3 降到 Q2/Q1，但必须记录可诊断原因，不能静默让同类浮层随机呈现不同材质。

- 指针帧只写入当前活动表面的少量 CSS 变量，正常目标是在性能面板中不形成可观察的持续长任务。

### 13.13 不进入共享模块的内容

以下能力必须留在液态玻璃引擎内部，不能散落到组件事件处理器或通用主题 token 中：

- IOR、厚度、bezel、位移尺度和贴图分辨率。
- SVG filter 节点、`feImage` 资源和 RGB 色散管线。
- Worker 协议、LRU、object URL 与 generation token。
- Q3/Q2/Q1 光学质量选择和运行期故障降级。

共享模块只负责表达“这个元素是什么表面角色”和“皮肤已经启用或停用”。这使全量效果可以大胆迭代，同时把对现有业务、数据和组件结构的影响限制在可替换的适配层。

- 引擎在几何资源提交后设置 `forming → settled`，约 `240ms` 后清理状态；换皮肤、注销、失焦、resize、页面隐藏、pointer cancel 和辅助媒体变化继续释放临时样式与光源状态。没有改变公共皮肤偏好、组件 DOM、业务接口或数据存储。
