# 应用外壳规范（阶段 A）

状态：核心已实装（阶段 A 已收尾）；完整触摸、焦点陷阱与无障碍专项见 [触摸、焦点与无障碍计划](TOUCH_FOCUS_A11Y_PLAN.md)。内容自 2026-09-30 起从 `NEXT_IMPLEMENTATION_HANDOFF.md` 原样迁出，仅调整标题层级。


## 1. 目标布局

桌面宽屏：

```text
[全局工具导航] [词条列表] [主编辑/查看区]
```

桌面中等宽度：

```text
[强制收起的图标导航栏] [词条列表] [主编辑/查看区]
```

竖屏移动端：

```text
[紧凑应用栏：菜单 | 当前模块 | 列表 | 主操作]
[主编辑/查看区]
```

- 全局工具导航在移动端成为左侧覆盖抽屉。
- 词条列表成为单独的列表/搜索抽屉。
- 选择词条后关闭列表抽屉并立即显示详情，不再要求滚动到列表底部。
- 抽屉内容独立滚动，页面主体保持自己的滚动位置。
- 语料列表暂不套用最终设计；只接入通用外壳，具体列表等待阶段 C。

## 2. 状态模型（已实装）

当前应用外壳使用独立的进程 UI 状态，核心字段如下：

```js
const shellState = {
  navCollapsed: false,
  wideNavCollapsed: false,
  navDrawerOpen: false,
  browserDrawerOpen: false,
};
```

- 这些状态不写入词典数据。
- 响应式自动折叠和宽屏用户手动折叠已经分开：中等宽度强制使用 rail，宽屏只读写 `wideNavCollapsed`，不会互相覆盖。
- 切换词典时可以保留全局导航状态，但词条列表抽屉应关闭。
- 打开/关闭抽屉不是数据页面切换，不应触发保存弹窗。
- 在抽屉中选择新词条或新模块时，仍必须经过现有未保存处理流程。

## 3. DOM 和 CSS 边界

- 应用外壳已经使用稳定区域：`app-nav`、`view-browser`、`view-content`、`mobile-app-bar`。
- 当前使用 CSS class 和 `data-*` 表达状态，例如：

```text
data-nav-state="expanded|rail|drawer"
data-browser-state="expanded|drawer"
```

- 桌面收起导航后只显示图标，并使用应用内 tooltip 和可访问名称。
- 导航使用现有内联图标体系，不另用文字圆角块代替常见图标。
- 词条详情没有复制到移动端专用 DOM；同一内容区通过布局状态响应。
- 避免只依赖 viewport 宽度；主工作区可考虑 container query，使 Electron 窗口和网页嵌入都能正确响应。

当前主断点如下；后续仍应以内容是否可用为准：

- 宽屏：约 `>= 1280px`。
- 中等宽度：约 `800-1279px`。
- 抽屉模式：约 `< 800px`。

### 词条列表与工具栏（三套皮肤共用，2026-11-09 起）

- 桌面宽度下词条列表列为 `minmax(240px, 340px)`，详情占剩余空间；`< 800px` 时列表在抽屉里。词条卡片最小高度 `104px`、内边距 `12px`，释义最多两行；紧凑卡片和只有正文的卡片不设最小高度。
- 工具栏是 `index.html` 中的静态结构，没有按皮肤切换的布局。第一行是撑满列表宽度的搜索框：放大镜、输入、清空（有搜索词时）、搜索设置。第二行是平的列表表头：左边为排序文字触发器（显示当前排序的短说法，英文为“Edited · Newest”这类，中文与完整说法相同；完整说法在 tooltip、读屏标签和菜单中；表头宽度不超过 `300px`，即 360px 及以下视口的抽屉里，去掉排序图标并把左右内边距缩到 `6px`；仍放不下时截断），右边依次为筛选、词根模式、细分隔线和新建，均为 `40px` 图标按钮。DOM 与键盘顺序与视觉顺序一致。
- 搜索框内的按钮和表头按钮在三套皮肤里都是平面按钮：静止时没有底、边框和凸起阴影，悬浮和按下显示中性浅底，弹层打开时保留打开态底色；筛选生效时筛选按钮保留强调色边（`--control-context-border`）。新建保留强调色描边配方（快捷键与 tooltip 不变），在表头中改为强调色浅底、无边框无阴影，是表头里唯一默认带底的按钮。
- 圆角由 `--entry-toolbar-radius` 决定：默认 `--radius-control`，液态玻璃覆盖为 `--radius-pill`。玻璃表面、tint 等材质留在皮肤文件。
- 词根模式按钮常驻原位：有筛选时以 `aria-disabled` 禁用，tooltip 说明“清除筛选后可用”，不隐藏。词根模式与筛选互斥，二者共用表头下方的状态行：有筛选时显示筛选状态，处于词根模式时显示带图标和文字的“全部展开／全部收起”（高度与筛选行同为 `34px`），都不在时该行不显示。
- 搜索设置、筛选和排序三个弹层是 `body` 的直接子节点（`.entry-workspace-menu`，fixed 定位，`--layer-floating-menu`），不在 sticky 列表或工具栏的层叠上下文里，也不增加覆盖视口的宿主容器。`lib/entry-toolbar-menus.js` 按触发器位置放置弹层，必要时避让视口边界；搜索设置／筛选面板宽 `340px`、排序菜单宽 `240px`，最大宽度为视口减 `24px`。外部点击同时检查触发器和弹层；Escape 关闭并返回触发器；滚动和 resize 只重新定位，Tab／失焦不关闭；所属工具栏隐藏（抽屉关闭）或离开词条页时关闭。

## 4. 交互与可访问性

- `Escape` 先关闭最上层抽屉或弹窗。
- 抽屉打开后锁定背景交互；完整焦点陷阱、触摸替代交互和无障碍专项见阶段 A+。
- 所有收起按钮提供 `aria-expanded`、`aria-controls` 和中英文 tooltip。
- 抽屉打开时不能破坏虚拟列表测量；容器从隐藏变为可见后要重新测量可见高度。
- 选择虚拟列表条目后，详情定位、词根模式多来源实例和高级筛选返回方式必须保持正确。
- 虚拟列表窗口重渲染（滚动、补窗、刷新）复用内容未变的卡片节点（词条列表两种模式与语料列表），内容签名不含选中状态，选中状态就地同步；复用的词条卡片监听器读取当前数据。卡片内容变化而被替换、或保留的行被移动导致焦点丢失时，焦点恢复到同一行同一位置的可聚焦元素，否则 Tab 会回到列表开头形成循环（2026-10-11）。

## 5. 阶段 A 验收

- 竖屏首次进入词条编辑时可直接看到词条详情或空状态。
- 无需滚过完整列表即可打开任意词条。
- 中等宽度工具导航固定为图标栏且不显示手动开关；词条列表仍可单独收起。
- 抽屉内搜索、排序、词根模式和高级筛选正常。
- 完整/局部编辑未保存时，从抽屉切换词条或模块仍正确提示。
- 320、480、768、1024、1440px 下无不可访问操作。
- 深色模式、中英文和长工具名称均测试通过。

## 6. 当前收尾状态

- 基础应用外壳、桌面导航收起、移动端顶部应用栏、工具导航抽屉和词条列表抽屉已经实装。桌面词条列表收起功能已于 2026-11-09 删除：它不记忆状态，搜索或筛选出结果时又会自动展开，实际很少能保持收起，而词典名旁的“⌄”开关容易被误认成切换词典的下拉菜单。
- 触发标签、词性和高级筛选等词条结果入口时，移动端会打开词条列表抽屉，桌面端会展开已收起的词条列表。
- 词条列表隐藏或抽屉关闭时触发跳转/保存后，会记录待聚焦词条，并在列表重新显示后滚动到当前词条。
- 移动端抽屉打开时，通用确认弹窗层级高于抽屉。
- 已抽查 320、480、768、1024、1440px 基础布局；320px 下抽屉筛选入口与未保存确认流程已抽查。
- 主要页面区域、词条编辑/详情和筛选排序控件已有中英文无障碍名称；完整焦点陷阱、触摸替代和系统性无障碍验收仍属于 A+。
- 阶段 A 收尾不包含阶段 A+ 的完整触摸、焦点陷阱和无障碍专项。
